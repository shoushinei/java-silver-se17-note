一問一答

答えを声に出してから開いてください。

Q1P p = new C(); のとき p.x（フィールド）と p.m()（メソッド）はどちらの実装？

フィールドは P、メソッドは C。インスタンスメソッドだけが実行時に実体を見て決まり（動的束縛）、フィールドと static メソッドはコンパイル時に宣言型で決まります（静的束縛）。この章の核心です。

Q2((P)c).x の結果が c.x と違うのはなぜ？

キャストで宣言型が変わったから。実体は同じですが、フィールドは宣言型で解決されます。親子の同名フィールドは両方とも実体の中に存在し、上書きされているわけではありません。

Q3親に A(int x) だけがあるとき、子の B(){} は？

コンパイルエラー。暗黙の super() が呼べません。エラーは子クラス側に出ます。super(0) と明示するか、親に A(){} を足します。

Q4コンストラクタの実行順序は？

最上位の親までさかのぼってから下りてくる。各階層で「初期化ブロック → コンストラクタ本体」の順です。親が完成していなければ子を組み立てられないため。

Q5オーバーライドで戻り値型・アクセス・検査例外はどう変えられる？

戻り値はサブ型に狭める可、アクセスは広げる可、検査例外は狭める・減らすのが可。逆はすべて不可。「呼ぶ側が困らない方向にだけ変えられる」と覚えます。非検査例外は自由。

Q5b「オーバーライドの戻り値型は同じでなければいけない」は正しい？

誤り。同じまたはサブ型。Object → String は可（共変戻り値）。ただし共変が効くのは参照型だけで、int → long は不可。void → String は継承関係が無いので不可です。

Q5c「抽象メソッドはオーバーライドできない」「オーバーロードされたメソッドはオーバーライドできない」は？

どちらも誤り。抽象メソッドはオーバーライドされるために存在します。オーバーロードされたメソッドも、それぞれ独立に上書きできます。4条件のうち完全一致が要求されるのは引数リストだけで、残り3つは片方向に緩められます。

Q6static メソッドはオーバーライドできる？

できない。static 同士なら書けますが、それは隠蔽（hiding）で、宣言型で解決されます。static と非 static を入れ替えるとコンパイルエラーです。

Q7オーバーライドのつもりで引数の型を間違えるとどうなる？

静かにオーバーロードになる。コンパイルは通り、親のメソッドが呼ばれ続けます。@Override を付けていればここで止まります。

Q8継承関係のある型へのダウンキャストが失敗するのはいつ？

実行時（ClassCastException）。コンパイルは通ります。継承関係がまったく無い型どうしのキャストはコンパイルエラーになるので、区別してください。

Q9P p = new C(); で C 固有のメソッドを呼ぶには？

((C)p).only() とキャストするか、if (p instanceof C c) でパターン変数を使います。「書ける範囲は宣言型、動く実装は実体型」。

Q10abstract メソッドを1つも持たない abstract クラスは？

合法。「インスタンス化させたくない」という意図だけで付けられます。逆に、abstract メソッドを持つクラスは abstract でなければなりません。

Q10bAbstractSample s = new ConcreteSample(); は合法？

合法。禁止されているのは new 抽象クラス名() と直接書くことだけで、型として使うのは自由です。むしろ型として使うためにある構文。親の具象メソッドから抽象メソッドを呼べば、子の実装が動きます（テンプレートメソッド）。

Q11abstract クラスはコンストラクタを持てる？ main は書ける？

どちらも可。コンストラクタは子の super() から呼ばれます。main は static なのでインスタンス不要で、java クラス名 で起動できます。

Q12final int[] arr = {1,2}; のとき arr[0] = 100; は？

OK。final が固定するのは矢印であって指す先の中身ではありません。arr = new int[]{3}; だけがエラーです。

Q13インタフェースのフィールドとメソッドに暗黙に付く修飾子は？

フィールドは public static final、メソッドは public abstract。フィールドは定数なので再代入不可。実装側は public を書かないと「アクセスを狭めた」ことになりエラーです。

Q13bインタフェースのメソッドに本体を書けるのはどんなとき？

default / static / private のいずれかが付いているときだけ。修飾子なし（＝暗黙に public abstract）に本体を書くと interface abstract methods cannot have body。public や abstract を明示しても同じです。付いていれば本体が必要、付いていなければ禁止という対称関係。

Q13cインタフェースのメソッドに protected や final は付けられる？

どちらも不可。protected はインタフェースが「誰でも使える約束事」なので中間段階が成立しません。final はオーバーライド禁止の意味で、オーバーライドされるためにあるインタフェースと矛盾します。public と abstract は冗長ですが書けます。

Q13dprivate void a(); と private default void c(){ } は？

どちらもエラー。前者は missing method body ── 本体を省くと暗黙に abstract になり「実装クラスに書かせる」意味になるが、private では相手に見えないので矛盾。後者は illegal combination of modifiers ── 継承させたいのに見せない、で矛盾。private void b(){ } だけが正解です。

Q13enew インタフェース名() は？

不可。is abstract; cannot be instantiated。抽象クラスとまったく同じエラーです。型として使うのは自由。new I(){ ... } は匿名クラスで別物（SE 17 の範囲外）。

Q14インタフェースの static メソッドは実装クラスに継承される？

されない。I.s() はエラーで、G.s() とインタフェース名で呼びます。default は継承されるので、この非対称が出題されます。

Q152つのインタフェースが同名の default を持ち、両方を実装すると？

コンパイルエラー（types A and B are incompatible）。解決はオーバーライドして A.super.m() と名指しすること。Java は曖昧さを書き手に解決させます。

Q15bクラスの中で super.m() と書くと、インタフェースの default は呼べる？

呼べない。super はスーパークラスだけを見ます。extends を書いていなければスーパークラスは Object なので cannot find symbol。default を呼ぶには I.super.m() と名指しします。
ただし親クラスがその default を継承していれば super.m() で届きます。

Q15cinterface B extends A、class C implements B のとき、C から A.super.m() は？

不可（not an enclosing class: A）。名指しできるのは直接の親だけです。C の直接の親は B なので B.super.m() なら通ります。implements の右に書かれている名前かどうかで判定します。

Q16クラスの具象メソッドと default が競合したら？

クラスが勝つ。エラーにはならない。「クラスは実装、インタフェースは規約」という優先順位です。record のアクセサが default に勝つのも同じ規則。

Q17default String toString() をインタフェースに書ける？

書けない。Object のメソッドは「クラスが勝つ」規則により default が絶対に使われないので、書くこと自体が禁止されています。

Q18sealed インタフェースを実装するクラスに必要なものは？

final / sealed / non-sealed のいずれかを必ず書く。書き忘れると sealed, non-sealed or final modifiers expected。record は暗黙に final なので不要です。

Q19permits は省略できる？ 相手はどこにあってもよい？

同一ファイル内なら省略可。相手は同じパッケージ（モジュール使用時は同じモジュール）に限る。封をする以上、コンパイラが全実装を一望できる必要があるためです。

Q20sealed と switch のパターンマッチングは SE 17 の出題範囲？

switch のパターンマッチングは範囲外（SE 17 ではプレビュー機能）。問われるのは sealed の構文規則 ── permits の範囲、実装側の3択、場所の制約です。

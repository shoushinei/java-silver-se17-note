宣言型か実体型か ── 章の核心

この章でもっとも出題され、もっとも間違えるのがここです。

対象何で決まるか用語
インスタンスメソッド実体型（実行時）オーバーライド
フィールド宣言型（コンパイル時）隠蔽（hiding）
static メソッド宣言型（コンパイル時）隠蔽（hiding）
実行して確認した結果最重要
class P {
    int x = 1;
    String m(){ return "P.m"; }
    static String s(){ return "P.s"; }
}
class C extends P {
    int x = 2;
    String m(){ return "C.m"; }
    static String s(){ return "C.s"; }
}

P p = new C();
System.out.println(p.x);      // 1    ← 宣言型 P で解決
System.out.println(p.m());    // C.m  ← 実体型 C で解決
System.out.println(p.s());    // P.s  ← 宣言型 P で解決

C c = new C();
System.out.println(c.x);          // 2
System.out.println(((P)c).x);     // 1  ← キャストで宣言型が変わる

理由は解決のタイミングです。
インスタンスメソッドだけが実行時に実体を見て決める（動的束縛）仕組みを持ちます。フィールドと static メソッドはコンパイル時に変数の型だけを見て決めてしまう（静的束縛）。
((P)c).x が 1 になるのは、キャストで宣言型が変わったからです。実体は同じ C のままですが、フィールドは宣言型で解決されるので結果が変わります。

フィールドは親子の同名フィールドが両方とも実体の中に存在します。上書きされるのではなく、2つ並んで存在し、宣言型でどちらを見るかが決まる。
super.x で親側を、this.x で自分側を明示できます。

super で親側を指すOK
class Sub extends Sup {
    int v = 20;                            // 親の v = 10 とは別に存在
    void m(){ System.out.println("Sub.m"); }
    void show(){
        System.out.println(v + " / " + super.v);   // 20 / 10
        m();                                        // Sub.m
        super.m();                                  // Sup.m
    }
}

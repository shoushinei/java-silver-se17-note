main メソッドのシグネチャ

JVM が実行の起点として探すメソッドは、この形と完全に一致していなければなりません。

基準となる形最重要
public static void main(String[] args) { }

JVM は「クラス名を受け取り、そのクラスから main という名前で、public かつ static で、戻り値が void で、String の配列を1つ受け取るメソッド」を探します。この4条件のどれか1つでも外れると起動できません。

変えてよい部分

すべて正しく実行できるOK
static public void main(String[] args) { }   // public と static は順不同
public static void main(String... args) { }  // 可変長引数でもよい
public static void main(String args[]) { }   // 括弧を変数名の後ろに置いてもよい
public static void main(String[] x) { }      // 引数名は自由
public static final void main(String[] args) { }   // final を付けてもよい

String... が通るのは、可変長引数の実体が配列だからです。コンパイル後のシグネチャは String[] と同一になります。String args[] が通るのは C 由来の古い記法が残っているためで、意味は String[] args とまったく同じです。

変えてはいけない部分

書き方結果エラーが出るタイミング
private static void main(...)起動できない実行時
public void main(...)（static なし）起動できない実行時
public static int main(...)起動できない実行時
public static void main()（引数なし）起動できない実行時
public static void main(int[] args)起動できない実行時
public static void Main(String[] args)起動できない実行時

ここが最頻出です。main の形が違ってもコンパイルは通ります。ただのメソッドとして文法上は正しいからです。エラーになるのは java コマンドで起動しようとした瞬間。
選択肢に「コンパイルエラー」と「実行時エラー」が並んでいたら、実行時エラーが正解です。

コンパイルは通り、実行で落ちる実行時
public class Main {
    public static void main(String[] args, int x) { }   // 引数が2つ
}

// javac Main.java  → 成功
// java Main        → 失敗
// Error: Main method not found in class Main, please define the main method as:
//    public static void main(String[] args)

main のオーバーロード

共存できるが、呼ばれるのは1つだけ要注意
public class Main {
    public static void main(String[] args) {
        System.out.println("A");
        main(10);                      // 明示的に呼べば動く
    }
    public static void main(int x) {
        System.out.println("B");
    }
}
// 出力: A B

main(int) はただのメソッドです。JVM が起点として選ぶのは常に String[] を取る方だけ。オーバーロードされた main は、自分で呼ばない限り実行されません。

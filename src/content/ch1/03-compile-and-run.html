03

コンパイルと実行

まず Java が動く仕組み

コマンドの規則は丸暗記できますが、仕組みを知っていると導けます。ここを押さえると、この節の問題はほぼ落とさなくなります。

ソースから実行までの3段階図
Main.java          人間が書くソースコード（ただのテキスト）
    │
    │  javac        コンパイル
    ↓
Main.class         バイトコード（JVM 用の中間コード。機種に依存しない）
    │
    │  java         JVM を起動して読み込み、解釈しながら実行
    ↓
実行

C 言語のコンパイラは、CPU が直接理解できる機械語を吐きます。だから Windows 用にコンパイルした実行ファイルは Mac では動きません。Java はここで一段はさみます。javac が作るのは機械語ではなく、JVM という仮想的なコンピュータ向けの命令＝バイトコードです。

バイトコードはどの機種でも同じ内容です。機種ごとの違いは JVM 側が吸収します。Windows には Windows 用の JVM、Mac には Mac 用の JVM があり、同じ .class をそれぞれが自分の CPU 向けに動かす。これが「一度書けばどこでも動く」（Write Once, Run Anywhere）の実体です。
java コマンドの正体はこの JVM を起動するプログラムです。

なぜ javac はファイル名、java はクラス名なのか

2つのコマンドは見ている世界が違います。

扱う対象渡すもの
javacファイルを読んでファイルを書くファイル名（.java 付き）
javaクラスをクラスパスから探すクラス名（拡張子なし）

javac はファイルを変換する道具なので、当然ファイル名が要ります。
一方 java は「この名前のクラスを持ってきて動かせ」と JVM に頼むコマンドです。JVM にとって世界はファイルではなくクラス名の空間でできていて、Main という名前を受け取ってからクラスパス上を探しにいきます。

だから java Main.class は失敗します。JVM はこれをファイル名だと思わず、「Main パッケージの class というクラス」と解釈するからです。ドットはパッケージの区切りにしか見えません。
実際のエラーは ClassNotFoundException: Main.class。.class ファイルが目の前にあっても失敗します。

同じ理由で、パッケージに属するクラスは java com.example.Main とドット区切りで渡します。これは「ディレクトリのパス」ではなくクラスの完全な名前です。正式な指定はこのドット区切りです（java com/example/Main も実際の JDK では読み替えられて動きますが、試験で選ぶべきは完全修飾名の形です）。

2つのコマンド

コマンド渡すものすること
javacファイル名（拡張子 .java あり）ソースを .class に変換する
javaクラス名（拡張子なし）.class を読み込んで main を起動する
基本の2ステップ最重要
javac Main.java        // Main.class が生成される
java Main              // 実行。.class や .java は付けない
ありがちな誤りNG
javac Main             // 失敗。javac にはファイル名（.java 付き）が必要
java Main.class        // 失敗。クラス名として "Main.class" を探しにいく
java Main.java         // ← これは失敗しない（次項を参照）

javac にはファイル名、java にはクラス名。java Main.class は「Main パッケージの class クラス」を探しにいって失敗します。この選択肢は頻出です。

java コマンドの2つのモード

java は1つのコマンドに2つの動作が入っています。判定は単純で、渡された引数が .java で終わっているかどうか、それだけです。

渡したものモード読むファイル.class は必要？
java Main
拡張子なし		クラス実行モードMain.class
クラスパスから探す		必要
java Main.java
.java で終わる		ソース実行モード
SE 11 以降		Main.java
その場で読む		不要

したがって、ソースファイルしか無い状態から出力に到達する道は2本あります。

どちらでもゴールに着く最重要
// 経路①  .class を作ってから実行する
javac Main.java        // Main.class が生成される
java Main              // その .class を読んで実行

// 経路②  ソースから直接実行する
java Main.java         // .class は作られない
java Main.java red     // 引数も渡せる

ソース実行モードの中身

コンパイルは省略されていない図
経路①  Main.java ──javac──→ Main.class ──java──→ JVM が実行
                              （ディスクに保存）

経路②  Main.java ──────────→ バイトコード ──→ JVM が実行
                            （メモリ上。保存しない）

よくある誤解は「ソース実行モードはコンパイルを飛ばしている」というものです。正しくはコンパイル結果を保存していないだけ。
Java は必ずバイトコードを経由します。経路②でもバイトコードは作られていて、ファイルに書かずそのまま JVM に渡しているだけです。「作る必要がない」のはクラスではなく .class ファイルです。

2つのモードが別物である証拠

.class と .java の中身をわざとズラすと、読んでいるファイルの違いがはっきり見えます。

同じディレクトリで出力が食い違う要注意
// VERSION 1 の状態でコンパイル
javac Main.java

// その後ソースだけを VERSION 2 に書き換える（再コンパイルはしない）

$ ls
Main.class  Main.java

$ java Main             → VERSION 1     // .class を読んでいる
$ java Main.java        → VERSION 2     // .java を読んでいる

同じコマンド、同じディレクトリなのに結果が違う。見ているファイルが別だからです。ソース実行モードは .class の存在を完全に無視します。

どちらを使うか

経路向いている場面特徴
java Main.java1ファイルの試し書き、動作確認毎回コンパイルが走るので起動が遅い。成果物が残らない
javac → java複数ファイル、繰り返し実行、配布.class が残るので2回目以降が速い

ソース実行モードには制約があります。1ファイルで完結するプログラム限定（そのファイル内に複数クラスを書くのは可）で、複数ファイルに分かれていると使えません。
また SE 11 で導入された機能なので SE 8 以前では動きません。「java Main.java はエラーになる」と書かれた古い教材があるのはそのためで、SE 17 の試験では動くのが正解です。

よく問われるオプション

オプション意味
javac -d bin Main.java.class の出力先を指定。パッケージ構造のディレクトリも自動で作られる
java -cp bin Mainクラスを探す場所を指定。-classpath と同じ
javac A.java B.java複数ファイルを同時にコンパイル
javac *.javaカレントの全ソースをコンパイル

-d と -cp の仕組み、どこに .class ができてどこを探すのか、選択肢の判定の手順は第1章 08で詳しく扱っています。

問題文の読み分け ── 同じ選択肢が正解にも誤りにもなる

この節でいちばん落とし穴になるのが、同じコマンドが問題によって正解にも不正解にもなることです。

ソースしか無い状態で java を叩く実行時
$ ls
Sample.java                      // .class はまだ存在しない

$ java Sample
Error: Could not find or load main class Sample
Caused by: java.lang.ClassNotFoundException: Sample
「クラスを実行するコマンドは？」「このプログラムを実行し
◯◯と表示したい」
ソースコードの提示なしあり
問われているものコマンド単体の妥当性出力までの手順
前提.class は既にある.java しか無い
java Sample○ 正しい× コンパイルがまだ
javac Sample.java
java Sample		—○
java Sample.java○○

判断の分かれ目は問題文にソースコードが載っているかです。
載っていなければ、コマンドの文法が正しいかを聞いている。載っていて「実行して〜と表示したい」とあれば、ソースから出力に至る手順を聞いています。後者では、コンパイル工程を含む形か java Sample.java でなければ正解になりません。
選択肢だけを見て機械的に判断すると、ここで確実に引っかかります。

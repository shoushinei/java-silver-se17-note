フィールドとライフサイクル

ローカル変数との決定的な違い

フィールドローカル変数
初期化既定値が入る（省略可）必須。使う前に代入がないとエラー
置き場所ヒープ（実体の中）スタック（メソッドの中）
寿命実体が生きている間メソッドを抜けるまで
アクセス修飾子付けられる付けられない
この差が出題されるNG
class T {
    int f;                            // OK。既定値 0 が入る
    void m() {
        int local;
        System.out.println(f);        // OK → 0
        System.out.println(local);    // コンパイルエラー
                                      // variable local might not have been initialized
    }
}

既定値は第2章の表と同じです。数値は 0、boolean は false、char は '\u0000'、参照型は null。フィールドが参照型なら、初期化しないまま使うと NullPointerException になります。

オブジェクトのライフサイクル

参照が切れたら回収対象図
Car c = new Car("A");     // ① 生成。c が実体を指す
c = new Car("B");         // ② 最初の実体を指す矢印が消えた
                          //    → どこからも参照されない → GC の対象
c = null;                 // ③ 2つ目も参照が切れる

ガベージコレクションについて問われるのは「いつ回収対象になるか」であって「いつ回収されるか」ではありません。
どこからも参照されなくなった時点で対象になりますが、実際に回収されるタイミングは JVM 任せで保証されません。System.gc() も「お願い」であって強制ではなく、finalize() は非推奨です。

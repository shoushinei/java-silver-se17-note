instanceof のパターンマッチング

SE 16 で正式化された機能で、SE 17 試験の新規範囲です。11 の教材には載っていません。

従来の書き方との比較基本
// 従来 ── 判定してから自分でキャスト
if (o instanceof String) {
    String s = (String) o;
    System.out.println(s.length());
}

// SE 16以降 ── 判定と同時に変数へ束縛される
if (o instanceof String s) {
    System.out.println(s.length());     // キャスト不要
}

s をパターン変数と呼びます。instanceof が true のときだけ値が入り、自動的にキャスト済みの状態で使えます。

実際に何が起きているか

「instanceof が型変換してくれる」という理解は半分だけ正しいです。正確には3つのことを同時に行っています。

従来の3行を1行に畳んだだけ最重要
// 従来
if (a instanceof B) {      // ① 判定する
    B b = (B) a;           // ② キャストする ③ 新しい変数に入れる
    b.only();
}

// パターンマッチング
if (a instanceof B b) {    // ①②③ を一度に
    b.only();
}

ここで作られているのは新しい変数です。元の変数 a は書き換わりません。
キャスト (B) a は「a の値を B として見た結果」を式の値として返すだけで、a 自身の宣言型にも指し先にも影響しません。a はそのまま A 型として残ります。

a と b は共存し、同じ実体を指す頻出
A a = new B();

if (a instanceof B b) {
    System.out.println(a == b);   // true ← オブジェクトは1つ

    a.test();      // ○ A にあるメソッド。実装は B のものが動く（多態）
    b.test();      // ○ 同じ結果

    a.only();      // ✗ error: cannot find symbol ── A に only() は無い
    b.only();      // ○ B 固有のメソッドはこちらから
}

オブジェクトは1つのまま、それを見るための窓口が2つになった状態です。
「どのメソッドを書けるか」は変数の宣言型で決まり、「どの実装が動くか」はオブジェクトの実際の型で決まります。a の宣言型は A のままなので only() は書けませんが、test() は書けて、動くのは B の実装です。
パターン変数の存在意義は、サブクラス固有のメンバを呼べる窓口を用意することにあります。

参照型のキャストは値を変えない

種類何が起きるか
基本データ型 (int) 3.9値そのものが変わる（3.9 → 3）
参照型 (B) a値は変わらない。コンパイラへの型の申告が変わるだけ

第2章のキャストとは意味が違います。参照型のキャストはオブジェクトを作り変えません。「このオブジェクトを B として扱わせてくれ」という宣言にすぎず、実行時に本当に B でなければ ClassCastException になります。

この構文が導入された理由も、ここから分かります。従来の書き方には判定した型とキャストする型を書き間違えられる穴がありました。
if (a instanceof B) { C c = (C) a; } はコンパイルが通り、実行時に落ちます。パターンマッチングは判定と変数宣言を1つの構文に閉じ込めることで、この食い違いを構造的に起こせなくしました。if を抜けると変数が消えるのも、判定が保証している範囲の外では意味を持たないからです。

パターン変数のスコープ

ここが唯一ややこしく、そのぶん出題されます。スコープは「その変数が確実に代入されている範囲」です。

&& では使えるOK
if (o instanceof String s && s.length() > 3) { }
// && の右側は「左が true のとき」しか評価されない → s は確実に存在する
|| では使えないNG
if (o instanceof String s || s.isEmpty()) { }
// コンパイルエラー: cannot find symbol
// || の右側は「左が false のとき」に評価される → s は存在しない
else 側で使う ── 黒本の定番最頻出
A[] array = { new A(), new B(), new A(), new B() };

for (A a : array) {
    if (a instanceof B b) {
        a.test();
    } else {
        b.test();          // コンパイルエラー
    }                      // error: cannot find symbol / symbol: variable b
}

else に来たということは instanceof が false だったということです。b に入れる値が無かったので、変数そのものが作られていません。
選択肢には ABAB BBBB AAAA ABBA と出力パターンが並びますが、その手前でコンパイルが通りません。配列の中身を追う必要すらありません。

パターンマッチングが出てきたら、出力を追う前にスコープを確認するのが速いです。
① パターン変数はどこで宣言されたか
② 使っている場所は「判定成功が確定した範囲」か
③ 範囲外ならそこで終わり
なお else だから使えない、と覚えると否定形で逆になったときに落とします。! を付ければ成功が確定する世界が else 側に移り、そちらで使えるようになります。

if を抜けると消えるNG
if (o instanceof String s) { }
System.out.println(s);      // コンパイルエラー: cannot find symbol
否定すると else 側で使える要注意
if (!(o instanceof String s)) {
    System.out.println("String ではない");   // ここでは s は使えない
} else {
    System.out.println(s.toUpperCase());     // ここでは使える
}

丸暗記ではなく「その位置に来たとき、判定は成功していたか」で判断してください。成功が確定している場所でだけ使えます。&& の右、if の中、否定した場合の else の中 ── いずれも「true だった」ことが確定している場所です。

その他の規則

null は常に false要注意
Object n = null;
System.out.println(n instanceof String);      // false（例外にはならない）
if (n instanceof String s) { }                // 中に入らない
無関係な型はコンパイルエラーNG
String s = "x";
System.out.println(s instanceof Integer);
// エラー: incompatible types: String cannot be converted to Integer

継承関係がまったく無い型どうしの instanceof は、実行するまでもなく false と分かるのでコンパイルエラーになります。Object 型の変数なら何とでも比較できます。

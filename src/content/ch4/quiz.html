Q1クラスに A(int x) だけを定義した。new A() は？

コンパイルエラー。デフォルトコンストラクタが自動生成されるのは、コンストラクタを1つも書かなかったときだけです。

Q2class B { void B(){} } はコンパイルできる？

できる。戻り値型が付いているのでコンストラクタではなくただのメソッドです。コンストラクタは1つも無いのでデフォルトが生成され、new B() も成功します。

Q3コンストラクタで name = name; と書くとどうなる？

エラーにはならず、フィールドは既定値のまま。引数に引数を代入しているだけです。フィールドを指すには this.name = name; が必要。出力を問う問題で null や 0 が正解になります。

Q4this() はどこに書ける？

コンストラクタの最初の1文だけ。自分自身は呼べず、メソッドからも呼べません。super() も先頭を要求するので、両方を同時に書くことはできません。

Q5戻り値の型だけが違うメソッドはオーバーロードになる？

ならない。コンパイルエラー。区別に使われるのは引数リストだけです。引数名だけ、アクセス修飾子だけの違いも同様にエラー。

Q6n(long) と n(Integer) があるとき n(5) はどちらを呼ぶ？

n(long)。優先順位は完全一致 → 拡大変換 → ボクシング → 可変長引数。手間の少ない方から試されます。

Q7k(Integer) と k(int...) があるとき k(5) は？

k(Integer)。ボクシングは可変長引数より優先されます。可変長引数は常に最後の手段です。

Q8static メソッドからインスタンス変数を参照できる？

できない。インスタンスが1つも無くても呼べるので、「どの実体の変数か」が決まりません。this も使えません。逆向き（インスタンス→static）は可能です。

Q9null の変数から static メソッドを呼ぶとどうなる？

正常に動く。NPE にならない。static メンバはコンパイル時に クラス名.メンバ へ読み替えられ、参照を使わないためです。

Q10static ブロックとインスタンス初期化ブロック、どちらが先？

static が先。しかもクラスにつき1回だけ。順序は「static変数・staticブロック（書いた順）」→ main → new のたびに「インスタンス変数・初期化ブロック（書いた順）」→ コンストラクタ本体。

Q10b初期化ブロックがコンストラクタより下に書かれていたら、どちらが先に動く？

初期化ブロックが先。コンストラクタ本体は常に最後です。ソース上の並び順が効くのは初期化子どうしの間だけ。ブロックの中身が各コンストラクタの先頭にコピーされる、と考えると位置が無関係な理由が分かります。

Q10cstatic int num; と { num = 10; } を持つクラスで、new せずに Sample.num を表示すると？

0。static フィールドへの参照はクラスの初期化しか起こしません。インスタンスが作られないので、インスタンス初期化ブロックもコンストラクタも実行されず、既定値のままです。new Sample(); を挟めば 100 になります。

Q11メソッドに配列を渡し、中で arr[0]=100 とした。呼び出し元は変わる？

変わる。渡されるのは矢印のコピーですが、指す先は同じ実体だからです。ただし arr = new int[]{...} と差し替えた場合は呼び出し元に影響しません。

Q12if (o instanceof String s || s.isEmpty()) は？

コンパイルエラー。|| の右側は「左が false のとき」に評価されるので、s が存在しません。&& なら使えます。

Q12bif (a instanceof B b) の中で a はまだ使える？

使える。パターンマッチングは a を変換するのではなく、新しい変数 b を作るだけです。a == b は true（同じ実体）。a の宣言型は A のままなので B 固有のメソッドは b から呼びます。

Q12cif (a instanceof B b) { a.test(); } else { b.test(); } の結果は？

コンパイルエラー。else は instanceof が false だった側なので b は存在しません。出力パターンの選択肢に惑わされず、先にスコープを確認します。

Q13if (!(o instanceof String s)) { A } else { B }。s が使えるのは？

B（else 側）だけ。「その位置に来たとき判定は成功していたか」で決まります。否定した場合、成功が確定しているのは else 側です。

Q14null instanceof String の結果は？

false。例外にはなりません。パターン変数を使う形でも、中に入らないだけです。

Q15record Point(int x, int y) の値の取り出し方は？

p.x()。getX() ではありません。p.x（括弧なし）もフィールドが private なのでエラーです。

Q16コンパクトコンストラクタで this.x = x; と書くと？

cannot assign a value to final variable x。コンパクト形式で触れる x は引数変数です。加工したいときは x = x * 10; と引数の方に代入します。代入はコンパイラが最後に自動追加。

Q17正規コンストラクタを自分で書き、片方のフィールドへの代入を忘れると？

variable y might not have been initialized。正規形式（引数リストがコンポーネントと一致）を書いた場合は、全フィールドを自分で代入する必要があります。

Q18コンポーネントと引数が違うコンストラクタを追加できる？

できるが、最初の1文で this(...) を呼ぶ必要がある。直接 this.x = ... と代入すると constructor is not canonical, so its first statement must invoke another constructor になります。初期化の経路を1本に絞る仕組みです。

Q18brecord Data(String value) に public Data() { } を足した。修正方法は？

2通り。①正規にする＝Data(String value) と引数を取り、かつ this.value = value; で初期化する（両方セットで必要。引数だけ直すと variable value might not have been initialized に変わるだけ）。②委譲する＝this("sample"); を第1文に置く。

Q18crecord のオーバーロードされたコンストラクタで super(); は使える？

使えない。record は暗黙に java.lang.Record を継承していますが、super() を明示的に呼ぶことはできません。「スーパークラスのコンストラクタを呼ぶ」という選択肢は常に誤りです。this(); も自分自身を呼ぶので recursive constructor invocation になります。

Q18dコンパクトコンストラクタの中で this.value を読むのは？

不可。variable value might not have been initialized。代入はブロックの最後に自動追加されるので、ブロック内ではフィールドは未代入です。書くことも読むこともできません。this. を外して引数変数 value を見れば通ります。

Q18einterface Test { default void value(){} } を record Data(String value) が実装すると？

コンパイルエラー。自動生成されるアクセサは String value()、インタフェースは void value()。名前と引数が同じで戻り値型だけ違うのでオーバーライドが成立しません。戻り値型を揃えれば通り、アクセサが default に勝ちます。

Q19record にメソッドは書ける？

書ける。インスタンスメソッド・static メソッド・static フィールドは自由です。アクセサや toString の上書きも可。禁止はインスタンスフィールドの追加だけ（field declaration must be static）。

Q20record はインタフェースを実装できる？ 継承は？

実装は可、継承は不可。暗黙に final なので継承されず（cannot inherit from final）、暗黙に java.lang.Record を継承済みなので extends も書けません。上下とも塞がっていると覚えます。

Q21public record R(int x) の標準／正規コンストラクタを private にできる？

できない。attempting to assign stronger access privileges; was public。record 本体より狭くはできません。

Q22record A(int[] arr) で、中身が同じ2つを equals で比べると？

false。自動生成の equals は参照型のコンポーネントをその型の equals で比べます。配列の equals は参照比較なので一致しません。「record は常に中身で比較」は配列のときだけ成り立ちません。

Q23javap で record を見ると、クラス宣言はどう表示される？

public final class Point extends java.lang.Record。ソースに書いていない final が付いており、親も既に埋まっています。継承も被継承も不可な理由がこの1行に出ています。

Q24コンポーネントが0個の record やローカル record は書ける？

どちらも書ける。record Empty() { } は Empty[] と表示され、メソッド内に定義するローカル record も可能です。可変長引数（int... nums）やジェネリックもコンポーネントにできます。ネストした record は暗黙に static。

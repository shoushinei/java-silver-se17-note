null との付き合い方

この章の問題で最も多く問われるのが null です。判定基準は1行で足ります。

null に「ドット」を付けたら NullPointerException。付けなければ安全。

安全な操作

ドットがないOK
String s = null;

s = null;                    // 代入
s == null;                   // 比較 → true
System.out.println(s);       // "null" と表示される
System.out.println("a" + s); // "anull"
String.valueOf(s);           // "null" ← static メソッド
"abc".equals(s);             // false  ← 呼ぶ側が null でない
Arrays.toString(null);       // "null" ← static メソッド

例外になる操作

ドットがある実行時
String s = null;
s.length();          // ① メソッド呼び出し
s.equals("abc");     // ①

int[] a = null;
a.length;            // ② フィールドアクセス（配列の length を含む）
a[0];                // ③ 添字アクセス

Integer i = null;
int j = i;           // ④ アンボクシング ← ドットは無いが裏で intValue() が呼ばれる

④だけがドットのない例外です。ラッパー型から基本データ型への代入だけは要注意。第3節のボクシングの話とつながります。

「配列そのもの」と「配列の中身」を区別する

length が動くかどうかで見分ける最重要
String[] a = new String[3];    // 配列はある。中身が null
a.length;          // 3        ← OK
a[0];              // null     ← OK
a[0].length();     // NullPointerException

String[] b = null;             // 配列そのものがない
b.length;          // NullPointerException
b[0];              // NullPointerException
どこが null か.length[0][0].xxx()
配列そのもの例外例外例外
配列の中身OKOK（null が返る）例外

拡張for文での挙動

取り出すだけなら止まらない要注意
String[] arr = {"A", null, "C", "D"};

for (String s : arr) System.out.print(s);          // "AnullCD"
for (String s : arr) System.out.print(s.length()); // 2周目で例外（1文字目は出力済み）

拡張for文の走査そのものは null があっても止まりません。取り出した後にドットを付けたときだけ落ちます。

コレクションでの null

ArrayList には null を入れられるOK
List<String> list = new ArrayList<>();
list.add(null);           // OK
list.size();              // 1  ← null も1個として数えられる
list.get(0);              // null
list.contains(null);      // true
list.get(0).length();     // NullPointerException

List.of("a", null);       // NullPointerException ← 生成時点で落ちる

第6章の判定基準がそのまま使えます。null は「呼ばれたとき」だけ例外になるので、選択肢を読むときは「ドットがあるか」だけを探してください。

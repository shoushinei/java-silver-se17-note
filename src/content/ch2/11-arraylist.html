ArrayList

公式チェックリストに「ArrayList の使用」が独立項目として明記されています。Bronze では出題されない範囲なので、ここも新規に固めてください。

基本形形
import java.util.ArrayList;
import java.util.List;

List<String> list = new ArrayList<>();

java.util パッケージなので、import が必要です。java.lang と違い自動 import されません。

型引数のルール

4つの書き方はすべてコンパイルが通る要注意
ArrayList<String> a = new ArrayList<>();          // 標準形
ArrayList<String> b = new ArrayList<String>();    // 冗長だが可
ArrayList<String> c = new ArrayList();            // 右辺が raw。警告は出る
ArrayList          d = new ArrayList<>();         // 左辺が raw。警告は出る

ArrayList<String> e = new ArrayList<Integer>();   // コンパイルエラー: 不一致
List<int>         f = new ArrayList<>();          // コンパイルエラー: 基本データ型は不可

「raw type だからコンパイルエラー」という選択肢は誤りです。互換性のため許されており、警告が出るだけです。

raw type は異なる型を混ぜられる要注意
ArrayList list = new ArrayList<>();
list.add("x");        // OK
list.add(10);         // OK。混ざる
list.add(true);       // OK

Object o = list.get(0);            // OK。安全
String s = list.get(0);            // コンパイルエラー: Object が返る
String t = (String) list.get(0);   // OK
String u = (String) list.get(1);   // ClassCastException（実行時）

Object で受ければ安全ですが、Object のメソッドしか呼べません。キャストが唯一のリスク源です。

主要メソッド

add と set ── 割り込むか上書きするか

要素数が変わるかどうかで見分ける最重要
List<String> a = new ArrayList<>(List.of("A","B","C"));
a.add(1, "X");
System.out.println(a);          // [A, X, B, C]  ← B は消えず後ろへずれる
System.out.println(a.size());   // 4

List<String> b = new ArrayList<>(List.of("A","B","C"));
b.set(1, "X");
System.out.println(b);          // [A, X, C]     ← B が消える
System.out.println(b.size());   // 3

位置の境界 ── add は size まで、set は size-1 まで

飛び地は作れない最重要
List<String> list = new ArrayList<>();
list.add("A");                 // [A]   size 1

list.add(1, "B");              // OK。size と同じ位置＝末尾に追加と同義
list.add(3, "C");              // IndexOutOfBoundsException

list.set(1, "X");              // OK（size 2 なので 0〜1）
list.set(2, "X");              // IndexOutOfBoundsException

ArrayList は連続した並びなので、途中に空きを作れません。配列と違い「まだ存在しない位置」に代入することはできません。

remove ── 引数の型で動作が変わる

int リテラルだけが位置指定最重要
List<Integer> list = new ArrayList<>(List.of(10, 20, 30));

list.remove(1);                     // [10, 30] ← インデックス1を削除
list.remove(Integer.valueOf(10));   // [20, 30] ← 値10を削除
list.remove(new Integer(10));       // 同上（Object 版が選ばれる）

remove(int) と remove(Object) はオーバーロードです。完全一致 → 拡大変換 → ボクシング → 可変長引数という第4章の解決順序がそのまま効いています。

戻り値と例外も違う要注意
List<Integer> list = new ArrayList<>(List.of(10, 20, 30));

list.remove(Integer.valueOf(99));   // false。見つからなくても例外にならない
list.remove(99);                    // IndexOutOfBoundsException
値の削除は equals で判定される要注意
class Item { int id; Item(int id) { this.id = id; } }

List<Item> list = new ArrayList<>();
list.add(new Item(1));
list.remove(new Item(1));       // 削除されない！
System.out.println(list.size());    // 1

Item は equals() をオーバーライドしていないので参照比較になります。String なら中身が一致すれば削除されます（equals がオーバーライドされているため）。第8節の StringBuilder と同じ構造です。

拡張for文の中で変更すると壊れる

ConcurrentModificationException最重要
List<String> list = new ArrayList<>(List.of("A","B","C","D","E"));
for (String s : list) {
    if ("C".equals(s)) list.remove(s);
}
// A, B を経て C を削除した次の周で例外

名前に "Concurrent（並行）" と入っていますが、スレッドとは無関係です。「読んでいる最中に対象を作り変えた」ことを検知しているだけです。

仕組み ── cursor と size の一致

拡張for文は内部で Iterator を使っています。

実際の動き仕組み
Iterator<String> it = list.iterator();
while (it.hasNext()) {          // ① cursor != size を見るだけ
    String s = it.next();       // ② ここで初めて整合性をチェック
    ...
}

整合性チェックは next() の中にしかありません。だから next() に到達しなければ例外は起きません。

最後から2番目を削除すると例外にならない要注意
List<String> list = new ArrayList<>(List.of("A","B","C"));
for (String s : list) {
    if ("B".equals(s)) list.remove(s);
    else System.out.println(s);
}
// 出力は "A" だけ。C は取りこぼされるが例外は起きない

// B を取り出した直後: cursor = 2
// remove 後:          size   = 2
// hasNext(): 2 != 2 → false → ループ終了

n 個の k 番目を取り出した直後の cursor は k。削除後の size は n-1。一致するのは k = n-1、つまり「最後から2番目」を削除したときだけです。

判定手順：削除するのが最後から2番目か → Yes なら静かに終了（最後の要素は出力されない）／No なら次の周で例外。

正しい削除の書き方

3つの方法OK
// ① Iterator の remove を使う
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if ("C".equals(it.next())) it.remove();
}

// ② 通常の for 文で後ろから回す
for (int i = list.size() - 1; i >= 0; i--) {
    if ("C".equals(list.get(i))) list.remove(i);
}

// ③ ループの外で削除する
List<String> toRemove = new ArrayList<>();
for (String s : list) if ("C".equals(s)) toRemove.add(s);
list.removeAll(toRemove);

リストの生成方法と変更可否

生成方法add / removeset呼び名
new ArrayList<>()○○可変リスト
new ArrayList<>(3)○○可変リスト（3は初期容量）
List.of(1,2,3)✗✗不変リスト
Arrays.asList(...)✗○固定長リスト
変更しようとすると例外最重要
var a = List.of(1, 2, 3);
a.add(4);          // UnsupportedOperationException
a.set(0, 9);       // UnsupportedOperationException
List.of(1, null);  // NullPointerException ← null も入れられない

var b = Arrays.asList(new Integer[]{1, 2, 3});
b.add(4);          // UnsupportedOperationException
b.set(0, 9);       // OK ← サイズ変更ではないので通る

new ArrayList<>(3) の 3 を「要素3個」と読むと間違えます。これは初期容量で、StringBuilder(16) と同じ意味です。size() は 0 で、いくらでも追加できます。

Arrays.asList が set だけ通るのは、元の配列をそのまま包んでいるからです。配列は「長さは変えられないが中身は書き換えられる」ので、その性質がそのまま出ています。

元の配列と連動する要注意
Integer[] arr = {1, 2, 3};
List<Integer> list = Arrays.asList(arr);
list.set(0, 9);
System.out.println(arr[0]);   // 9 ← 元の配列も変わる
可変リストに変換するOK
List<Integer> a = new ArrayList<>(List.of(1, 2, 3));
a.add(4);      // OK

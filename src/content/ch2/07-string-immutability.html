String の不変性

String は不変（immutable）です。一度作られた文字列の中身は変わりません。「変更」に見える操作は、すべて新しいインスタンスを返しているだけです。

元の文字列は変わらない最重要
String s = "Hello";
s.concat(" World");
s.toUpperCase();
s.replace("H", "J");
System.out.println(s);   // Hello ← 何も変わっていない
戻り値を受け取れば変わるOK
String s = "Hello";
s = s.concat(" World");
System.out.println(s);   // Hello World

メソッドを呼んだだけで代入していないコードが頻出します。「変数が書き換わったはず」と思って選択肢を選ぶと落ちます。戻り値を受け取っているかを必ず目で確認してください。

== と equals()

リテラルは共有される最重要
String a = "Hello";
String b = "Hello";
System.out.println(a == b);        // true  ← 定数プールで同一インスタンス

String c = new String("Hello");
System.out.println(a == c);        // false ← new は必ず新規インスタンス
System.out.println(a.equals(c));   // true  ← 中身は同じ

文字列リテラルは定数プールに格納され、同じ内容なら同じインスタンスが使い回されます。new を書くと、必ず別のインスタンスが作られます。

連結が定数式かどうかで変わる要注意
String a = "Hello";
System.out.println(a == "Hel" + "lo");   // true  ← コンパイル時に確定

String h = "Hel";
System.out.println(a == h + "lo");       // false ← 実行時に生成される

final String f = "Hel";
System.out.println(a == f + "lo");       // true  ← final なら定数式

ここでも final の1語で結果が反転します。コンパイル時に値が確定するかという同じ判定基準が、型変換・String 比較・第6章の multi-catch すべてに共通して効いています。

intern() ── 定数プールにある同じ中身のインスタンスを取り出す

戻り値はプールのインスタンス要注意
String a = "Hello";                 // プールのインスタンス
String b = new String("Hello");     // new で新しく作られた別のインスタンス
String c = b.intern();              // プールから同じ中身のものを取り出す

System.out.println(a == b);         // false
System.out.println(a == c);         // true  ← c はプールのインスタンス
System.out.println(b == c);         // false ← b が指す先は変わらない

intern() は、同じ中身の文字列が定数プールにあればそれを返し、無ければプールに登録してから返すメソッドです。戻り値は必ずプールのインスタンスなので、同じ中身どうしなら == が true になります。

呼んだだけでは何も変わらない頻出
String a = "Hello";
String b = new String("Hello");
b.intern();                                    // 戻り値を捨てている
System.out.println(a == b);                    // false ← b は new したインスタンスのまま

String h = "Hel";
System.out.println(a == h + "lo");             // false ← 実行時に作られた別インスタンス
System.out.println(a == (h + "lo").intern());  // true  ← intern() でプールのものに揃う

b.intern() は変数 b の指す先を書き換えるメソッドではありません。プールの参照を戻り値として返すだけなので、受け取らなければ何も起きません。この節の冒頭の「戻り値を代入しない限り変わらない」と同じ構造で、b.intern(); と書いただけのコードが引っかけとして出ます。

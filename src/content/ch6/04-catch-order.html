04

catch の順序

サブクラスを先に、スーパークラスを後に。これが唯一のルールです。

子 → 親 の順OK
try {
} catch (IOException e) {      // 子
} catch (Exception e) {        // 親
}
親 → 子 の順NG
try {
} catch (Exception e) {        // 親が先に全部捕まえる
} catch (IOException e) {      // コンパイルエラー: 到達不能
}

後者がエラーになるのは、Exception が先に全部を捕まえてしまい、下の IOException が到達不能になるからです。エラーメッセージにも「到達できない catch ブロック」と出ます。

上から順に評価され、最初にマッチした1つだけが実行されます。複数の catch が続けて動くことはありません。

また、継承関係にない例外どうしなら順序は自由です。IOException と SQLException に親子関係はないので、どちらが先でも通ります。

発生し得ない検査例外を catch すると

投げられない検査例外の catchNG
try {
    System.out.println("x");   // IOException を投げる可能性がない
} catch (IOException e) {      // コンパイルエラー
}

ただし Exception と RuntimeException（およびその子孫）は常に catch してよいという例外扱いです。非検査例外はどこでも発生し得るためです。

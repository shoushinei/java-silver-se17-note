一問一答

問題を解く前の自己確認用です。答えを開く前に、頭の中で言い切れるか試してください。

Q1検査例外の定義を1行で言うと？

Exception の子孫で、かつ RuntimeException の子孫でないもの。Error 系と RuntimeException 系はすべて非検査です。

Q2try { } だけを書くとどうなる？

コンパイルエラー。catch か finally が最低1つ必要です。ただし try-with-resources なら try 単体で成立します。

Q3catch (Exception e) の後に catch (IOException e) を書くと？

コンパイルエラー。親が先に全部捕まえるため、下の catch が到達不能になります。子 → 親の順が正解です。

Q4catch (IOException | FileNotFoundException e) は？

コンパイルエラー。FileNotFoundException は IOException の子なので、multi-catch に親子関係のある例外は並べられません。

Q5multi-catch の変数 e に再代入できる？

できない。暗黙的に final です。単一の catch なら再代入できます。

Q6try { return val; } finally { val = 100; } の戻り値は？

return した時点の値。return で値が退避されるため、finally での書き換えは戻り値に影響しません。

Q7try で例外を投げ、finally に return 2; があると？

例外は握りつぶされ、2 が返る。finally の return は tryの return も例外も上書きします。

Q8finally が実行されないケースは？

System.exit() が呼ばれたときだけ。JVM ごと終了するためです。

Q9try-with-resources で、close と catch はどちらが先？

close が先。try → close → catch → finally の順です。リソースの後始末が終わってから例外処理に入ります。

Q10try (A a = new A(); B b = new B()) で閉じられる順は？

b → a の逆順。後に宣言したものから閉じます。

Q11親が throws IOException。子で throws Exception は？

コンパイルエラー。検査例外は広げられません。逆に throws FileNotFoundException や throws なしは OK。非検査例外は自由に追加できます。

Q12カスタム例外を非検査にしたいときの継承元は？

RuntimeException。Exception を継承すると検査例外になります。あわせて、コンストラクタは継承されないので自分で定義する必要があります。

Q+1try (Res r = new Res()) の括弧の中は何をしている？

ただの変数宣言。Res r = new Res(); と同じで、コンストラクタが動いてリソースを開きます。close() はここには書かれておらず、ブロックを抜けるときにコンパイラが生成した呼び出しが走ります。

Q+2AutoCloseable の中身は？

void close() throws Exception; の抽象メソッド1つだけ。java.io.Closeable はそのサブインタフェースで、例外を IOException に狭めています（オーバーライドで検査例外を狭めるのは可）。

Q+3close() メソッドを持っているのに try(...) に書けないのはなぜ？

implements AutoCloseable が無いから。コンパイラはメソッド名ではなく型で判断します（Res cannot be converted to AutoCloseable）。逆に implements だけ書いて close() を実装しないと、抽象メソッド未実装のエラーです。

Q+4close() は具体的に何をする？

自分で書く。決まった処理は無い。典型は「コンストラクタで開いたものを閉じる」。GC が回収するのは Java のメモリだけで、OS 側のファイルハンドルや DB 接続は対象外なので、明示的に返す必要があります。

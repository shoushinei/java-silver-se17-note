クラス階層と3つの分類

すべての判断はこの階層から派生します。catch の順番も multi-catch も「どちらが親か」で決まるので、親子関係そのものを覚えておく必要があります。

検査検査例外（catch か throws が必須）非検査非検査例外

検査例外かどうかの判定は、次の1行がすべてです。

Exception の子孫で、かつ RuntimeException の子孫でないものが「検査例外」。それ以外（Error 系と RuntimeException 系）はすべて「非検査例外」です。

名前だけでは判定できない組が狙われます。

  • IOException は RuntimeException の子ではない（兄弟）。だから検査例外
  • NumberFormatException は RuntimeException の孫。「Format」でも入出力とは無関係で、非検査
  • FileNotFoundException と NoSuchFileException は IOException の子孫。検査例外
  • ArrayIndexOutOfBoundsException と StringIndexOutOfBoundsException は兄弟。親は共通の IndexOutOfBoundsException
  • Error は Exception の子ではない。catch (Exception e) では捕まらない

catch に並べるときの親子早見表

同じ try に並べるなら、左の列（子）を上、右の列（親）を下に書きます。逆にすると下の catch に到達できず、コンパイルエラーです（節04）。multi-catch の | には、同じ行の2つを並べられません（節05）。

親子関係を知らないと解けない3問最頻出
try { Integer.parseInt(s); }
catch (IllegalArgumentException e) { }
catch (NumberFormatException e) { }            // コンパイルエラー: 親が先

try { arr[i] = 1; }
catch (IndexOutOfBoundsException e) { }
catch (ArrayIndexOutOfBoundsException e) { }   // コンパイルエラー: 親が先

try { new FileReader("a.txt"); }
catch (FileNotFoundException | IOException e) { }   // コンパイルエラー: 親子を | で並べた
親子関係が無い（兄弟）なら順番は自由、| でも並べられるOK
catch (ArithmeticException e) { } catch (NullPointerException e) { }      // どちらが先でもよい
catch (ArithmeticException | NullPointerException e) { }                  // OK
catch (Exception e) { } catch (Error e) { }                                // OK。Error は Exception の子ではない
catch (FileNotFoundException e) { } catch (IOException e) { }              // OK。子 → 親の順

例外以外も含めた標準クラスの親子関係は、第5章 14「型の親子関係 総まとめ」にまとめています。

3分類の実質的な違いは 「処理を書かないとコンパイルエラーになるか」だけです。この一点を軸に選択肢を切っていけば、分類問題はほぼ落としません。

検査例外を投げるのに宣言がないNG
void m() {
    throw new IOException();   // コンパイルエラー
}
throws で宣言すれば通るOK
void m() throws IOException {
    throw new IOException();
}
非検査例外は何も要らないOK
void m() {
    throw new RuntimeException();   // 宣言も catch も不要
}

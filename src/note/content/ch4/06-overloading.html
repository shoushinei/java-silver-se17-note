メソッドのオーバーロード

同じ名前で複数のメソッドを定義することです。成立条件は引数リストが違うこと、それだけです。

違うものオーバーロードになるか
引数の型○
引数の数○
引数の順序（型が違う場合）○
戻り値の型だけ× コンパイルエラー
引数名だけ× コンパイルエラー
アクセス修飾子だけ× コンパイルエラー
戻り値型は区別に使われない頻出
void m(int x) { }
int  m(int x) { return 0; }
// エラー: method m(int) is already defined in class

どれが呼ばれるか ── 優先順位

候補が複数あるとき、コンパイラはこの順で探します。上で見つかればそこで確定します。

順位方法例
1完全一致m(5) → m(int)
2拡大変換m(5) → m(long)
3ボクシングm(5) → m(Integer)
4可変長引数m(5) → m(int...)
実際に確かめた結果最重要
static void n(long x)    { System.out.println("long"); }
static void n(Integer x) { System.out.println("Integer"); }
n(5);                    // long ← 拡大変換がボクシングより優先

static void k(Integer x) { System.out.println("Integer"); }
static void k(int... x)  { System.out.println("varargs"); }
k(5);                    // Integer ← ボクシングが可変長より優先

覚え方は「面倒な処理ほど後回し」です。拡大変換は数値を広げるだけ、ボクシングはオブジェクトを作る、可変長引数は配列を作る。コンパイラは手間の少ない方から試します。
第2章の「拡大変換とボクシングは組み合わせられない」もここに繋がります。m(Long) しかないところに int を渡すと、拡大してからボクシングはできないのでエラーになります。

順位は「使える候補」の中で比べる

コンパイラはまず、引数の数と型で呼び出せるメソッドだけを候補に残し、その中で上の順位を比べます。候補が1つしか残らなければ、順位に関係なくそれが選ばれます。

3つの候補に、いろいろな引数を渡す最頻出
static void show(double v)  { System.out.print("D"); }
static void show(Integer v) { System.out.print("I"); }
static void show(int... v)  { System.out.print("V"); }

byte b = 2;
show(b);                    // D  byte → double（拡大変換）
show(10);                   // D  int → double（拡大変換）。ボクシングと可変長より先
show('A');                  // D  char → double も拡大変換
show(10L);                  // D  long → double
show(Integer.valueOf(5));   // I  完全一致
show();                     // V  引数0個で呼べるのは int... だけ
show(1, 2);                 // V  引数2個も int... だけ

引っかかりやすいのは次の2点です。

  • 拡大変換は隣の型だけではありません。byte・short・char・int・long は、どれも double まで一気に届きます（第2章 03の図の右向き全部）。「10 は int だから int... に行く」は誤りで、可変長引数は他の候補が1つも使えないときの最後の手段です。
  • 可変長引数は「0個以上」を受け取ります。show() は長さ0の配列を渡す正しい呼び出しで、コンパイルエラーではありません（第4章 03）。引数を1つ要求する show(double) と show(Integer) は0個では呼べないので、候補は int... だけです。
候補が1つも無ければコンパイルエラー対比
static void show(double v) { }
show();     // コンパイルエラー: method show cannot be applied to given types

拡大変換の候補が複数あれば、一番近い型

long と double のどちらにも届くとき要注意
static void w(long v)   { System.out.print("L"); }
static void w(double v) { System.out.print("D"); }

w(1);       // L  int から近いのは long
w('c');     // L  char → int → long
w(1.5f);    // D  float から届くのは double だけ

ボクシングしてから広げるのは OK、広げてからボクシングは NG

変換の順番で結果が変わる要注意
static void o(Object v) { System.out.print("O"); }
static void l(Long v)   { }

o(1);       // O  int → Integer（ボクシング）→ Object（親の型へ）はできる
l(1);       // コンパイルエラー: int → long（拡大）→ Long（ボクシング）はできない

Integer は Object の子なので、ボクシングした後に Object 型の引数へ渡せます。一方、int を Long にするには「long に広げてからボクシング」の2段階が必要で、これは許されません。Long に渡したいなら 1L と書きます。

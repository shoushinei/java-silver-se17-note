static 変数と static メソッド

static が付いたものはクラスに1つ、付かないものはインスタンスごとに1つです。

共有されるかどうか基本
class Counter {
    static int shared;      // クラスに1つ
    int each;               // インスタンスごとに1つ
}

Counter a = new Counter();
Counter b = new Counter();
a.shared = 10;  a.each = 1;
b.shared++;     b.each = 2;

System.out.println(a.shared);   // 11 ← b の変更が a にも見える
System.out.println(a.each);     // 1  ← 独立している

アクセスの向きは一方通行

どこからstatic メンバへインスタンスメンバへ
インスタンスメソッド○○
static メソッド○×
static からインスタンスは見えない最頻出
class St {
    int f = 1;
    static void m() {
        System.out.println(f);       // コンパイルエラー
        // non-static variable f cannot be referenced from a static context
        System.out.println(this);    // エラー: static に this は存在しない
    }
}

理由はstatic メソッドはインスタンスが1つも無くても呼べるからです。呼ばれた時点で「どの実体の f か」が決まらないので、参照しようがありません。
逆向き（インスタンスメソッドから static）は、クラスが読み込まれている以上 static は必ず存在するので、問題なく使えます。
main が static であるがゆえに、そこからインスタンス変数を直接触れないのも同じ理由です。

インスタンス経由でも static は同じ実体要注意
Counter a = null;
System.out.println(a.shared);    // NullPointerException にならない！

// static メンバは参照ではなくクラスで解決されるため、
// a.shared は Counter.shared に読み替えられる

null の変数から static メンバを呼んでも例外になりません。コンパイル時に クラス名.メンバ へ読み替えられるからです。
「null.静的メソッド() は NPE になる」という選択肢は誤りです。

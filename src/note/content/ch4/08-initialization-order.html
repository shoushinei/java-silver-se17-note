08

初期化の順序

出力順を問う問題が出ます。static は最初に1回だけ、インスタンス側は new のたびと覚えます。

実行して確認した順序最重要
class Init {
    static int s = p("① static変数");
    static { p("② static初期化ブロック"); }
    int i = p("④ インスタンス変数");
    { p("⑤ インスタンス初期化ブロック"); }
    Init() { p("⑥ コンストラクタ"); }

    public static void main(String[] a) {
        p("③ main開始");
        new Init();
        p("--- 2個目 ---");
        new Init();
    }
}

// 出力:
// ① ② ③ ④ ⑤ ⑥
// --- 2個目 ---
// ④ ⑤ ⑥          ← static 側は2回目には走らない

順序の原理は「クラスの準備 → 実体の準備」です。
1回目：クラスがロードされ、static 変数と static ブロックが書いた順に実行される（クラスにつき1回だけ）。
new のたび：インスタンス変数と初期化ブロックが書いた順に実行され、最後にコンストラクタ本体が走ります。
変数とブロックは種類でまとめられるのではなく、ソース上の並び順で実行されます。

罠① 書いた位置とコンストラクタの関係

初期化ブロックがコンストラクタより下に書かれていても、実行はコンストラクタ本体より先です。

順序は位置で決まらない最頻出
class Sample {
    Sample() { System.out.println("A"); }     // ソース上は先
    { System.out.println("B"); }              // ソース上は後
}

new Sample();

// 出力:
// B      ← 初期化ブロックが先
// A      ← コンストラクタ本体は最後

コンストラクタ本体は常に最後です。ソース上の並び順が効くのは初期化子どうしの間だけ（インスタンス変数の初期化と初期化ブロックの相対順）で、コンストラクタとの前後関係には影響しません。
コンパイラは初期化ブロックの中身を各コンストラクタの先頭（super() の直後）にコピーする、と考えると腑に落ちます。だから位置は無関係で、どのコンストラクタで new しても実行されます。ただし this(...) で始まるコンストラクタにはコピーされません（下の罠③）。

罠② new しなければ走らない

インスタンス初期化ブロックは、名前のとおりインスタンスを作るときにしか動きません。

static フィールドを読むだけでは動かない最頻出
class Sample {
    static int num;                   // 既定値 0
    { num = 10; }                     // インスタンス初期化ブロック
    public Sample() { num = 100; }
}

System.out.println(Sample.num);       // 0

// new していないので、初期化ブロックもコンストラクタも一度も実行されない

Sample.num という参照はクラスの初期化（static 側）しか引き起こしません。static 変数と static ブロックは走りますが、インスタンスは1つも作られないので、インスタンス初期化ブロックとコンストラクタは動きようがありません。
結果、num は既定値の 0 のままです。

new すれば動く要注意
System.out.println(Sample.num);       // 0
new Sample();                         // 初期化ブロック → コンストラクタ の順
System.out.println(Sample.num);       // 100

インスタンス初期化ブロックの中から static 変数を書き換えること自体は合法です。ただし new されるまでは反映されません。「静的な変数を触っているから静的に動く」と考えると間違えます。ブロックの種類が実行タイミングを決めるので、中身が何を触っているかは無関係です。

この2問は組で出ます。判定手順は次の2段階です。
① new があるか ── 無ければインスタンス側は一切動かない
② 初期化ブロック → コンストラクタ本体 ── 位置に関係なくこの順
選択肢に「コンパイルエラー」が並びますが、どちらも文法上は正しいコードです。

罠③ this(...) で始まるコンストラクタでは動かない

初期化ブロックは1回の new で1回だけ要注意
class Box {
    { System.out.print("I "); }       // インスタンス初期化ブロック
    Box() {
        this(10);                     // 別のコンストラクタへ
        System.out.print("A");
    }
    Box(int size) {
        System.out.print("B" + size + " ");
    }
}

new Box();

// 出力: I B10 A    ← I は1回だけ。Box(int) の中で、その本体より先に動く

初期化ブロックとインスタンス変数の初期化がコピーされるのは、super(...)（書かなければ暗黙の super()）を呼ぶコンストラクタだけです。this(...) で始まるコンストラクタにはコピーされません。もしコピーされたら、1回の new で同じ初期化が2回動いてしまうからです。
流れは「Box() → this(10) で Box(int) へ → 暗黙の super() → 初期化ブロック → Box(int) の本体 → Box() の残り」です。継承と組み合わせた順番は第5章 02で確認できます。

アクセス修飾子の到達範囲

アクセス修飾子は「どこまで名前が届くか」を決めます。パッケージという境界があって初めて意味を持つので、パッケージとセットで覚えるのが正しい順序です。

修飾子同じクラス同じパッケージ別パッケージの
サブクラス		それ以外
public○○○○
protected○○△×
修飾子なし
（package private）		○○××
private○×××

覚え方は「クラス → パッケージ → 継承 → 全世界」の4段階です。上から順に1段ずつ壁が広がっていきます。表を丸暗記するのではなく、private が最も狭く public が最も広い、その途中に「パッケージまで」と「パッケージ＋継承先まで」の2段があると理解してください。

修飾子なし＝パッケージプライベート

パッケージの外からは見えないNG
// a/Base.java
package a;
public class Base {
    int pkg = 3;                  // 修飾子なし
}

// b/Pkg.java
package b;
import a.Base;
public class Pkg {
    void t(Base x) { System.out.println(x.pkg); }
}
// error: pkg is not public in Base; cannot be accessed from outside package

default というアクセス修飾子は存在しません。「デフォルト」「パッケージプライベート」と呼ばれますが、書くのは何も書かないことです。
default というキーワード自体は Java にありますが、それは switch のラベルとインタフェースのデフォルトメソッドの話で、アクセス修飾子ではありません。選択肢に default int x = 3; と出てきたらコンパイルエラーです。

protected の△が意味すること

ここがこの節で唯一ややこしい部分で、そのぶん頻出です。別パッケージのサブクラスは protected メンバに常にアクセスできるわけではありません。

参照の型で結果が変わる最重要
// a/Base.java
package a;
public class Base {
    protected int prot = 2;
}

// b/Sub.java
package b;
import a.Base;
public class Sub extends Base {
    void viaThis()       { System.out.println(this.prot); }   // OK
    void viaSub(Sub s)   { System.out.println(s.prot); }      // OK
    void viaBase(Base x) { System.out.println(x.prot); }      // コンパイルエラー
}
// error: prot has protected access in Base

別パッケージのサブクラスが protected メンバに触れるのは、自分自身か、自分と同じ型（またはそのサブクラス）の参照を通したときだけです。スーパークラス型の参照 Base x 経由では届きません。

理由は protected の目的にあります。これは「継承した自分の部品として使ってよい」という許可であって、「Base 型のオブジェクトなら誰でも中を覗いてよい」ではありません。Base x の中身が本当に Sub なのかは、コンパイル時にはわかりません。だから禁止されます。
同じパッケージ内であれば、そもそもパッケージの権限だけでアクセスできるので、この制限は関係ありません。

サブクラスでなければ public 以外は届かないNG
package b;
import a.Base;
public class Other {                          // extends していない
    void t(Base x) {
        System.out.println(x.pub);            // OK
        System.out.println(x.prot);           // コンパイルエラー
    }
}

継承と組み合わせたときの全体像は第5章 12「アクセス修飾子と継承」にまとめています。子クラスと同じパッケージの、継承していないクラスから子の参照経由で protected を呼ぶパターンなど、パッケージが違うときの判定を一覧にしてあります。

トップレベルのクラスに付けられる修飾子

2種類しか書けないNG
private   class Hidden  { }    // error: modifier private not allowed here
protected class Guarded { }    // error: modifier protected not allowed here

public class A { }             // OK
class B { }                    // OK（修飾子なし＝同一パッケージから見える）

トップレベルの型に付けられるのは public か修飾子なしの2択だけです。private と protected は「外側に自分を囲むものがある」ことが前提の修飾子なので、ファイル直下のクラスには意味を持ちません。
ネストしたクラス（クラスの中のクラス）なら4種類すべて使えます。

フィールドとメソッド以外

対象規則
インタフェースのメソッド暗黙に public。書かなくても public になる
インタフェースのフィールド暗黙に public static final
コンストラクタ4種類すべて使える。private にすると外部から new できない
ローカル変数付けられない。スコープはブロックで決まる
ローカル変数に修飾子は不可NG
void m() {
    private int x = 1;      // コンパイルエラー
    final   int y = 2;      // OK。final はアクセス修飾子ではない
}

第5章とつながります。オーバーライドではアクセス範囲を狭められません。protected のメソッドを修飾子なしでオーバーライドすると attempting to assign weaker access privileges; was protected になります。広げる（protected → public）のは自由です。

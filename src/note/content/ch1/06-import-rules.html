import と import static

まず「完全修飾名」── クラスの本当の名前

Java のクラスは、パッケージ名まで含めた名前が本当の名前です。これを完全修飾名といいます。ArrayList の本当の名前は java.util.ArrayList、Math は java.lang.Math です。

import を1行も書かなくても、完全修飾名なら使えるOK
public class Main {
    public static void main(String[] args) {
        java.util.List<String> list = new java.util.ArrayList<>();
        System.out.println(list);      // []
    }
}

毎回これを書くのは長いので、名前の前の部分を省略させてもらう宣言が import です。ほかのファイルを読み込んだり、コードをコピーしたりするわけではありません。import を書いても書かなくても、できあがるプログラムは同じです。

import と import static ── 省略できる部分が違う

import なしjava.util.ArrayList全部書く
import java.util.ArrayList;java.util.ArrayListパッケージ名を省略できる
import static なしjava.lang.Math.max(3, 7)java.lang は自動なので、クラス名から書く
import static java.lang.Math.max;java.lang.Math.max(3, 7)クラス名まで省略できる
パッケージ名クラス名static メンバ名線を引いた部分＝書かなくてよい
importimport static
省略できるものパッケージ名パッケージ名とクラス名
対象クラス・インタフェースなどの型クラスの static フィールド・static メソッド
書く形import パッケージ.クラス;
import パッケージ.*;		import static パッケージ.クラス.メンバ;
import static パッケージ.クラス.*;
どこで止めるかクラス名で止めるメンバ名（または *）まで書く
使うときの形List<String> listmax(3, 7)　PI

一言でいうと、import は「クラス名だけで書かせて」、import static は「メンバ名だけで書かせて」という宣言です。import static は、Math.max や Integer.parseInt のようにクラス名.メンバ名で呼ぶものから、クラス名を取り除きます。

正しい書き方は4つ

書き方読み込むもの使い方
import java.util.ArrayList;クラスを1つnew ArrayList<>()
import java.util.*;java.util の直下のクラス全部List ArrayList Map …
import static java.lang.Math.max;static メンバを1つ（同じ名前のオーバーロードは全部）max(3, 7) も max(1.5, 2.5) も
import static java.lang.Math.*;Math の static メンバ全部max(3, 7) PI abs(-1) …
import static でよく使うものOK
import static java.lang.Math.*;                // max, min, abs, PI …
import static java.lang.Integer.parseInt;      // static メソッド
import static java.lang.Integer.MAX_VALUE;     // static フィールド（定数）
import static java.lang.System.out;            // out も System の static フィールド

public class Main {
    public static void main(String[] args) {
        out.println(max(3, 7) + " " + PI);                 // 7 3.141592653589793
        out.println(parseInt("12") + " " + MAX_VALUE);     // 12 2147483647
    }
}

間違った書き方 ── 形で見分ける

書き方結果理由
static import java.lang.Math.max;エラー語順は import static。逆は書けない
import static java.lang.Math;エラーimport static はメンバ名（または *）まで書く。クラスで止めない
import java.lang.Math.max;エラーstatic を付けないと、最後は型の名前でなければならない。max は型ではない
import java.util;エラーパッケージ名だけは書けない。java.util.* と書く
import static java.lang.Math.max();エラーメソッドでも ( ) は付けない
import java.util.*.*;エラー* は最後に1つだけ
import static java.lang.String.length;エラーlength は static ではない（インスタンスメソッドは import static できない）
import java.lang.Math.*;文は OKMath の中の型を読み込む書き方（Math には無いので何も増えない）。max(3, 7) と書くと、そこでエラー

最後の行が一番の引っかけです。import java.lang.Math.*; 自体はコンパイルできます（import java.util.List.*; なども同じ）。でも static メンバは読み込まれないので、max や PI を名前だけで使った行でエラーになります。static メンバを名前だけで使いたいなら、必ず import static です。

import static はクラス名を読み込まない

メンバを読み込んでも、クラスそのものは別要注意
// util/Calc.java
package util;
public class Calc {
    public static int twice(int x) { return x * 2; }
    public int inst() { return 1; }                  // static でない
}

// app/Main.java
package app;
import static util.Calc.*;

twice(10);            // OK  20
inst();               // エラー: static でないメソッドは読み込まれない
Calc c = null;        // エラー: cannot find symbol ── Calc という型は import していない

型として Calc も使いたいなら、import util.Calc; を別に書きます。import と import static は役割の違う別々の文です。

自分のクラスに同じ名前のメソッドがあると、自分のメソッドが優先されます。import static java.lang.Math.max; があっても、クラスの中で static int max(int a, int b) を定義していれば、max(3, 7) はそちらを呼びます。

import が要らないとき

ケース理由
java.lang のクラスimport java.lang.*; が自動で書かれているのと同じ。String System Math Integer Object Exception など
同じパッケージのクラス同じパッケージどうしは、クラス名だけで届く
完全修飾名で書いたときjava.util.List と書けば、import は要らない

java.lang が自動で読み込まれるのはクラス名までです。Math.max(3, 7) は書けますが、max(3, 7) と書くにはやはり import static が要ります。また、import java.lang.String; のように自分で書いてもエラーにはなりません（無駄なだけ）。同じ import を2回書いてもエラーになりません。

* が届く範囲 ── 直下だけ

サブパッケージは含まない頻出
import java.util.*;

List<String> a;       // OK  java.util.List
TimeUnit t;           // エラー: cannot find symbol
                      // TimeUnit は java.util.concurrent にある。java.util の直下ではない

java.util.concurrent は名前が java.util で始まっているだけの別のパッケージです。パッケージは入れ子のフォルダではなく、ドットを含んだ1つの名前だと考えると間違えません。使うなら import java.util.concurrent.*; を別に書きます。同じ理由で、import java.*; は「java というパッケージは無い」というエラーになります。

名前がぶつかったとき

java.util.Date と java.sql.Date のように、違うパッケージに同じ名前のクラスがあることがあります。

書いた import結果
import java.util.*;
import java.sql.*;		import 自体は OK。Date を使った行でエラー（reference to Date is ambiguous）。使わなければエラーにならない
import java.util.*;
import java.sql.*;
import java.util.Date;		OK。* よりクラスを名指しした import が優先され、Date は java.util.Date になる
import java.util.Date;
import java.sql.Date;		import の行でエラー（使わなくてもエラー）。名指しどうしはぶつけられない
import java.util.Date; と、同じファイルに class Date {}エラー（Date is already defined in this compilation unit）

どちらも使いたいときは、片方（または両方）を完全修飾名で書きます。

完全修飾名で書けば import は要らないOK
java.util.Date d1 = new java.util.Date();
java.sql.Date  d2 = new java.sql.Date(0L);
強さ名前の見つけ方
1そのファイルで宣言したクラスと、クラスを名指しした import（import java.util.Date;）
2同じパッケージのクラス
3* の import（自動の java.lang.* も含む）。ここで2つ見つかると、使った行でエラー

import static どうしも同じ考え方です。import static java.lang.Integer.*; と import static java.lang.Long.*; を並べると、両方にある MAX_VALUE を使った行でエラーになります。片方を import static java.lang.Long.MAX_VALUE; のように名指しすれば、そちらが優先されます。

書く場所

順番は package → import → クラスNG
import java.util.*;     // エラー: package より前には書けない
package shop;

public class Cart { }

1つのファイルの中は、package 文（あれば1つ）→ import 文（いくつでも）→ クラスの宣言、の順です。import と import static どうしの順番は自由です。

import の規則

import は「このクラス名を短く書かせてほしい」という宣言です。コードを読み込むわけでも、性能に影響するわけでもありません。

2つの書き方OK
import java.util.List;      // 単一型インポート
import java.util.*;         // オンデマンドインポート（そのパッケージの全クラス）

import が要らない2つのケース

ケース理由
java.lang のクラス自動でインポートされる。String System Integer Math Object Exception など
同じパッケージのクラス姓が同じなので名前だけで届く

System.out.println がいきなり書けるのは、java.lang が自動インポートされているからです。逆に java.util.List や java.time.LocalDate は明示しないと使えません。
import java.lang.String; と書いてもエラーにはなりません。冗長なだけです。

ワイルドカードはサブパッケージを含まない

階層は降りてくれないNG
import java.util.*;

TimeUnit t;      // コンパイルエラー: cannot find symbol
                 // TimeUnit は java.util.concurrent にあり、java.util には無い

java.util.* が指すのは java.util 直下のクラスだけです。java.util.concurrent は名前が似ているだけの別パッケージで、使うには import java.util.concurrent.*; が別途必要になります。パッケージは入れ子の階層ではなく、ドットを含んだ1つの名前だと考えるのが正確です。

クラスの内側は指せないNG
import java.util.List.*;      // メソッドはインポートできない（static import を除く）
import java.util;             // パッケージ自体はインポートできない

名前が衝突した場合

曖昧さはコンパイルエラーNG
import java.util.*;
import java.sql.*;

Date d;      // コンパイルエラー: reference to Date is ambiguous
             // both class java.sql.Date and class java.util.Date match
解決策は2つOK
// ① 片方だけ単一型インポートする ── ワイルドカードより優先される
import java.util.*;
import java.sql.*;
import java.util.Date;              // これで Date は java.util.Date に確定

// ② 完全修飾名で書く ── import 自体が不要
java.util.Date d1 = new java.util.Date();
java.sql.Date  d2 = new java.sql.Date(0L);

優先順位は単一型インポート ＞ オンデマンドインポート。ただし単一型インポート同士で同じクラス名が衝突するとエラーです（import java.util.Date; と import java.sql.Date; の併記は不可）。その場合は完全修飾名しか手がありません。

static インポート

クラス名を省略して static メンバを使うOK
import static java.lang.Math.max;      // メソッド1つ
import static java.lang.Math.*;        // Math の static メンバ全部

System.out.println(max(3, 7));         // Math. を書かずに呼べる → 7

語順は import static です。static import と書くとコンパイルエラー。この1点だけを問う問題が出ます。
また、import static が指すのはクラスの static メンバであって、パッケージやクラス自体ではありません。

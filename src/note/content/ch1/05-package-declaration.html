パッケージ宣言

パッケージはクラスの姓にあたるものです。同じ名前のクラスが世界中にあっても、姓が違えば区別できます。

書ける順序は1通りしかない最重要
package com.example.app;       // ① package は必ず先頭（コメント以外の何よりも前）

import java.util.List;         // ② import は package の後、型宣言の前
import java.util.ArrayList;

public class Main { }          // ③ 型宣言

この順序が逆でも、重複してもコンパイルエラーです。package は1ファイルに最大1つ、しかも先頭。import の後ろに package を書いた選択肢は必ず誤りです。

順序違反NG
import java.util.List;
package foo;                   // コンパイルエラー
                               // class, interface, enum, or record expected
public class Main { }
package の前に書いてよいものOK
// コメントはいくつ書いてもよい
/* ブロックコメントも可 */
package com.example;           // OK

public class Main { }

ディレクトリ構造との対応

パッケージ名 = ディレクトリ階層図
package com.example.app;   の Main クラスは

bin/
└── com/
    └── example/
        └── app/
            └── Main.class

javac -d bin Main.java     // このディレクトリを自動で作ってくれる
java -cp bin com.example.app.Main   // 実行時は完全修飾名で指定する

パッケージに属するクラスを実行するとき、java コマンドには完全修飾名を渡します。java Main ではクラスが見つからずエラーです。正式な指定はドット区切りの com.example.app.Mainで、ここも定番です。
java com/example/app/Main は、実際の JDK では起動ランチャーが / を . に読み替えるので動きます。選択肢に両方あれば、正式なドット区切りを選んでください。-d と -cp の詳しい仕組みは第1章 08にあります。

パッケージ名がすべて小文字なのは慣習で、文法上の制約ではありません。ただし java で始まるパッケージ名は使用が禁止されています。

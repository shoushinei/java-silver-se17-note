ポリモーフィズムと参照型のキャスト

アップキャストは暗黙、ダウンキャストは明示基本
P p = new C();            // アップキャスト。暗黙に行われる
C c = (C) p;              // ダウンキャスト。明示的に書く必要がある

アップキャスト（子→親）が安全なのは、子は必ず親の性質をすべて持っているからです。逆は保証されないので、書き手が「これは C のはずだ」と明示する必要があります。

実体が違えば実行時例外実行時
P p2 = new P();
C c2 = (C) p2;
// ClassCastException: class P cannot be cast to class C

// コンパイルは通る。落ちるのは実行時

継承関係があるのにキャストが失敗するのは実行時。継承関係がまったく無い型どうしのキャストはコンパイルエラー。この2つを区別して選択肢を切ります。

安全な書き方OK
if (p instanceof C c) {          // 第4章 節09のパターンマッチング
    c.only();
}

宣言型が「呼べる範囲」を決める

子固有のメソッドは親型からは呼べない最頻出
class P { void m(){} }
class C extends P { void only(){} }

P p = new C();
p.m();          // OK
p.only();       // error: cannot find symbol ── P に only() は無い
((C)p).only();  // OK。キャストして宣言型を変える

「どのメソッドを書けるか」は宣言型、「どの実装が動くか」は実体型。この2軸の分離がポリモーフィズムの本体です。
コンパイラは実行時に何が入るかを知らないので、変数の型に書かれているものしか許可できません。

キャストはどこに掛かるか

キャストは . より結合が弱い頻出
P p = new C();
((C) p).only();     // OK。p を C として扱ってから only() を呼ぶ
(C) p.only();       // エラー: (C) (p.only()) と読まれる
                    //   P に only() は無く、キャストだけの式は文にもならない（not a statement）

キャストより、. によるメソッド呼び出しやフィールドの参照のほうが先に結びつきます。(C) p.only() は「p.only() の結果をキャストする」という意味になるので、子のメソッドを呼びたいときは ((C) p) のようにキャストした式全体を括弧で囲みます。

コンパイルが通るキャスト、通らないキャスト

キャスト元 → キャスト先コンパイル実行時
親クラス → 子クラス○実体が違えば ClassCastException
親子関係の無いクラス → クラス（兄弟など）×—
final でないクラス → インタフェース（実装していなくても）○実体が実装していなければ ClassCastException
final クラス → 実装していないインタフェース×—
インタフェース → インタフェース○実体しだい
インタフェースへのキャストは通りやすい要注意
class Animal { }
final class Stone { }
interface Pet { }

Animal a = new Animal();
Pet p1 = (Pet) a;       // コンパイルは通る → 実行時に ClassCastException
Stone s = new Stone();
Pet p2 = (Pet) s;       // コンパイルエラー: Stone は final で、Pet を実装していない

Animal は Pet を実装していませんが、Animal の子のどれかが Pet を実装しているかもしれないので、コンパイラは可能性を否定できず、キャストを許します。Stone は final で子を作れないので、Pet になる可能性が無く、エラーにできます。
クラス同士の場合は、親子関係の外にある型にはどうやってもなれないので、兄弟へのキャストはエラーです（節14）。

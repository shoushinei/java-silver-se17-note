ポリモーフィズムと参照型のキャスト

アップキャストは暗黙、ダウンキャストは明示基本
P p = new C();            // アップキャスト。暗黙に行われる
C c = (C) p;              // ダウンキャスト。明示的に書く必要がある

アップキャスト（子→親）が安全なのは、子は必ず親の性質をすべて持っているからです。逆は保証されないので、書き手が「これは C のはずだ」と明示する必要があります。

実体が違えば実行時例外実行時
P p2 = new P();
C c2 = (C) p2;
// ClassCastException: class P cannot be cast to class C

// コンパイルは通る。落ちるのは実行時

継承関係があるのにキャストが失敗するのは実行時。継承関係がまったく無い型どうしのキャストはコンパイルエラー。この2つを区別して選択肢を切ります。

安全な書き方OK
if (p instanceof C c) {          // 第4章 節09のパターンマッチング
    c.only();
}

宣言型が「呼べる範囲」を決める

子固有のメソッドは親型からは呼べない最頻出
class P { void m(){} }
class C extends P { void only(){} }

P p = new C();
p.m();          // OK
p.only();       // error: cannot find symbol ── P に only() は無い
((C)p).only();  // OK。キャストして宣言型を変える

「どのメソッドを書けるか」は宣言型、「どの実装が動くか」は実体型。この2軸の分離がポリモーフィズムの本体です。
コンパイラは実行時に何が入るかを知らないので、変数の型に書かれているものしか許可できません。

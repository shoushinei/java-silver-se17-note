シールクラス（sealed）

SE 17 で正式化。この試験の新規範囲で、11 の教材には載っていません。

sealed は継承・実装できる型を名指しで限定する修飾子です。

permits で相手を列挙する最重要
sealed interface Shape permits Circle, Square, Tri { }

record Circle(double r) implements Shape { }     // record は暗黙に final
final class Square implements Shape { }          // 打ち止め
non-sealed class Tri implements Shape { }        // 封を解く

class MyTri extends Tri { }                      // non-sealed なので継承できる

final が全面禁止、修飾子なしが全面開放だとすると、sealed はその中間を埋めるものです。
従来は「この型の実装は3種類だけ」という設計意図をコメントでしか表現できず、誰かが4つ目を作れてしまいました。sealed はその意図をコンパイラに強制させます。

実装側は3択を必ず宣言する

修飾子意味
finalここで完全に打ち止め
sealedさらに permits で限定して継承を許す
non-sealed封を解く。誰でも継承できる
書き忘れるとエラー最頻出
sealed interface S permits A { }
class A implements S { }
// error: sealed, non-sealed or final modifiers expected
permits に無い型は実装できない頻出
sealed interface S permits A { }
final class A implements S { }
final class B implements S { }
// error: class is not allowed to extend sealed class: S
//        (as it is not listed in its 'permits' clause)

record は暗黙に final なので、3択の宣言が不要です。sealed と record が組で出てくるのはこのためです。
non-sealed は Java で唯一ハイフンを含むキーワードです。

規則内容
付けられる先クラス・抽象クラス・インタフェース
permits の相手の場所同じパッケージ（モジュール使用時は同じモジュール）
permits の省略同一ファイル内なら可。コンパイラが推論する
sealed + final不可（意味が矛盾）
record に sealed不可（既に final）
別パッケージは permits できないNG
package p1;
public sealed interface X permits p2.Y { }
// error: class X in unnamed module cannot extend a sealed class
//        in a different package

sealed の本来の狙いは switch のパターンマッチングで網羅性を検査させることですが、switch のパターンマッチングは SE 17 ではプレビュー機能なので出題範囲外です。
SE 17 で問われるのは構文規則の方 ── permits の範囲、実装側の3択、場所の制約です。

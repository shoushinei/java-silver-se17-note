オーバーライドとオーバーロードの区別

オーバーライドオーバーロード
場所親子関係の間同じクラス内でもよい
引数リスト完全一致違う
戻り値型同じかサブ型無関係（区別に使われない）
どれが呼ばれるか実行時の実体型で決まるコンパイル時の宣言型で決まる
引数を1文字変えるとオーバーロードになる最頻出
class A { void m(int x){ System.out.println("A"); } }
class B extends A {
    void m(long x){ System.out.println("B"); }     // 引数が違う → オーバーロード
}

A a = new B();
a.m(5);        // A ← オーバーライドされていないので親のものが動く

オーバーライドのつもりで引数の型を書き間違えると、静かにオーバーロードになります。コンパイルは通り、出力だけが変わる。
@Override を付けていればここで止まります。黒本はこの引っかけを多用します。

呼ばれるメソッドは2段階で決まる

段階いつ何を見るか決まること
① オーバーロードの選択コンパイル時変数の型（宣言型）と、引数の宣言型どのシグネチャ（引数の形）を呼ぶか
② オーバーライドの選択実行時実体の型①で決めたシグネチャの、どのクラスのメソッドを動かすか
引数の実体が ArrayList でも、変数の型で選ばれる頻出
class Printer {
    void print(Collection<String> c) { System.out.print("C "); }
    void print(List<String> l)       { System.out.print("L "); }
}

Collection<String> c = new ArrayList<>();
Printer p = new Printer();
p.print(c);                        // C ← 変数 c の型は Collection
p.print((List<String>) c);         // L ← キャストで型を変えれば List 版
p.print(new ArrayList<String>());  // L ← ArrayList は List にも Collection にも合う。より具体的な List 版
① と ② が両方効く最頻出
class A {
    void who(Object o) { System.out.print("A-Object "); }
    void who(String s) { System.out.print("A-String "); }
}
class B extends A {
    void who(Object o) { System.out.print("B-Object "); }   // who(Object) だけオーバーライド
}

A a = new B();
Object o = "x";
a.who(o);       // B-Object
a.who("x");     // A-String

a.who(o): ① 引数 o の宣言型は Object。中身が文字列でも who(Object) が選ばれます。② 実体は B で、B は who(Object) をオーバーライドしているので「B-Object」。
a.who("x"): ① 引数は String なので who(String)。② B は who(String) をオーバーライドしていないので、A のものが動き「A-String」。
オーバーロードは「実体」を見ない、オーバーライドは「実体」を見る。この1行で両方の問題が解けます。

03

メソッドのオーバーライド

成立条件はシグネチャ（名前＋引数リスト）が完全一致すること。そのうえで4つの制約があります。

項目規則方向
戻り値の型同じ、またはサブ型（共変戻り値）狭めるのは可
アクセス修飾子狭められない広げるのは可
検査例外増やせない・広げられない狭める・減らすのは可
非検査例外自由制限なし
すべて実機で確認最重要
class A { Object m(){ return null; } }
class B extends A { String m(){ return null; } }        // OK（共変戻り値）

class A { String m(){ return null; } }
class B extends A { Object m(){ return null; } }        // NG。広げるのは不可

class A { protected void m(){} }
class B extends A { public void m(){} }                 // OK（広げる）

class A { public void m(){} }
class B extends A { protected void m(){} }              // NG（狭める）

class A { void m(){} }
class B extends A { void m() throws IOException {} }    // NG（検査例外を追加）

class A { void m() throws IOException {} }
class B extends A { void m() throws FileNotFoundException {} }   // OK（狭める）

class A { void m(){} }
class B extends A { void m() throws RuntimeException {} }        // OK（非検査）

覚え方は「呼ぶ側が困らないように」です。A 型の変数で呼んでいる人にとって、
・戻り値が String（サブ型）に狭まるのは困らない ── Object として受け取れる
・アクセスが広がるのは困らない ── 見えていたものが見え続ける
・検査例外が減るのは困らない ── catch していた分が減るだけ
逆向きはすべて呼び出し側を壊すので禁止されます。

オーバーライドできないもの

3つの禁止NG
class A { final void m(){} }
class B extends A { void m(){} }        // error: cannot override（final メソッド）

class A { static void m(){} }
class B extends A { void m(){} }        // error（static を非static で）

class A { void m(){} }
class B extends A { static void m(){} } // error（非static を static で）

static と非 static は相互に入れ替えられません。static メソッド同士なら書けますが、それはオーバーライドではなく隠蔽（hiding）です（節05）。
private メソッドはそもそも子から見えないので、同名で書いてもまったく別のメソッドになります。

@Override はアノテーションであり必須ではありませんが、付けておくと綴り間違いをコンパイラが検出してくれます。付けたのにオーバーライドになっていなければ method does not override or implement a method from a supertype。

戻り値型は「同じ」ではなく「同じかサブ型」

ここを「同じでなければいけない」と覚えると、選択肢を1つ間違えます。

親 → 子結果理由
String → String○同じ
Object → String○サブ型に狭めている（共変戻り値）
String → Object×広げている
void → String×継承関係がまったく無い
int → long×基本データ型に共変は効かない
long → int×同上

選択肢の「戻り値型は同じでなければいけない」は誤りです。サブ型に狭めるのは許されます。
共変が効くのは参照型だけ。int と long は継承関係ではなく変換の関係なので、共変になりません。

第4章 節10の record の問題（default void value() と アクセサ String value() の衝突）は、「違ううえに、サブ型ですらなかった」ケースです。
Object → String なら通り、void → String は通らない。この一段があるので「同じでなければならない」という覚え方では説明できません。

4つの条件の非対称

項目規則
引数リスト完全一致（型・数・順番）── ここだけ緩められない
戻り値型同じ、またはサブ型
アクセス修飾子狭められない（広げるのは可）
検査例外増やせない・広げられない（減らすのは可）

引数だけが「完全一致」で、残り3つは片方向に緩められます。この非対称そのものを問う選択肢問題が出ます。
引数が1つでも違えばオーバーライドではなくオーバーロードになる（節04）ので、そこだけは厳密でなければならない、という理屈です。

誤りの選択肢としてよく出るもの

選択肢判定
戻り値型は同じでなければいけない× サブ型可
抽象メソッドはオーバーライドできない× むしろされるために存在する
オーバーロードされたメソッドはオーバーライドできない× それぞれ独立に上書きできる
引数リストは型・数・順番すべてが同じ○ 正しい

ジェネリクスを含むオーバーライド

< > の中身まで見て判定する要注意
class A {
    List<Number> get(Set<CharSequence> s) { return null; }
}
class B extends A {   // 下の4つは、どれか1つだけを書いた場合の判定
    ArrayList<Number> get(Set<CharSequence> s) { return null; }  // OK。共変戻り値
    List<Integer>     get(Set<CharSequence> s) { return null; }  // エラー: List<Integer> は List<Number> の子ではない
    List<Number>      get(Set<String> s)       { return null; }  // エラー: name clash
    List<Number>      get(TreeSet<String> s)   { return null; }  // OK。引数の型が違うのでオーバーロード
}

戻り値の共変は < > の外側だけで効きます。ArrayList は List の子なので ArrayList<Number> は OK ですが、中身の Integer と Number に親子関係があっても List<Integer> は List<Number> の子になりません（第2章 14）。
引数の Set<String> と Set<CharSequence> は、コンパイル後に < > が消える（型消去）とどちらも Set になります。引数リストが「違う」のでオーバーライドにならず、消した後は「同じ」なのでオーバーロードとしても共存できず、name clash というコンパイルエラーになります。同じクラスの中に m(List<String>) と m(List<Integer>) を並べても同じエラーです。

「サブクラスに定義できるメソッドはどれか」の解き方

親のメソッドを1つ見せて、子に書ける宣言を選ばせる形式です。< > が付くと急に難しく見えますが、引数 → 戻り値 → 修飾子の順に見れば機械的に切れます。

見るところ判定
1引数リストを、< > の中身まで含めて親と見比べる・完全に同じ → オーバーライド。2 へ進む
・< > の外側が違う（Set → TreeSet）→ 別のメソッド＝オーバーロード。戻り値もアクセスも自由 → ○
・< > の中身だけが違う（Set<CharSequence> → Set<String>）→ 型消去すると同じ → name clash で ×
2戻り値< > の外側は子に狭めてよい（List → ArrayList）。< > の中身は完全一致でなければ ×
3アクセス修飾子・検査例外狭める／増やすと ×（上の表と同じ）

親が public List<Number> get(Set<CharSequence> s) のとき、子に書ける／書けないは次のように分かれます。どれか1つだけを子に書いた場合の判定です。

子に書く宣言判定理由
ArrayList<Integer> get(Set<String> s)×1 で脱落。name clash
List<Integer> get(TreeSet<String> s)○引数の外側が違う → 別のメソッド。戻り値は問われない
List<Integer> get(Set<String> s)×1 で脱落。name clash
List<Object> get(Set<CharSequence> s)×2 で脱落。戻り値の中身が違う
List<Integer> get(Set<CharSequence> s)×同上。Integer が Number の子でも関係ない
ArrayList<Number> get(Set<CharSequence> s)○中身は同じで、外側だけ子に狭めた＝共変戻り値

2つ選ばせる問題では、オーバーロードに逃げたもの（引数の外側を変える）と、共変戻り値で通るもの（戻り値の外側だけ子にする）が1つずつという作りがよく出ます。
エラーメッセージも見分けの助けになります。引数で外したときは name clash ... have the same erasure, yet neither overrides the other、戻り値で外したときは attempting to use incompatible return type です。
唱えるのは1つだけ ── < > の中身は引数でも戻り値でも完全一致。緩められるのは外側だけ（第5章 14の④）。

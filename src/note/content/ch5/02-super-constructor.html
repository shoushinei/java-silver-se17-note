コンストラクタと super()

コンストラクタは継承されません。そのかわり、子のコンストラクタは必ず親のコンストラクタを呼びます。

書かなければ super() が自動挿入される最重要
class Sub extends Sup {
    Sub() {
        // super();  ← 書かなくてもコンパイラがここに入れる
        System.out.println("Sub()");
    }
}
実行順序は「親が先」頻出
class Base { Base(){ System.out.println("① Base()"); } }
class Mid extends Base {
    { System.out.println("② Mid 初期化ブロック"); }
    Mid(){ System.out.println("③ Mid()"); }
}
class Sub extends Mid { Sub(){ System.out.println("④ Sub()"); } }

new Sub();     // ① ② ③ ④

順序は最上位の親までさかのぼってから、下りてくる形になります。各階層で「初期化ブロック → コンストラクタ本体」の順（第4章 節08）。
子は親の状態を土台にするので、親が完成していなければ子を組み立てられないという理屈です。

親に引数なしコンストラクタが無い最頻出
class A { A(int x){} }              // 引数ありを定義 → デフォルトは生成されない
class B extends A { B(){} }         // 暗黙の super() が呼べない

// error: constructor A in class A cannot be applied to given types;
//   required: int

エラーは子クラスの側に出ます。親のコードは何も間違っていません。
解決は B(){ super(0); } と明示的に引数を渡すか、親に A(){} を足すか。第4章 節04の「1つでも定義するとデフォルトは生成されない」がここに波及します。

規則内容
super() の位置第1文のみ
this() との併用不可。どちらも第1文を要求する
this() を書いた場合super() は挿入されない（合流先が呼ぶ）

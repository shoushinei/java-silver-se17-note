final

付ける先意味
クラス継承できない（cannot inherit from final）
メソッドオーバーライドできない
変数再代入できない
final 変数は「参照が固定される」だけ要注意
final int[] arr = {1, 2};
arr[0] = 100;              // OK。中身は変えられる
arr = new int[]{3};        // error: cannot assign a value to final variable arr

final StringBuilder sb = new StringBuilder("a");
sb.append("b");            // OK
sb = new StringBuilder();  // error

参照型の final が固定するのは矢印であって、指す先の中身ではありません。「final なら中身も変えられない」は誤りで、選択肢に出ます。
本当に中身も不変にしたければ record や不変クラスを使います。

final クラスの例は String、Integer などのラッパークラス、そして record（暗黙）。
abstract とは正反対の意味なので同時には付けられません。「継承を強制する」と「継承を禁止する」は両立しません。

abstract / final / インタフェースの組み合わせ ── 一覧

書き方結果理由
abstract final class A×継承の強制と禁止で矛盾（illegal combination of modifiers）
final interface I×インタフェースは実装されるためにある
abstract interface I○インタフェースは暗黙に abstract。書いても冗長なだけ
abstract クラスの final void m(){ }○本体があるので問題ない。子はオーバーライドできないだけ
abstract クラスの static void m(){ }○インスタンス不要なので、クラス名で呼べる
普通のクラスの abstract void m();×abstract メソッドを持つクラスは abstract でなければならない
final クラスの abstract void m();×同上。しかも final なので誰も実装できない
final abstract void m();×オーバーライドの強制と禁止で矛盾
private abstract void m();×子から見えないので実装できない
static abstract void m();×static はオーバーライドされない
protected abstract void m();○子から見えるので実装できる
abstract void m(){ }×abstract メソッドに本体は書けない
インタフェースの final void m();×インタフェースのメソッドに final は付けられない（節10）
コンストラクタに final / abstract / static×コンストラクタは継承もオーバーライドもされない（modifier ... not allowed here）

覚え方は2つだけです。abstract は「子に書かせる」、final は「子に触らせない」。子に書かせるには、子から見えて（private ×）、子がオーバーライドできる（static ×・final ×）必要があります。
そしてabstract メソッドが1つでもあれば、クラスも abstract。この2点から表の ○× はすべて導けます。

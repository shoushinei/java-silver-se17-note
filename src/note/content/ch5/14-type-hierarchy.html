型の関係 総まとめ

代入できるか・キャストが要るか・instanceof が書けるか・オーバーライドになるか・catch の順番・拡張 for 文で回せるか。試験の判定はほとんどが「2つの型がどういう関係にあるか」で決まります。その関係は、次の5系統しかありません。

どの型どうしか関係の決まり方詳しく
①基本データ型どうし親子関係は無い。あるのは変換の向きだけ（int→long は自動、逆はキャスト）第2章 03
②基本データ型 ⇄ ラッパーボクシング／アンボクシング。1段階だけ（int→Long は不可）第2章 03
③参照型どうし親子関係。extends と implements を上にたどって出会えるかこの節
④型引数（< > の中身）中身の親子関係は持ち上がらない（List<Integer> は List<Number> の子ではない）第2章 14
⑤配列どうし要素の親子関係がそのまま持ち上がる（String[] は Object[] の子）第2章 11

④ と ⑤ は逆向きです。同じ「入れ物」なのに、配列は要素の親子をそのまま引き継ぎ、ジェネリクスは引き継ぎません。この1点だけで選択肢が2つ切れる問題が出ます。

全体像 ── 型の世界は2つに分かれる

「int は Object の子ですか」と聞かれたらいいえです。Object o = 1; が書けるのは、先に int が Integer に変わってから、親の Object に代入されているからです。
基本データ型は 8 つで固定、参照型は無数にありますが、どれも必ず Object につながります。

① 基本データ型どうし ── 親子ではなく「変換の向き」

基本データ型に instanceof・キャストの失敗（ClassCastException）・オーバーライドの共変はありません。あるのは「自動で広がるか、キャストが要るか」だけです。
この一本道の上で、さらに3つの規則が効きます ── byte・short・char の演算は int に昇格する、複合代入（+=）には暗黙のキャストが入る、final の定数は範囲内なら縮小代入できる（第2章 03）。

② 基本データ型 ⇄ ラッパー ── 変換は1段階だけ

2段階になると通らない最頻出
Integer a = 5;                 // OK  int → Integer（ボクシングだけ）
Long    b = 5;                 // ×   int → long → Long の2段階
Long    c = 5L;                // OK  long → Long
Integer d = 'a';               // ×   char → int → Integer の2段階
Object  e = 'a';               // OK  char → Character（1段階）→ 親へ
long    f = Integer.valueOf(5);   // OK  アンボクシング → 拡大変換（この向きは2段階でも通る）
double  g = 5;                 // OK  int → double（① の話）

「ボクシングしてから広げる」（Integer → Object、Integer → Number）は通り、「広げてからボクシング」（int → long → Long）は通りません。オーバーロードの選択でも同じ順序が効きます（第4章 06）。
アンボクシングは逆で、long f = Integer.valueOf(5) のようにアンボクシングしてから広げるのは許されます。

③ 参照型どうし ── 判定のルールは3つだけ

関係代入例
子 → 親そのまま代入できるNumber n = Integer.valueOf(1);
親 → 子キャストが必要。実体が違えば実行時に ClassCastExceptionInteger i = (Integer) n;
親子関係なし（兄弟など）キャストしてもコンパイルエラーLong l = (Long) i;（i は Integer）

代入できるか ── よく出る組み合わせ

○ はコンパイルできる、× はコンパイルエラー最頻出
Number n = 1;                              // ○ int → Integer（ボクシング）→ Number（親へ）
Object o = 1;                              // ○ 同上。Object はすべての親
Number n = 'a';                            // × Character は Number の子ではない
Number n = true;                           // × Boolean も Number の子ではない
Integer i = 1;  Long l = i;                // × Integer と Long は兄弟
Long l = (Long) i;                         // × 兄弟はキャストしても不可

CharSequence cs = new StringBuilder();     // ○ StringBuilder は CharSequence を実装
String s = new StringBuilder("a");         // × StringBuilder は String の子ではない
String s = cs;                             // × 親 → 子。(String) cs とキャストすれば通る

Object o = new int[1];                     // ○ 配列はすべて Object の子
Object[] oa = new String[1];               // ○ String[] は Object[] の子（配列の共変性）
Object[] oa = new int[1];                  // × int[] は Object[] の子ではない（int は Object でないため）

Iterable<String> it = new ArrayList<String>();          // ○ ArrayList → List → Collection → Iterable
Collection<String> c = new HashMap<String, String>();  // × Map は Collection ではない
List<Object> lo = new ArrayList<String>();             // × < > の中身は親子でも不可（第2章 14）

AutoCloseable ac = new Scanner("x");       // ○ Scanner → Closeable → AutoCloseable
Exception e = new FileNotFoundException(); // ○ 子孫 → 祖先
RuntimeException r = new IOException();    // × IOException は RuntimeException の子ではない
親 → 子のキャストは、実体が違えば実行時に落ちる対比
Number n = 1L;                 // 実体は Long
Integer i = (Integer) n;       // コンパイルは通るが ClassCastException（Long は Integer ではない）

コンパイラが見るのは変数の型どうしの親子関係だけです（節05）。Number と Integer は親子なのでキャストは書けますが、実体が Long だったことは実行してみるまで分かりません。一方 Integer と Long は兄弟なので、実体を見るまでもなくコンパイルの時点でエラーになります。

④ 型引数 ── < > の中身の親子は持ち上がらない

親子が使えるのは < > の外側だけ頻出
List<Object>     a = new ArrayList<String>();    // × 中身が違う
List<Number>     b = new ArrayList<Integer>();   // × Integer は Number の子でも不可
Collection<String> c = new ArrayList<String>();  // ○ 外側だけが変わっている
List<String>     d = new ArrayList<>();          // ○ <> は左辺に合わせてくれる

List<Object> e = new ArrayList<>();
e.add("a");                                      // ○ 要素として子を入れるのは自由
e.add(1);                                        // ○

もし List<Object> a = new ArrayList<String>(); が書けてしまうと、a.add(1) で String 専用のリストに Integer が入ってしまいます。それを防ぐために、< > の中身は左右で完全一致と決められています。
「リストごと代入する」のと「要素として入れる」のは別の話です。List<Object> に "a" や 1 を add するのは何の問題もありません（第2章 14）。
コンパイル後に < > が消える（型消去）ため、m(List<String>) と m(List<Integer>) は同じクラスに並べられません（節03）。

⑤ 配列 ── 要素の親子が、そのまま持ち上がる

持ち上がるのは参照型の要素だけ要注意
Object[] a = new String[1];      // ○ String は Object の子 → String[] も Object[] の子
Number[] b = new Integer[1];     // ○ 同じ理由
Object[] c = new int[2][3];      // ○ int[][] は「int[] の配列」。要素の int[] は参照型
Object   d = new int[1];         // ○ 配列はすべて Object の子

Object[] e = new int[1];         // × 要素の int は参照型ではないので持ち上がらない
long[]   f = new int[1];         // × int → long は① の変換であって親子ではない

int[] は Object の子ではあるが、Object[] の子ではありません。要素の int が Object の子でないからです。一方 int[][] は要素が int[]（参照型）なので Object[] に入ります。
持ち上がった結果、Object[] a = new String[1]; のあとで a[0] = 1; と書くとコンパイルは通り、実行時に ArrayStoreException になります（第2章 11）。ジェネリクスが同じ事故をコンパイル時に止めるのと対照的です。

場面別 ── どの関係が、どこで効くか

場面効く関係と判定
代入（=）子 → 親はそのまま。親 → 子はキャスト。無関係は不可
キャスト親子ならコンパイルは通る（実体が違えば ClassCastException）。無関係なクラスどうしはコンパイルエラー。final でないクラス → インタフェースは通る（節06）
instanceof無関係な型どうしはコンパイルエラー。null は常に false（第4章 09）
拡張 for 文配列か Iterable の子孫だけ。Map と String は回せない（第2章 14）
try-with-resourcesAutoCloseable の子孫だけ（第6章 09）
catch の順番子を上、親を下。逆だとコンパイルエラー（第6章 04）
multi-catch親子関係にある2つは | で並べられない（第6章 05）
オーバーライドの引数完全一致。< > の中身が違えば name clash（節03）
オーバーライドの戻り値同じかその子（共変戻り値）。効くのは < > の外側だけ
オーバーライドの例外検査例外は子に狭めるのは可、親に広げるのは不可（第6章 10）
オーバーロードの選択拡大変換 → ボクシング → 可変長引数 の順に候補を探す（第4章 06）
配列への代入要素の親子は持ち上がる。合わない型を入れると ArrayStoreException（⑤）
ジェネリクスの代入< > の中身は完全一致（④）
record暗黙に Record を継承しているので extends は書けない。implements は書ける（第4章 10）
sealed子になれるのは permits に挙げた型だけ（節11）

迷ったときは、この順に確かめる

確かめること答えの出し方
1基本データ型か、参照型か混ざっていれば ② の話。ボクシング1段階で届くかだけを見る
2（参照型どうしなら）片方から extends / implements を上へたどって相手に出会えるか出会えなければ無関係。代入もキャストもコンパイルエラー
3どちらが上か子 → 親はそのまま代入。親 → 子はキャストが必要で、実体が違えば実行時に落ちる

そのうえで、< > が付いていたら ④（中身は完全一致）、[ ] が付いていたら ⑤（要素の関係が持ち上がる）を重ねて考えます。この順番を守れば、知らないクラス名が出てきても判定できます。
例外の木は第6章 01、コレクションの木は第2章 14に、それぞれ詳しい図があります。

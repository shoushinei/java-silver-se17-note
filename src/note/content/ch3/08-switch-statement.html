switch 文（従来の形）

int より大きい整数型（long）と、小数、boolean は使えません。「int に収まる整数系＋String＋enum」と覚えると確実です。

case ラベルは定数でなければならない

final の有無で結果が変わる最重要
final int A = 1;
int b = 2;

switch (x) {
    case A:  break;      // OK。コンパイル時に確定する定数
    case b:  break;      // コンパイルエラー: 変数は使えない
    case 1 + 2: break;   // OK。定数式
}

第2章の縮小変換や String の定数プールと同じ判定基準です。コンパイル時に値が確定するかが問われています。

重複と範囲外NG
byte x = 1;
switch (x) {
    case 1: break;
    case 1: break;       // コンパイルエラー: 重複
    case 200: break;     // コンパイルエラー: byte の範囲外
}

break がないとフォールスルーする

一致した位置から下へ流れる最重要
int x = 2;
switch (x) {
    case 1: System.out.println("A");
    case 2: System.out.println("B");
    case 3: System.out.println("C");
    default: System.out.println("D");
}
// 出力: B C D ← break がないので下まで流れる

一致した case から下のすべてが実行されます。break があればそこで抜けます。

default は最後でなくてもよい要注意
int x = 5;
switch (x) {
    default: System.out.println("D");
    case 1:  System.out.println("A");
}
// 出力: D A ← default から下へ流れる

default はどこに書いてもよく、そこからもフォールスルーします。「default は最後に書かなければいけない」という選択肢は誤りです。

switch に null を渡すと落ちる ── println との違い

同じ null でも結果が違う最重要
String s = null;
System.out.println(s);       // null  ← 落ちない

switch (s) {                 // NullPointerException
    case "a": break;
    default:  break;         // default があっても受け止めない
}

同じ null を渡しているのに、println は "null" と表示し、switch は例外になります。違いは中身に触る前に、null かどうかを確かめるかどうかです。

null を渡すと中でしていること
println(s)"null" と表示String.valueOf(s) で、null なら "null" という文字列に置き換えてから出力する
switch (s)NullPointerExceptionnull かどうかを確かめずに、いきなり s.hashCode() を呼ぶ

switch が裏で呼んでいるメソッド

switch は case の値と上から1つずつ比べているわけではありません。渡された値をいったん int に変換し、その int で分岐先を探します。その変換のために、渡された値のメソッドを呼びます。null に対してメソッドを呼ぶので落ちる、というのが仕組みです。

switch に渡す型裏で呼ばれるものnull のときの例外メッセージ
Strings.hashCode()
（一致したら s.equals(...) で確認）		Cannot invoke "String.hashCode()" because "…" is null
enumc.ordinal()（定数の番号）Cannot invoke "Color.ordinal()" because "…" is null
Integer などのラッパーi.intValue()（アンボクシング）Cannot invoke "java.lang.Integer.intValue()" because "…" is null
int などの基本データ型—そもそも null を入れられない
コンパイル後の中身（javap -c で確認）参考
// switch (s) { case "A": ... default: ... } をコンパイルすると
invokevirtual  String.hashCode   // ① まず s.hashCode() を呼ぶ ← s が null ならここで落ちる
lookupswitch                     // ② その int で分岐先を探す
invokevirtual  String.equals     // ③ ハッシュ値が同じ別の文字列もあり得るので、equals で確かめる

例外のメッセージには、switch が何を呼ぼうとして落ちたかがそのまま書かれています。第2章 13 の「null にドットを付けたら NullPointerException」の特殊な形で、switch は見えないドットを付けていると覚えてください。アンボクシング（int j = i;）と同じ種類の落ち方です。
なお、「switch に null が来たら NullPointerException」は言語仕様で決まっている動作で、hashCode() などはそれを実現する手段です。case が1つも無い switch (s) { } でも、コンパイラが null チェック（Objects.requireNonNull）を差し込むので、やはり落ちます。

default は null を受け止めません。default は「どの case にも一致しなかったとき」の行き先ですが、一致するかを調べる前の hashCode() の時点で落ちるので、default までたどり着きません。「default があるので default が実行される」という選択肢は誤りです。
switch 式（次の 09）でも同じです。また SE 17 では case null と書くことができず、コンパイルエラーになります。

null を渡さないようにする

switch の前で null を片付けるOK
if (s != null) {
    switch (s) { case "A": ... }
}

switch (s == null ? "" : s) {      // null なら "" に置き換えてから渡す
    case "A": ...
    default:  ...                  // null はここに来る
}

println が null で落ちない仕組みは第5章 13、ドットの無い NullPointerException の一覧は第2章 13にあります。
参考までに、Java 21 以降は case null -> が書けるようになりました。ただし SE 17 の試験では書けない（コンパイルエラー）が正解です。

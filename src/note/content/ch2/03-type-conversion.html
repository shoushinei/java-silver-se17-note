03

型変換

拡大変換（自動）と縮小変換（キャスト必須）

変換の方向図
byte → short → int → long → float → double     ← この向きは自動
char ─────────↗

double → float → long → int → short → byte     ← この向きはキャスト必須
int → char

long → float が拡大変換なのは直感に反しますが、float のほうが表現範囲が広いためです。精度は失われますが、コンパイルは通ります。

罠1 ── byte・short・char の演算は int に昇格する

この章で最頻出です。

byte + byte は intNG
byte a = 1, b = 2;
byte c = a + b;      // コンパイルエラー: a + b の結果は int
キャストすれば通るOK
byte c = (byte)(a + b);

罠2 ── 複合代入演算子は暗黙のキャストを含む

意味は同じでも結果が違う要注意
byte a = 1;
a += 2;       // OK。+= に暗黙の縮小キャストが組み込まれている
a++;          // OK。同じ理由
a = a + 2;    // コンパイルエラー

a += 2 は通るが a = a + 2 はエラー。この非対称が選択肢に並びます。意味は同じなのに結果が違う、という点だけ覚えてください。

罠3 ── コンパイル時定数なら縮小変換が通る

final の有無で結果が変わる要注意
byte a = 10;            // OK。10 は範囲内の定数
byte b = 200;           // コンパイルエラー: 範囲外

final int x = 10;
byte c = x;             // OK。final なのでコンパイル時に確定

int y = 10;
byte d = y;             // コンパイルエラー: final でない

final という1語の有無だけで合否が変わります。第4章の「実質的に final」や第6章の multi-catch の変数と同じ考え方で、コンパイラが値を確定できるかどうかが判定基準です。

ボクシングと拡大変換は組み合わせられない

2段階の変換は不可NG
Long a = 5;      // コンパイルエラー
// int → long（拡大変換）→ Long（ボクシング）の2段階は許されない
1段階なら通るOK
Long a = 5L;              // long → Long のボクシングだけ
Integer b = 5;            // int → Integer のボクシングだけ
long c = Integer.valueOf(5);   // アンボクシング → 拡大変換

Integer キャッシュ

127 と 128 で結果が変わる最重要
Integer a = 127, b = 127;
System.out.println(a == b);   // true

Integer c = 128, d = 128;
System.out.println(c == d);   // false

オートボクシングは内部で Integer.valueOf() を呼びますが、-128 〜 127 の範囲はキャッシュされた同一インスタンスが返るためです。値の比較には必ず equals() を使います。

null のアンボクシング実行時
Integer i = null;
int j = i;      // コンパイルは通り、実行時に NullPointerException

03

型変換

型変換は、ある型の値を別の型の変数に入れる・別の型として計算するときに起きます。どんな組み合わせでも、答えは次の3つのどれかです。

判定意味例
暗黙でよい何も書かなくても、コンパイラが自動で変換するlong l = 10;
キャストが必要(型) を書けば変換できる。書かないとコンパイルエラーint i = (int) 3.9;
変換できないキャストを書いてもコンパイルエラーint i = (int) true;

どれになるかは、変換の種類で決まります。まず種類の地図を見て、そのあと1つずつ説明します。罠はこの節の最後にまとめてあります。

全体の地図 ── 変換は5種類

種類向き書き方例
① 拡大変換基本データ型 → 範囲の広い基本データ型暗黙long l = 10;
② 縮小変換基本データ型 → 範囲の狭い基本データ型キャスト
（書かなくてよい場面が3つ）		int i = (int) 10L;
③ ボクシング基本データ型 → 対応するラッパー暗黙Integer i = 5;
④ アンボクシングラッパー → 対応する基本データ型暗黙int n = i;
⑤ 参照型の変換子 → 親 ／ 親 → 子暗黙 ／ キャストObject o = "a";
String s = (String) o;
変換できないboolean ⇄ 数値、文字列 ⇄ 数値、無関係な参照型不可(int) "12"

① ② 基本データ型どうし ── 変換表

行が変換元、列が変換先です。変数どうしの代入（short s = b; のような形）で確かめた結果です。

byte―○△○○○○×

○ 暗黙でよい（拡大変換）△ キャストが必要（縮小変換）× 変換できない

表を覚える必要はありません。次の一本道が分かれば、表は全部作れます。

表から読み取ること理由
右向きは飛ばしてもよい（byte → double も暗黙）範囲が広い型には、狭い型の値が必ず収まる
short → char・char → short はどちらもキャスト同じ16ビットでも、char は 0〜65535（負の数なし）、short は -32768〜32767 で、範囲が重ならない
byte → char もキャストchar は負の数を表せない
long → float は暗黙float は 32 ビットだが、表せる範囲は long より広い（桁の細かさは落ちる）
boolean は全部 ×true/false は数値ではない。(int) true もエラー
暗黙の拡大変換でも、細かい桁は落ちることがある要注意
int big = 123456789;
float f = big;                 // 暗黙で OK
System.out.println(f);         // 1.23456792E8
System.out.println((int) f);   // 123456792 ← 元の 123456789 に戻らない

「拡大変換は値が変わらない」は、整数どうし（int → long など）と float → double の話です。int → float・long → float・long → double は、暗黙でできても細かい桁が丸められることがあります。

② 縮小変換 ── キャストすると値はどうなるか

キャストは「範囲を超えるかもしれないが、承知の上で変換する」という宣言です。コンパイルは通り、実行時の例外にもならず、値のほうが変わります。

キャスト結果何が起きたか
(byte) 200-56整数 → 狭い整数：入りきらない上の桁（ビット）を捨てる。一周して負の数になることもある
(byte) 30044
(short) 40000-25536
(int) 3.993小数 → 整数：小数点以下を切り捨てる（0 に近い方へ。四捨五入しない）
(int) -3.99-3
(int) 1e102147483647小数 → 整数で範囲外なら、int の最大値に張りつく（一周しない）
(char) 65'A'char と整数は、文字コードで行き来する
(int) 'A'65
キャストが掛かるのは、すぐ右の1つだけ要注意
System.out.println(7 / 2);             // 3     int ÷ int
System.out.println((double) 7 / 2);    // 3.5   7 を double にしてから割る
System.out.println((double) (7 / 2));  // 3.0   先に int どうしで割って 3、それを double に
System.out.println(7 / 2.0);           // 3.5   片方が double なので double で計算（④）

② の続き ── キャストを書かなくても縮小できる3つの場面

場面例条件・注意
1. 定数の代入byte b = 10;
char c = 65;

2. 複合代入b += 300;+= -= *= などは、キャストが最初から組み込まれている。範囲を超えても通り、値が変わる
3. ++ と --b++;複合代入と同じく、キャストが組み込まれている
定数の特例が効く・効かない最頻出

byte b = 200;             // ×   定数でも範囲外

int y = 10;

static void take(byte v) { }

複合代入は通るが、値が変わることがある最頻出
byte b = 10;
b = b + 1;       // ×  b + 1 は int（④）。int を byte に入れるにはキャストが要る
b += 1;          // OK b = (byte)(b + 1) と同じ
b++;             // OK
b += 300;        // OK ただし 10 + 1 + 1 + 300 = 312 → (byte) 312 → 56

int i = 5;
i += 1.5;        // OK i = (int)(i + 1.5) → 6
i = i + 1.5;     // ×  i + 1.5 は double

演算するときの型 ── 数値昇格

2つの数を計算するとき、Java は計算の前に両方を同じ型にそろえます。そろえ先は上から順に決まります。

順どちらかが…計算の型
1doubledouble
2floatfloat
3longlong
4それ以外（byte short char int だけ）int

4 番目が大事です。byte + byte も short + short も char + char も、結果は intです。-b のような単項のマイナスも int になります。
だから byte c = a + b; は「int を byte に入れる」ことになってエラーです。ただし a と b が final の定数なら、a + b も定数になるので、範囲内なら特例 1 で代入できます。

計算の結果の型最頻出
byte a = 1, b = 2;
byte c = a + b;              // ×  a + b は int
byte d = (byte) (a + b);     // OK
final byte p = 1, q = 2;
byte r = p + q;              // OK 定数どうしなので、結果も定数

long  x = 1 * 2L;            // OK long
int   y = 1 * 2L;            // ×  long
float z = 1.5f + 1;          // OK float
int   w = 5 + 1.0;           // ×  double
char の計算は、文字コードの int になる要注意
char c = 'A';
System.out.println(c + 1);          // 66    char + int → int
System.out.println((char) (c + 1)); // B     int を char に戻す
c++;
System.out.println(c);              // B     ++ にはキャストが組み込まれている
System.out.println('a' + 'b');      // 195   char + char → int（97 + 98）
System.out.println("" + 'a' + 'b'); // ab    左に String があると連結になる

③ ④ ボクシングとアンボクシング

基本データ型にはそれぞれ、値をオブジェクトとして包むラッパークラスがあります。コレクション（List<Integer>）や Object 型の変数には基本データ型を直接入れられないので、包む必要があります。

基本データ型byteshortcharintlongfloatdoubleboolean
ラッパークラスByteShortCharacterIntegerLongFloatDoubleBoolean

名前が単純に大文字になるだけではないのは、char → Character と int → Integer の2つです。

4つの用語

用語意味書いたコードコンパイラがすること
ボクシング基本データ型 → ラッパー（包む）Integer.valueOf(5)―
アンボクシングラッパー → 基本データ型（ほどく）i.intValue()―
オートボクシングボクシングをコンパイラが自動で行うことInteger i = 5;Integer i = Integer.valueOf(5); に書き換える
オートアンボクシングアンボクシングをコンパイラが自動で行うことint n = i;int n = i.intValue(); に書き換える

「オート」が付くのは、変換の中身は同じで、自分で書くか自動かの違いだけです。Java 5 からは自動で行われるので、試験で「ボクシング」と言えば、ふつうはこの自動の変換を指します。

自動で起きる場面

場面例起きること
代入Integer i = 5; ／ int n = i;ボクシング ／ アンボクシング
メソッドの引数・戻り値list.add(5);5 を Integer に包んで渡す
計算i + 1i をほどいて int で計算
比較i == 5片方が基本データ型なら、ほどいて値で比べる
Object に入れるObject[] a = {1, 'a', 2.0, true};中身はそれぞれ Integer・Character・Double・Boolean になる

できる・できない ── 1段階ずつしか進めない

ボクシングで行き来できるのは対応するペアだけ（int ⇄ Integer、long ⇄ Long …）です。ペアでない型へは、次のように組み合わせて届くかどうかで決まります。

コード判定理由
Integer a = 5;○int → Integer（ペア）
Long a = 5;×int → long → Long の2段階。広げてから包むのは不可
Long a = 5L;○long → Long（ペア）
Long a = (long) 5;○キャストで先に long にしてあるので、包むだけ
Double a = 5;×int → double → Double の2段階
Integer a = 5L;×long は Integer のペアではない
Object a = 5; ／ Number a = 5;○int → Integer に包んでから、親の型へ（⑤）。包んでから親へは可
long a = Integer.valueOf(5);○Integer → int にほどいてから、long へ広げる。ほどいてから広げるのは可
int a = (int) Long.valueOf(5);×Long → long → int は、ほどいてから狭める。キャストを書いても不可
Byte a = 10;○定数の特例（範囲内の定数 → byte）のあとに包む。Short・Character も同じ
int x = 10; Byte a = x;×x は定数ではないので特例が効かない

まとめると、包む・ほどく以外に進めるのは「包んだあと親へ」と「ほどいたあと広げる」だけです。「広げてから包む」（Long a = 5;）と「ほどいてから狭める」はできません。
オーバーロードでどのメソッドが選ばれるかにも、この規則がそのまま効きます（第4章 06）。

ラッパーの比較と null

ラッパーどうしの == は参照の比較最重要
Integer a = 127, b = 127;
System.out.println(a == b);        // true
Integer c = 128, d = 128;
System.out.println(c == d);        // false
System.out.println(c.equals(d));   // true  値の比較には equals
System.out.println(c == 128);      // true  片方が int なので、ほどいて値で比べる

オートボクシングは内部で Integer.valueOf() を呼びます。-128 〜 127 の値は、あらかじめ用意された同じインスタンスが返るので、== でも true になります。範囲外は毎回新しいインスタンスなので false です。

型が違うと equals は false、null をほどくと例外実行時
Long l = 1L;
System.out.println(l.equals(1));   // false  1 は Integer に包まれる。Long と Integer は別の型
System.out.println(l == 1);        // true   ほどいて値で比べる

Integer n = null;
int x = n;                         // コンパイルは通り、実行時に NullPointerException
                                   // n.intValue() を呼ぶのと同じだから

⑤ 参照型どうし

クラスやインタフェースの型どうしは、親子関係で決まります。基本データ型の「広い・狭い」の代わりに「親・子」を使う、と考えると同じ形です。

向き判定例
子 → 親（アップキャスト）暗黙Object o = "a";
親 → 子（ダウンキャスト）キャストString s = (String) o; ── 実体が違えば実行時に ClassCastException
親子関係が無い×Integer i = (Integer) "a";
基本データ型のキャストとの違い対比
Object o = 1;              // 中身は Integer
Long l = (Long) o;         // コンパイルは通るが ClassCastException（Integer は Long ではない）
long m = (long) 1;         // 基本データ型なら、値を変換するので問題ない

参照型のキャストは値を作り変えません。「この変数の中身は本当はこの型のはずだ」と伝えるだけなので、違っていれば実行時に失敗します。詳しくは第5章 06、型の親子関係は第5章 14にあります。

変換できないもの

組み合わせ例（すべてコンパイルエラー）代わりの方法
boolean ⇄ 数値(int) true ／ (boolean) 1flag ? 1 : 0 ／ n != 0
文字列 → 数値(int) "12"Integer.parseInt("12")
数値 → 文字列(String) 12String.valueOf(12) ／ "" + 12
ペアでないラッパーLong l = Integer.valueOf(5);Long.valueOf(i)（i を long に広げてから包む）
親子関係の無い参照型(Integer) "a"―

判定の手順

確かめること答え
1boolean と数値、文字列と数値の組み合わせかそうなら変換できない
2両方とも基本データ型か一本道の右向きなら暗黙、左向きならキャスト。ただし定数・複合代入・++ -- ならキャスト不要
3基本データ型とラッパーかペアなら暗黙。ペアでなければ「包んでから親へ」「ほどいてから広げる」で届くときだけ可
4両方とも参照型か子 → 親は暗黙、親 → 子はキャスト（実行時に失敗しうる）、無関係は不可
5計算の途中か先に数値昇格（double → float → long → int）で計算の型を決めてから、1〜4 を当てはめる

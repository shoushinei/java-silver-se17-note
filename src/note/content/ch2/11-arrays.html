配列

宣言の書き方

括弧の位置は2通りOK
int[] a;      // 推奨
int b[];      // C言語風。合法だが非推奨
int[] c, d;   // c と d の両方が配列
int e[], f;   // e だけが配列。f は int ← 引っかけ

int e[], f; の f は配列ではありません。角括弧を型側に書くか変数側に書くかで、2つ目以降の意味が変わります。

生成と初期化

3つの書き方OK
int[] a = new int[3];              // {0, 0, 0} ← 既定値で埋まる
int[] b = {1, 2, 3};               // 宣言と同時のみ
int[] c = new int[]{1, 2, 3};      // どこでも使える

上の2つは動作がまったく同じで、どちらも新しい配列インスタンスを1つ作ります。違うのは書ける場所だけです。

初期化子だけの形は宣言時のみNG
int[] a;
a = {1, 2, 3};                     // エラー: 型を推論できない
a = new int[]{1, 2, 3};            // OK

void m(int[] arr) { }
m({1, 2, 3});                      // エラー
m(new int[]{1, 2, 3});             // OK

var b = {1, 2};                    // エラー: var とは併用できない
var c = new int[]{1, 2};           // OK
サイズと初期化子の関係NG
int[] a = new int[];               // エラー: サイズも初期化子もない
int[] b = new int[3]{1, 2, 3};     // エラー: 両方は指定できない
負のサイズ実行時
int[] a = new int[-1];    // コンパイルは通り、実行時に NegativeArraySizeException

既定値 ── 基本データ型と参照型で扱いが違う

基本データ型はそのまま使えるOK
int[] nums = new int[3];
System.out.println(nums[0]);       // 0
System.out.println(nums[0] + 1);   // 1 ← 計算できる
参照型は null なので使えない最重要
class Item { int price = 100; }

Item[] items = new Item[3];        // 箱を3つ用意しただけ
System.out.println(items[0]);          // null ← インスタンスは1つも無い
System.out.println(items[0].price);    // NullPointerException

new Item[3] は「Item を3個作った」のではなく「Item を入れる箱を3個用意した」だけです。参照型の配列は2段階になります。

中身も作るOK
Item[] items = new Item[3];
for (int i = 0; i < items.length; i++) {
    items[i] = new Item();         // ← これが必要
}
System.out.println(items[0].price);    // 100

フィールド初期化子（int price = 100;）はインスタンス生成時に初めて実行されるので、new Item() を書かない限り 100 という値はどこにも存在しません。第4章の内容がそのまま効いています。

基本データ型の配列に null は入れられないNG
int[] a = {1, null, 3};           // コンパイルエラー
Integer[] b = {1, null, 3};       // OK ← ラッパーなら入る

2次元配列

後ろの次元は省略できる要注意
int[][] a = new int[2][3];    // OK。2×3
int[][] b = new int[2][];     // OK。後ろは省略可（各行は null）
int[][] c = new int[][3];     // コンパイルエラー: 前を省略はできない

b[0] = new int[5];            // 行ごとに長さを変えられる（ジャグ配列）
b[1] = new int[2];
初期化子の入れ子の深さ ＝ 次元の数頻出
int[][] a = {{1, 2}, {3}};           // OK。行ごとに長さが違ってよい
int[][] b = {{1}, null, {}};         // OK。null の行、要素0個の行もよい
int[] c[] = {{1}, {2}};              // OK。int[][] と同じ意味
int[][] d = new int[][]{{1}, {2, 3}};// OK

int[][] e = {1, 2};                  // コンパイルエラー: int cannot be converted to int[]
int[][] f = {{1, 2}, 3};             // コンパイルエラー: 3 の場所には int[] が必要
int[] g = {{1}, {2}};                // コンパイルエラー: 1次元に { } は入れられない
int[][][] h = {{1, 2}, {3, 4}};      // コンパイルエラー: 3次元なのに2段しかない
int[][] i = new int[][]{1, 2};       // コンパイルエラー: new でも同じ
int[][] j = new int[2][]{{1}, {2}};  // コンパイルエラー: サイズと初期化子は併用できない
int[][] k = new int[2];              // コンパイルエラー: 右辺は1次元

判定のコツは、一番外側の { } の中身が「1つ下の次元の型」になっているかを見ることです。int[][] の外側の { } には int[]（{ } か null）を並べます。int の値がそのまま置かれていたらエラーです。

階層を数える

角括弧の数だけ階層がある最重要
String[][] array = { {"A","B"}, null, {"C","D","E"} };

array.length              // 3  ← 行の数
array[0].length           // 2  ← 1行目の要素数
array[2].length           // 3
array[0][0].length()      // 1  ← 1行目1列目の文字数
array[1].length           // NullPointerException（行そのものが null）

要素数の数え方は外側の { } の直下にあるカンマだけを数えます。内側の { } の中のカンマは無関係です。縦に書き直すと確実です。

縦に並べると行数が見えるコツ
String[][] array = {
    {"A", "B"},          // array[0]  長さ2
    null,                // array[1]  null
    {"C", "D", "E"}      // array[2]  長さ3
};

拡張for文と階層

ループ変数の型が階層を決める最重要
String[][] array = { {"A","B"}, null, {"C","D","E"} };

for (String[] tmp : array) {      // tmp は array[i] と同じもの
    total += tmp.length;          // ← array の長さではなく array[i] の長さ
}
// 1周目 tmp = {"A","B"} → 2
// 2周目 tmp = null      → NullPointerException

ドットの左に書いてある変数の型を見る。これが判定のすべてです。array と書けば String[][] の長さ、tmp と書けば String[] の長さになります。

型は選べない。要素の型で決まっているNG
String[][] array = ...;

for (String[] tmp : array)      // OK。要素は String[]
for (String tmp : array)        // エラー: String[] を String に入れられない
for (String[][] tmp : array)    // エラー: String[] を String[][] に入れられない
for (Object tmp : array)        // OK。String[] は Object の一種
for (var tmp : array)           // OK。String[] と推論される

全要素を1つずつ見るには、ループを2重にする必要があります。String[][] → String[] → String と、1階層ずつしか下りられません。

ループ変数はコピー要注意
String[] arr = {"a", "b"};
for (String s : arr) {
    s = "X";                  // 元の配列は変わらない
}
System.out.println(arr[0]);   // "a"

第4章の値渡しと同じです。要素を書き換えたいなら通常の for 文で arr[i] = "X" と書く必要があります。

配列の表示 ── println では中身が出ない

ハッシュ形式になる最重要
int[] a = {1, 2, 3};

System.out.println(a);              // [I@1b6d3586
System.out.println(a.toString());   // [I@1b6d3586 ← 同じ。書いても変わらない
System.out.println(new int[0]);     // [I@... ← 要素数0でも同じ形式

配列は toString() をオーバーライドしていないので、Object の既定実装（クラス名＋@＋ハッシュコード）がそのまま使われます。println は中身を見に行きません。

なぜ「クラス名@ハッシュ値」になるのか、自作クラスではどうなるのか、null を println するとどうなるのかは第5章 13「Object から受け継ぐ toString / equals / hashCode」にまとめています。

記号意味
[配列。次元の数だけ付く（[[I なら2次元）
I / D / C / Zint / double / char / boolean
L...;参照型（[Ljava.lang.String;）
@ 以降ハッシュコード（16進数）
中身を出すには Arrays.toStringOK
import java.util.Arrays;

Arrays.toString(new int[]{1,2,3});        // "[1, 2, 3]"
Arrays.toString(new String[2]);           // "[null, null]"
Arrays.toString((int[]) null);            // "null"  ← 例外にならない（null を直接書くと曖昧でコンパイルエラー）
Arrays.deepToString(new int[][]{{1,2}});  // "[[1, 2]]" ← 2次元用

char[] だけはprintln に専用のオーバーロードがあるので中身が出ます。ただし連結すると toString() に戻ります。

char[] は例外要注意
char[] c = {'a', 'b', 'c'};
System.out.println(c);          // abc  ← 中身が出る
System.out.println("" + c);     // [C@1b6d3586 ← 連結すると変わる

コピー ── 代入と clone は別物

代入は参照のコピー最重要
int[] a = {1, 2, 3};
int[] b = a;              // 同じ配列を指すだけ
int[] c = a.clone();      // 新しい配列が作られる

b[0] = 99;
System.out.println(a[0]); // 99 ← b の変更が伝わる
System.out.println(c[0]); // 1  ← c は無関係

System.out.println(a == b);   // true
System.out.println(a == c);   // false

配列の clone() は public で、戻り値は元と同じ配列型です（int[] の clone は int[]）。キャストも例外処理も要りません。クラスの clone との違いは第5章 13にあります。

clone で「一部が共有される」── 浅いコピー

clone() が作るのは新しい箱（配列）だけです。箱の中身は、そのまま書き写されます。書き写されるものが「値」なのか「矢印（参照）」なのかで、共有されるかどうかが決まります。

要素の型箱に入っているものclone した後
基本データ型（int[] など）値そのもの完全に別物。片方を変えても、もう片方は変わらない
参照型（StringBuilder[] Item[] など）オブジェクトへの矢印箱は別だが、指す先のオブジェクトは共有
2次元配列（int[][] など）行（int[]）への矢印外側の箱は別だが、中の行は共有
参照型の配列 ── 中身の変更は伝わり、差し替えは伝わらない最頻出
StringBuilder[] a = { new StringBuilder("x"), new StringBuilder("y") };
StringBuilder[] b = a.clone();

b[0].append("!");                  // 指す先のオブジェクトを書き換える
b[1] = new StringBuilder("z");     // b の箱の矢印を差し替える

System.out.println(a[0] + " " + a[1]);   // x! y  ← [0] は共有なので変わる。[1] は変わらない
System.out.println(b[0] + " " + b[1]);   // x! z
System.out.println(a == b);              // false  配列（箱）は別
System.out.println(a[0] == b[0]);        // true   中のオブジェクトは同じ
System.out.println(a[1] == b[1]);        // false  差し替えたので別

判定は1つだけです。b[i].メソッド() や b[i].フィールド = … で指す先を書き換えたら、元の配列にも伝わる。b[i] = … で要素そのものに代入したら、b の箱が変わるだけで元の配列には伝わりません。
第4章 03の「参照を渡したメソッドの中で、中身の書き換えは伝わるが、差し替えは伝わらない」とまったく同じ仕組みです。

String の配列は、共有されていても困らない対比
String[] s = {"p", "q"};
String[] t = s.clone();
t[0] = t[0] + "!";                   // 新しい String を作って t[0] に代入 ＝ 差し替え
System.out.println(s[0] + " " + t[0]);   // p p!

clone 直後は s[0] と t[0] が同じ String を指しています。ただ String は不変で、指す先を書き換えるメソッドがありません。変更は必ず「新しい String を作って代入」＝差し替えになるので、結果として元の配列には影響しません。StringBuilder との違いに注意してください。

別々なのは外側の箱だけで（a == b は false）、行は共有です（a[0] == b[0] は true）。

2次元配列 ── 中の行が共有される要注意
int[][] a = { {1, 2}, {3, 4} };
int[][] b = a.clone();

b[0][0] = 9;                     // 共有している行の中身を書き換える
b[1] = new int[]{7, 8};          // b の箱の枠を差し替える

System.out.println(a[0][0]);     // 9  ← 元も変わる
System.out.println(a[1][0]);     // 3  ← 差し替えは伝わらない
System.out.println(a[0] == b[0]);// true  行は同じもの
System.out.println(a[1] == b[1]);// false 付け替えたので別

b 専用なのは外側の箱の枠だけです。だから a に伝わらないのは 添字1つの代入（b[1] = …）だけ。b[0][0] = … のように添字が2つ以上なら、共有している行を触るので a にも伝わります。

付け替えた枠はその後も別。付け替えていない枠は共有のまま要注意
int[][] a = { {1, 2}, {3, 4} };
int[][] b = a.clone();
b[1] = new int[]{7, 8};    // b[1] だけ新しい行に付け替え
b[1][0] = 100;             // 付け替えた先を触る → a には伝わらない
b[0][1] = 555;             // 付け替えていない行 → 共有のまま

System.out.println(a[1][0]);   // 3
System.out.println(a[0][1]);   // 555

一度付け替えた枠の先は、もう a と別の行です。付け替えはその枠1つだけの話で、他の枠の共有は切れません。

3次元でも、別々なのは一番外側の箱だけ引っかけ
int[][][] p = { { {1, 2}, {3, 4} }, { {5, 6} } };
int[][][] q = p.clone();

q[0][0][0] = 99;           // 添字3つ → 共有部分
q[0][1] = new int[]{0};    // 差し替えだが添字2つ。q[0] は共有の箱なので p にも伝わる
q[1] = new int[][]{ {7} }; // 添字1つ → q 専用の枠

System.out.println(p[0][0][0]);   // 99
System.out.println(p[0][1][0]);   // 0  ← 差し替えなのに伝わる
System.out.println(p[1][0][0]);   // 5

「添字を最後まで付けたら共有、途中で止めたら分離」と覚えると、3次元で間違えます。q[0][1] は、共有している2段目の箱 q[0] の枠です。何次元でも、分離するのは添字1つの代入だけです。

「付け替えは伝わらない、先を触ると伝わる」は、clone 以外でも同じ判定です。

場面変数・枠そのものに代入. や [ ] で先を触る
clone した配列b[1] = … → 元に伝わらないb[1][0] = … → 伝わる
メソッドの引数（第4章 03）arr = … → 呼び出し元に伝わらないarr[0] = … → 伝わる
final int[] arr（第5章 08）arr = … → コンパイルエラーarr[0] = … → できる
行まで別にしたいとき（深いコピー）参考
int[][] a = { {1, 2}, {3, 4} };
int[][] d = new int[a.length][];
for (int i = 0; i < a.length; i++) {
    d[i] = a[i].clone();         // 行も1つずつ clone する
}
d[0][1] = 8;
System.out.println(a[0][1] + " " + d[0][1]);   // 2 8 ← 元は変わらない

他のコピー方法もあります。Arrays.copyOf(a, 5) は長さを変えられ、足りない分は既定値で埋まります。ただしcopyOf も浅いコピーで、共有のされ方は clone と同じです。

Arrays.copyOf も中身は共有要注意
StringBuilder[] a = { new StringBuilder("x") };
StringBuilder[] c = Arrays.copyOf(a, 2);   // 長さ2。足りない [1] は既定値の null
c[0].append("?");
System.out.println(a[0] + " " + c[1]);     // x? null

第4章とつながります。配列は参照型なので、メソッドに渡すと参照がコピーされます。arr[0] = 99 は呼び出し元に伝わりますが、arr = new int[]{...} は伝わりません。

配列の共変性と ArrayStoreException

配列は、String[] を Object[] 型の変数に代入できます。String が Object の子なので、String の配列も Object の配列の子として扱われるためです（共変）。

コンパイルは通るが、実行時に落ちる要注意
Object[] arr = new String[3];   // OK。String[] は Object[] の子として扱われる
arr[0] = "a";                   // OK
arr[1] = 1;                     // ArrayStoreException: java.lang.Integer
                                // 変数の型は Object[] だが、実体は String[]

コンパイラは変数の型（Object[]）しか見ないので、arr[1] = 1 を通します。しかし実体は String[] で、そこに Integer は入れられません。これを実行時に配列自身が検査して ArrayStoreException を投げます。「コンパイルエラー」を選ばせる引っかけに注意してください。

数値の型どうしでも同じ実行時
Number[] n = new Integer[2];
n[0] = 1.5;                     // ArrayStoreException: java.lang.Double
ジェネリクスは最初からコンパイルで弾く対比
List<Object> list = new ArrayList<String>();   // コンパイルエラー
// ArrayList<String> は List<Object> に変換できない

配列は実行時に「自分は String の配列だ」と覚えているので、入れた瞬間に検査できます。一方ジェネリクスは実行時に型の情報を持たないため、危険な代入を最初からコンパイルエラーにして防ぎます。
ArrayStoreException は RuntimeException の子（非検査例外）なので、catch も throws も義務ではありません。第6章 02 の一覧にも載せています。

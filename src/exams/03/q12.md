次のプログラムをコンパイル、実行したときの結果として、正しいものを選びなさい。

```java title=Main.java
public class Main {
    public static void main(String[] args) {
        StringBuilder sb = new StringBuilder("ja");
        sb.append("va");
        String a = sb.toString();
        String b = sb.toString();
        String c = "java";
        System.out.println((a == b) + " " + a.equals(b) + " "
                + sb.equals(c) + " " + (a.intern() == c));
    }
}
```

- A. 「true true true true」と表示される
- B. 「false true true true」と表示される
- C. 「false true false true」と表示される
- D. 「true true false true」と表示される
- E. 「false true false false」と表示される
- F. StringBuilder と String を equals で比べているため、コンパイルエラーが発生する

## 解説
1. `a == b` → **false**。StringBuilder の `toString()` は、呼ぶたびに**新しい String のインスタンス**を作って返します。中身は同じ "java" でも、a と b は別のインスタンスです。
2. `a.equals(b)` → **true**。String の equals は中身を比べます。
3. `sb.equals(c)` → **false**。StringBuilder は equals をオーバーライドしていないので、Object の equals（== と同じく同じインスタンスかどうか）が使われます。そもそも StringBuilder と String は別のクラスなので、中身が同じでも true にはなりません。
4. `a.intern() == c` → **true**。intern() は定数プールにある同じ内容の文字列を返します。リテラルの "java" はプールの文字列なので、c と同じインスタンスです。

よって「false true false true」です。

- F: equals の引数は Object 型なので、どんなオブジェクトでも渡せます。コンパイルエラーにはなりません（結果が false になるだけです）。
- StringBuilder の中身と比べたいときは、`sb.toString().equals(c)` のように、いったん String にしてから比べます。

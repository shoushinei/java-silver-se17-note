次の2つのクラスがあります。

```java title=Repo.java
import java.util.Collection;

public class Repo {
    public Collection<String> find() {
        return null;
    }
}
```

```java title=UserRepo.java
import java.util.*;

public class UserRepo extends Repo {
    @Override
    public ［型］ find() {
        return null;
    }
}
```

UserRepo の `［型］` の部分に記述したとき、コンパイルが成功するものを選びなさい。

- A. `Collection<Object>`
- B. `Iterable<String>`
- C. `List<String>`
- D. `List<CharSequence>`
- E. `Object`
- F. `ArrayList<String>`

## 解説
オーバーライドするメソッドの戻り値の型は、親のメソッドと**同じ型か、そのサブクラス（サブタイプ）**でなければなりません（共変戻り値）。親の戻り値は `Collection<String>` です。

ジェネリクスの型どうしが親子になるのは、**型引数（< > の中）が同じで、外側の型が親子のとき**だけです。

| 選択肢 | `Collection<String>` との関係 | 結果 |
|---|---|---|
| A. `Collection<Object>` | 型引数が違うので親子ではない | エラー |
| B. `Iterable<String>` | Collection の**親**（広くなる） | エラー |
| C. `List<String>` | List は Collection の子、型引数も同じ | OK |
| D. `List<CharSequence>` | 型引数が違うので親子ではない | エラー |
| E. `Object` | すべての型の親（広くなる） | エラー |
| F. `ArrayList<String>` | ArrayList → List → Collection の子孫、型引数も同じ | OK |

A と D は「String は Object（CharSequence）の子なのだから大丈夫」と考えがちですが、`List<String>` と `List<Object>` は親子ではありません。もし親子だとすると、`List<Object>` 型の変数を通して String のリストに Integer を入れられてしまうからです。

次のプログラムは、Worker クラスでコンパイルエラーになります。

```java title=Main.java
interface Runner {
    void run();
}
class Base {
    void run() {
        System.out.println("base");
    }
}
class Worker extends Base implements Runner {
}
public class Main {
    public static void main(String[] args) {
        Runner r = new Worker();
        r.run();
    }
}
```

その理由として、正しいものを選びなさい。

- A. Worker が run メソッドを定義していないため。インタフェースの抽象メソッドは、親クラスから受け継いだメソッドでは実装できない
- B. Base と Runner に同じ名前のメソッドがあり、どちらを受け継ぐか決められないため
- C. Base が Runner を implements していないため
- D. Base から受け継いだ run には修飾子が無く、public である Runner の run を実装するにはアクセスが狭いため
- E. Runner の run に public が付いていないため

## 解説
インタフェースの抽象メソッドは、書かなくても**暗黙に public** です。Worker は Base から `run()` を受け継いでいて、これが Runner の `run()` の実装として扱われます。ところが Base の run は修飾子なし（パッケージ内だけ）なので、public より狭くなります。実装（オーバーライド）でアクセスを狭めることはできないので、エラーになります。

- A: 親クラスから受け継いだメソッドでも、条件が合えばインタフェースの実装になります。Base の run が `public void run()` なら、Worker は何も書かずにコンパイルでき、実行すると「base」と表示されます。
- B: クラスから受け継いだメソッドとインタフェースのメソッドが同じでも、あいまいにはなりません。クラスのメソッドが実装として使われます。
- C: Runner を implements しているのは Worker です。Base が implements している必要はありません。
- E: インタフェースのメソッドは public を書かなくても public です。Runner に public を書いても、結果は変わりません。

直し方は、Base の run を public にするか、Worker で `public void run()` をオーバーライドすることです。

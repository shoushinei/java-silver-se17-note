次のプログラムをコンパイル、実行したときの結果として、正しいものを選びなさい。

```java title=Main.java
abstract class Drink {
    abstract int price();

    @Override
    public String toString() {
        return "price=" + price();
    }
}
class Tea extends Drink {
    int price() {
        return 150;
    }
}
class Coffee extends Drink {
    int price() {
        return 200;
    }
}
public class Main {
    public static void main(String[] args) {
        Drink[] drinks = { new Tea(), new Coffee(), new Drink() };
        for (Drink d : drinks) {
            System.out.println(d);
        }
    }
}
```

- A. 抽象クラス Drink を new しているため、21 行目でコンパイルエラーが発生する
- B. 「price=150」「price=200」「price=0」と表示される
- C. 「price=150」「price=200」と表示されたあと、実行時に例外がスローされる
- D. 抽象クラス Drink の配列を作っているため、21 行目でコンパイルエラーが発生する
- E. Drink の toString から抽象メソッド price を呼んでいるため、6 行目でコンパイルエラーが発生する

## 解説
21 行目の配列の初期化子に `new Drink()` があります。Drink は抽象クラスなので、**new でインスタンスを作れません**。コンパイルエラーです。

ポリモーフィズムの流れ（Tea と Coffee の price が呼ばれる）を追わせておいて、実はコンパイルエラーという作りです。

- B・C: コンパイルが通らないので、実行まで進みません。`new Drink()` を消せば「price=150」「price=200」と表示されます。
- D: `Drink[]` は「Drink 型の参照を入れる箱」を作るだけで、Drink のインスタンスは作りません。抽象クラス型の配列は作れます。同じ 21 行目のエラーでも、理由が違います。
- E: 抽象クラスの具象メソッドから、抽象メソッドを呼んでかまいません。実行時には実体（Tea や Coffee）の price が呼ばれます。

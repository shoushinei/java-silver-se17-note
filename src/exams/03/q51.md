次の2つのクラスがあります。

```java title=Parent.java
public class Parent {
    private void a() { }
    void b() { }
    public final void c() { }
    static void e() { }
}
```

```java title=Child.java
public class Child extends Parent {
    // insert code here
}
```

Child の `// insert code here` に挿入したとき、コンパイルが成功するコードを選びなさい。

- A. `static void e() { }`
- B. `private void b() { }`
- C. `void e() { }`
- D. `public void c() { }`
- E. `public String a() { return ""; }`
- F. `static void b() { }`

## 解説
| 選択肢 | 親のメソッド | 判定 |
|---|---|---|
| A | `static void e()` | OK。static 同士なので**隠蔽**になる（オーバーライドではない） |
| B | `void b()`（修飾子なし） | エラー。private はより狭いアクセスなので、オーバーライドで狭めている |
| C | `static void e()` | エラー。インスタンスメソッドで static メソッドをオーバーライドすることはできない |
| D | `public final void c()` | エラー。final メソッドはオーバーライドできない |
| E | `private void a()` | OK。private メソッドは受け継がれないので、子の a() はまったく別の新しいメソッド。戻り値の型が違っても問題ない |
| F | `void b()`（インスタンス） | エラー。static メソッドでインスタンスメソッドを隠すことはできない |

C と F は向きが逆の同じ規則です。**static かどうかがそろっていない**同じシグネチャのメソッドは、どちらの向きでも書けません。

E は「戻り値の型が違うのでオーバーライドの規則違反」と考えがちですが、親の a() は private で子からは見えないので、そもそもオーバーライドの関係になりません。

次のインタフェースと抽象クラスがあります。

```java title=Engine.java
public interface Engine {
    void start();
    void stop();
}
```

```java title=BaseEngine.java
public abstract class BaseEngine implements Engine {
    public void start() {
        System.out.println("start");
    }
    abstract void check();
}
```

同じパッケージの別のファイルに記述したとき、コンパイルが成功するクラスの宣言を選びなさい。

- A. `class A extends BaseEngine { public void stop() { } }`
- B. `class B extends BaseEngine { void stop() { } void check() { } }`
- C. `abstract class C extends BaseEngine { void check() { } }`
- D. `class D implements Engine { public void start() { } }`
- E. `class E extends BaseEngine implements Engine { public void stop() { } }`
- F. `class F extends BaseEngine { public void stop() { } private void check() { } }`

## 解説
BaseEngine は Engine の start を実装していますが、stop はまだです。さらに自分で抽象メソッド check を足しています。BaseEngine を継承する**具象クラス**は、stop と check の両方を実装しなければなりません。

| 選択肢 | stop | check | 判定 |
|---|---|---|---|
| A | public で実装 | 無い | エラー |
| B | 修飾子なし（public より狭い） | 実装 | エラー |
| C | 無い | 実装 | **OK**。abstract クラスなので、stop の実装を残してよい |
| D | 無い（Engine を直接実装） | 関係ない | エラー。具象クラスなのに stop が無い |
| E | public で実装 | 無い | エラー。implements Engine を書き足しても check の実装は必要 |
| F | public で実装 | private（修飾子なしより狭い） | エラー |

- B: Engine の stop は暗黙に public なので、実装する側も public でなければなりません。
- F: check は修飾子なし（パッケージ内）で宣言されているので、private にすると狭めることになります。

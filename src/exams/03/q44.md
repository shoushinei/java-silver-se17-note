次のメソッドの定義のうち、コンパイルエラーになるものを選びなさい。

- A. `short e() { return 100; }`
- B. `Long d() { return 10; }`
- C. `long a() { return 10; }`
- D. `double c() { return 'a'; }`
- E. `Object f() { return 1; }`
- F. `float b() { return 1.5; }`

## 解説
return に書いた値は、**変数への代入と同じルール**で戻り値の型に変換されます。`short x = 100;` が通るなら `short e() { return 100; }` も通る、と考えます。

| 選択肢 | 値の型 → 戻り値の型 | 判定 |
|---|---|---|
| A | int の定数 100 → short | OK。定数で short の範囲（-32768〜32767）に入るので、`short s = 100;` と同じく入る |
| B | int → Long | **エラー**。int をボクシングすると Integer になり、Long にはならない |
| C | int → long | OK。拡大変換 |
| D | char → double | OK。'a' は 97 で、拡大変換で 97.0 になる |
| E | int → Object | OK。Integer にボクシングしてから、親の Object として扱う |
| F | double → float | **エラー**。1.5 は double のリテラルで、float へは縮小になる（1.5f なら OK） |

B が特に間違えやすいところです。ボクシングは、基本データ型を**対応するラッパークラス**（int なら Integer）にするだけです。「int から long に広げてから Long にボクシング」という2段階の変換はしてくれません。`return 10L;` と書けば通ります。

## 検証
@case A・C・D・E は通る
@file T.java
class T {
    short e() { return 100; }
    long a() { return 10; }
    double c() { return 'a'; }
    Object f() { return 1; }
}
@javac

@case 正解 B は CE
@file T.java
class T { Long d() { return 10; } }
@javac-error incompatible types

@case 正解 F は CE
@file T.java
class T { float b() { return 1.5; } }
@javac-error incompatible types

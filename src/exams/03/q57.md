例外についての説明として、正しいものを選びなさい。

- A. Error のサブクラスは検査例外なので、catch するか throws に書かなければならない
- B. RuntimeException とそのサブクラスの例外は、throws に書かなくてもメソッドの外へスローできる
- C. 1つの catch ブロックでは、1種類の例外しか捕まえられない
- D. throw 文に書けるのは、Throwable またはそのサブクラスのインスタンスだけである
- E. catch ブロックで例外を捕まえられなかったときは、finally ブロックは実行されない
- F. throws 句に検査例外を書いたメソッドは、その例外を必ずスローしなければならない

## 解説
- A: 誤り。Error とその子孫は、RuntimeException とその子孫と同じく**非検査例外**です。catch も throws も強制されません（そもそも Error はプログラムで回復できない深刻な問題を表すので、ふつうは捕まえません）。
- B: 正しい。RuntimeException の子孫は非検査例外なので、throws に書かなくてもメソッドの外へ出せます。
- C: 誤り。`catch (IllegalStateException | IllegalArgumentException e)` のように `|` でつなぐ multi-catch を使えば、1つの catch で複数の種類を捕まえられます。
- D: 正しい。`throw "error";` や `throw new Object();` のように、Throwable の子孫ではないものを投げるとコンパイルエラーです。
- E: 誤り。finally は、例外が catch で捕まらずにメソッドの外へ出ていく場合も、出ていく前に実行されます。
- F: 誤り。throws は「投げるかもしれない」という宣言です。実際に投げなくてもかまいません。

@case C は誤り: multi-catch で2種類を捕まえられる
@file Main.java
public class Main {
    public static void main(String[] args) {
        try {
            Integer.parseInt("x");
        } catch (IllegalStateException | IllegalArgumentException e) {
            System.out.println("caught");
        }
    }
}
@javac
@run Main
@stdout

@end

@case E は誤り: 捕まえられなくても finally は実行される
@file Main.java
public class Main {
    public static void main(String[] args) {
        try {
            throw new IllegalStateException();
        } catch (IllegalArgumentException e) {
            System.out.println("catch");
        } finally {
            System.out.println("finally");
        }
    }
}
@javac
@run Main
@output

@end

    void m() throws java.io.IOException { }

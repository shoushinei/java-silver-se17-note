次のプログラムをコンパイル、実行したときの結果として、正しいものを選びなさい。

```java title=Main.java
class Animal {
    String eat(int amount) {
        return "A" + amount;
    }
}
class Dog extends Animal {
    String eat(Integer amount) {
        return "D" + amount;
    }
}
public class Main {
    public static void main(String[] args) {
        Animal a = new Dog();
        Dog d = new Dog();
        String s1 = a.eat(1);
        String s2 = d.eat(2);
        String s3 = d.eat(Integer.valueOf(3));
        System.out.println(s1 + " " + s2 + " " + s3);
    }
}
```

- A. 「D1 D2 D3」と表示される
- B. 「A1 D2 D3」と表示される
- C. 「A1 A2 D3」と表示される
- D. 「A1 A2 A3」と表示される
- E. 16 行目の d.eat(2) の呼び出しがあいまいなため、コンパイルエラーが発生する

## 解説
Dog の `eat(Integer)` は、Animal の `eat(int)` と引数の型が違うので、**オーバーライドではなくオーバーロード**です。Dog には、受け継いだ `eat(int)` と自分の `eat(Integer)` の2つがあります。

| 行 | 変数の型 | 候補 | 選ばれるもの | 表示 |
|---|---|---|---|---|
| 15 | Animal | `eat(int)` だけ | Animal の eat(int)。Dog はこれをオーバーライドしていないので、実体が Dog でもそのまま | A1 |
| 16 | Dog | `eat(int)` と `eat(Integer)` | int の 2 は、ボクシングなしで受け取れる `eat(int)` が優先 | A2 |
| 17 | Dog | `eat(int)` と `eat(Integer)` | Integer は、そのまま受け取れる `eat(Integer)` が優先（int 版はアンボクシングが必要） | D3 |

よって「A1 A2 D3」です。

- A: Dog の eat(Integer) が eat(int) をオーバーライドしていると考えた誤りです。もし Dog に `@Override` を付けると、何もオーバーライドしていないのでコンパイルエラーになります。
- B: 16 行目でボクシングして Integer 版を選ぶと考えた誤りです。オーバーロードの選択では、ボクシングが要らない候補が先に選ばれます。
- E: 1段階目（ボクシングなし）で eat(int) だけに決まるので、あいまいにはなりません。

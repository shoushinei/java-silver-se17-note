次のクラスの `// insert code here` に挿入したとき、コンパイルが成功するコードを選びなさい。

```java title=Calc.java
public class Calc {
    int sum(int[] values) {
        return 0;
    }
    // insert code here
}
```

- A. `int sum(int... values) { return 1; }`
- B. `long sum(int[] values) { return 1L; }`
- C. `int sum(Integer[] values) { return 1; }`
- D. `static int sum(int[] nums) { return 1; }`
- E. `int sum(int[][] values) { return 1; }`
- F. `private int sum(int[] data) { return 1; }`

## 解説
同じ名前のメソッドを並べられるのは、**引数の型・数・並び**が違うときだけです（オーバーロード）。

| 選択肢 | 引数の型 | 判定 |
|---|---|---|
| A | `int...`（中身は `int[]`） | 既存の `sum(int[])` と同じなのでエラー |
| B | `int[]` | 戻り値の型だけが違うのでエラー |
| C | `Integer[]` | `int[]` とは別の型なので OK |
| D | `int[]` | static かどうかと引数名は区別に使われないのでエラー |
| E | `int[][]` | `int[]` とは別の型なので OK |
| F | `int[]` | アクセス修飾子と引数名だけが違うのでエラー |

A が紛らわしいところです。可変長引数 `int...` は、メソッドの中では `int[]` 型の引数として扱われ、シグネチャ（メソッドを区別する情報）も `int[]` と同じになります。そのため「sum(int...) と sum(int[]) の両方は宣言できない」というエラーになります。

C の `Integer[]` と `int[]` は、要素の型が違う別の配列型です。配列どうしにはボクシングもないので、別の引数として区別されます。

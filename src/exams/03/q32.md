次のクラスがあります。

```java title=Loader.java
import java.io.IOException;

public class Loader {
    public static String read(String path) throws IOException {
        if (path.isEmpty()) {
            throw new IOException("empty");
        }
        return "data";
    }
}
```

別のクラスに次のメソッドを定義したとき、コンパイルが成功するものを選びなさい。

- A. `void a() throws Exception { Loader.read("x"); }`
- B. `void b() { Loader.read("x"); }`
- C. `void c() { try { Loader.read("x"); } catch (RuntimeException ex) { } }`
- D. `void d() throws java.io.FileNotFoundException { Loader.read("x"); }`
- E. `void e() { try { Loader.read("x"); } catch (Exception ex) { } }`
- F. `void f() { try { Loader.read("x"); } finally { } }`

## 解説
read は検査例外の IOException を throws に書いています。呼び出す側は、次のどちらかをしなければなりません。

1. catch で捕まえる（IOException か、その親の型で）
2. 自分の throws に書いて、さらに呼び出し元へ任せる（IOException か、その親の型で）

| 選択肢 | 判定 | 理由 |
|---|---|---|
| A | OK | Exception は IOException の親なので、throws Exception で任せられる |
| B | エラー | 捕まえても任せてもいない |
| C | エラー | IOException は RuntimeException の子ではないので、この catch では捕まらない |
| D | エラー | FileNotFoundException は IOException の**子**。子を書いても、親の IOException は任せたことにならない |
| E | OK | Exception は IOException の親なので、この catch で捕まえられる |
| F | エラー | finally は例外を捕まえないので、IOException はそのまま外へ出ていく |

D は向きを間違えやすいところです。throws や catch に書いた型は、**その型と子孫**の例外を引き受けます。FileNotFoundException と書いても、その親である IOException は引き受けられません。

次のうち、実行すると NumberFormatException がスローされるものを選びなさい。

- A. `int a = Integer.parseInt(null);`
- B. `int b = Integer.parseInt("+12");`
- C. `int c = Integer.parseInt("12.0");`
- D. `double d = Double.parseDouble("12");`
- E. `Integer e = Integer.valueOf("-0");`
- F. `String s = null; int f = s.length();`

## 解説
- A: null を渡すと、**NullPointerException ではなく NumberFormatException** になります（「null という文字列は数値にできない」という扱い）。正しい。
- B: 先頭の `+` や `-` の符号は付けてよいので、12 になります。
- C: `"12.0"` は小数の形なので、整数（int）としては読めません。正しい。
- D: `Double.parseDouble` は整数の形の文字列も読めるので、12.0 になります。
- E: `-0` は符号付きの 0 として読めるので、0 になります。
- F: null の変数に `.length()` を付けているので NullPointerException です。NumberFormatException ではありません。

NumberFormatException は IllegalArgumentException の子（非検査例外）です。catch の順番や multi-catch の問題で、この親子関係もよく使われます。

## 検証
@case 正解 A: parseInt(null) は NumberFormatException
@file Main.java
public class Main {
    public static void main(String[] args) {
        int a = Integer.parseInt(null);
    }
}
@javac
@run Main
@exception NumberFormatException

@case 正解 C: parseInt("12.0") は NumberFormatException
@file Main.java
public class Main {
    public static void main(String[] args) {
        int c = Integer.parseInt("12.0");
    }
}
@javac
@run Main
@exception NumberFormatException

@case B・D・E は例外にならない
@file Main.java
public class Main {
    public static void main(String[] args) {
        int b = Integer.parseInt("+12");
        double d = Double.parseDouble("12");
        Integer e = Integer.valueOf("-0");
        System.out.println(b + " " + d + " " + e);
    }
}
@javac
@run Main
@stdout
12 12.0 0
@end

@case F は NullPointerException
@file Main.java
public class Main {
    public static void main(String[] args) {
        String s = null;
        int f = s.length();
    }
}
@javac
@run Main
@exception NullPointerException

次のプログラムを確認してください。Car クラスでコンパイルエラーが発生します。

```java title=Vehicle.java
public sealed abstract class Vehicle permits Car {
    public abstract int wheels();
}
```

```java title=Car.java
public sealed class Car extends Vehicle {
    public int wheels() {
        return 4;
    }
}
```

コンパイルエラーの理由として、正しいものを選びなさい。

- A. Vehicle が sealed と abstract を同時に宣言しているため
- B. sealed を宣言した Car に、サブクラスが1つもないため
- C. sealed クラスを継承するクラスは、final でなければならないため
- D. Vehicle が、別のファイルにある Car を permits に書いているため
- E. Car が abstract メソッドの wheels を public で実装しているため

## 解説
sealed は「継承できるクラスを限定する」修飾子なので、**許可されたサブクラスが1つ以上**なければなりません。Car は sealed なのに、permits も無く、同じファイルに子クラスもありません。そのため `sealed class must have subclasses` というコンパイルエラーになります。

- A: sealed と abstract は同時に付けられます。むしろよくある組み合わせです。
- C: sealed クラスの子は final・sealed・non-sealed のどれかであればよく、final に限りません。Car は sealed を選んでいるので、そこは問題ありません。
- D: 同じパッケージなら、別のファイルのクラスを permits に書けます。
- E: 抽象メソッドを public で実装するのは正しい書き方です。

直し方は、Car を `final` や `non-sealed` にするか、Car の子クラスを用意することです。たとえば Car.java の中に `final class Taxi extends Car { }` を書けば、permits を省略しても Taxi が許可されたサブクラスになり、コンパイルできます。

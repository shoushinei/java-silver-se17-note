次のメソッドは、コンパイルエラーになります。

```java title=Finder.java
public class Finder {
    static int indexOf(int[] a, int key) {
        for (int i = 0; i < a.length; i++) {
            if (a[i] == key) {
                return i;
            }
        }
    }
}
```

コンパイルが成功するように修正する方法として、正しいものを選びなさい。

- A. 7 行目と 8 行目の間に `return -1;` を追加する
- B. 6 行目の後（if 文の後ろ）に `else { return -1; }` を追加する
- C. 7 行目と 8 行目の間に `throw new IllegalArgumentException("not found");` を追加する
- D. 2 行目の戻り値の型を `void` に変える
- E. 4〜6 行目の if 文を、`return i;` の1文だけにする

## 解説
エラーの理由は `missing return statement` です。コンパイラは、for の条件 `i < a.length` が最初から false の場合（配列が空など）、**ループの本体が1回も実行されずにメソッドの最後に到達する**経路があると判断します。その経路には return がありません。

- A: ループの後ろに return を置けば、すべての経路で値を返します。正しい。
- B: if-else にしても、それは**ループの中**の話です。ループを1回も回らない経路は残るのでエラーのままです。
- C: 最後に例外を投げれば、メソッドの終わりに到達する経路がなくなります。return の代わりになります。正しい。
- D: void にすると、今度は `return i;`（値を返す return）がエラーになります。
- E: 本体を `return i;` だけにしても、ループが回らない経路は残るのでエラーのままです。

「ループの中で必ず return するから大丈夫」とは判断されません。コンパイラは変数の値を追わず、**ループが0回で終わる可能性**を常に考えます（`while (true)` のように条件が定数の true なら別です）。

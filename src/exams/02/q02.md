次のクラスの `// insert code here` に挿入したとき、コンパイルが成功するコードを選びなさい。

```java title=Calculator.java
import java.io.IOException;

public class Calculator {
    protected Number calc(int x) throws IOException {
        return x;
    }
}
```

```java title=SafeCalculator.java
public class SafeCalculator extends Calculator {
    // insert code here
}
```

- A. `public Integer calc(int x) { return x; }`
- B. `protected Object calc(int x) { return x; }`
- C. `Number calc(int x) { return x; }`
- D. `protected Number calc(int x) throws Exception { return x; }`
- E. `public Number calc(long x) throws Exception { return x; }`
- F. `private Integer calc(int x) { return x; }`

## 解説
引数が `int` のものは、親の `calc(int)` の**オーバーライド**なので、3つの規則を満たす必要があります。

| 規則 | 親 | 子で書けるもの |
|---|---|---|
| アクセス修飾子 | protected | protected か public（狭めるのは不可） |
| 戻り値の型 | Number | Number かその子（Integer など） |
| 検査例外 | IOException | IOException かその子、または書かない |

- A: public（広げた）・Integer（Number の子）・throws なし。すべて満たすので正しい。
- B: 戻り値 Object は Number の親なのでエラー。
- C: 修飾子なし（パッケージ）は protected より狭いのでエラー。
- D: Exception は IOException の親なので、検査例外を広げたことになりエラー。
- E: 引数が `long` なので、オーバーライドではなく**オーバーロード**です。別のメソッドとして扱われるので、throws も戻り値も自由です。正しい。
- F: private は狭めているのでエラー。

「throws Exception があるから E はエラー」と考えさせる引っかけです。まず引数の型を見て、オーバーライドかオーバーロードかを決めてから規則を当てはめます。

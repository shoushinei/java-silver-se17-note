次のプログラムをコンパイル、実行したときの結果として、正しいものを選びなさい。

```java title=Main.java
class Res implements AutoCloseable {
    private final String name;

    Res(String name, boolean fail) {
        if (fail) throw new IllegalStateException(name);
        this.name = name;
        System.out.print("open " + name + " ");
    }

    @Override
    public void close() {
        System.out.print("close " + name + " ");
    }
}

public class Main {
    public static void main(String[] args) {
        try (Res a = new Res("A", false); Res b = new Res("B", true)) {
            System.out.print("body ");
        } catch (IllegalStateException e) {
            System.out.print("catch " + e.getMessage() + " ");
        } finally {
            System.out.print("finally");
        }
    }
}
```

- A. 「open A catch B close A finally」と表示される
- B. 「open A close A close B catch B finally」と表示される
- C. 「open A close A catch B finally」と表示される
- D. 「catch B finally」と表示される
- E. close メソッドが throws Exception を宣言していないため、コンパイルエラーが発生する

## 解説
1. リソースは宣言の順に初期化されます。a が作られて「open A 」。
2. b のコンストラクタで例外が発生します。b は**作られていない**ので、閉じる対象にもなりません。try の本体（body）も実行されません。
3. 例外で try を抜けるとき、**すでに初期化が済んだリソースだけ**を逆順に閉じます。ここでは a だけなので「close A 」。
4. リソースを閉じてから catch に進み「catch B 」、最後に finally で「finally」。

- A: リソースを閉じるのは catch より**前**です。
- B: 作られていない b は閉じられません。
- E: AutoCloseable の close() は `throws Exception` と宣言されていますが、オーバーライドする側は例外を減らしてよいので、throws を書かなくても問題ありません。

次のプログラムの `// insert code here` に挿入したとき、コンパイルが成功するものを選びなさい。

```java title=Main.java
import java.io.*;
import java.nio.file.*;

public class Main {
    static void run(String path, String num) throws IOException {
        Files.readAllLines(Path.of(path));
        Integer.parseInt(num);
    }

    public static void main(String[] args) {
        try {
            run("data.txt", "x");
        }
        // insert code here
    }
}
```

- A.
  ```java
  catch (IOException e) { }
  catch (NoSuchFileException e) { }
  catch (NumberFormatException e) { }
  ```
- B.
  ```java
  catch (IllegalArgumentException e) { }
  catch (NumberFormatException e) { }
  catch (IOException e) { }
  ```
- C.
  ```java
  catch (NoSuchFileException | NumberFormatException e) { }
  catch (IOException | IllegalArgumentException e) { }
  ```
- D.
  ```java
  catch (NoSuchFileException | IOException e) { }
  catch (NumberFormatException e) { }
  ```
- E.
  ```java
  catch (Exception e) { }
  catch (IOException e) { }
  ```

## 解説
使われている例外の親子関係は次のとおりです。

| 子（先に書く） | 親（後に書く） |
|---|---|
| NoSuchFileException | IOException |
| NumberFormatException | IllegalArgumentException |
| IOException・IllegalArgumentException | Exception |

- A: IOException の後に、その子の NoSuchFileException を書いているので、2つ目の catch に到達できずエラー。
- B: IllegalArgumentException の後に、その子の NumberFormatException を書いているのでエラー。
- C: 1つ目の multi-catch の2つは親子関係が無く、2つ目も同じです。そして、子（NoSuchFileException・NumberFormatException）が上、親（IOException・IllegalArgumentException）が下という順番も守られています。正しい。
- D: multi-catch に親子関係のある NoSuchFileException と IOException を並べているのでエラー。
- E: Exception がすべてを捕まえるので、後ろの IOException に到達できずエラー。

multi-catch を使っても「子が先」の規則は同じです。1つの `|` の中では親子を混ぜない、catch ブロックの間では子を上に、と2段階で確かめます。

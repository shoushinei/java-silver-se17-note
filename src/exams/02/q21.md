次のインタフェースがあります。

```java title=Shape.java
public sealed interface Shape permits Circle, Square, Poly { }
```

Shape を実装する型の宣言として、コンパイルエラーにならないものを選びなさい。なお、各宣言は同じパッケージの別々のファイルに書き、ほかの型は正しく宣言されているものとします。

- A. `public record Circle(double r) implements Shape { }`
- B. `public final class Square implements Shape { }`
- C. `public class Poly implements Shape { }`
- D. `public non-sealed class Poly implements Shape { }`
- E. `public final class Triangle implements Shape { }`
- F. `public sealed class Square implements Shape { }`

## 解説
sealed インタフェースを実装できるのは `permits` に書いた型だけで、実装する側は **final・sealed・non-sealed のどれか**でなければなりません。

- A: record は**暗黙に final** なので、何も書かなくても条件を満たします。正しい。
- B: final を明示しています。正しい。
- C: 3つのどれも書いていないのでエラー。
- D: non-sealed にすると、Poly から先は誰でも継承できるようになります。正しい。
- E: Triangle は permits に書かれていないのでエラー。
- F: sealed にするなら、Square 自身の子を用意する（permits で指定するか、同じファイルに書く）必要があります。子が1つも無い sealed クラスは `sealed class must have subclasses` でエラーです。

「record には final と書いていないから C と同じでエラー」と考えさせるのが A の引っかけです。

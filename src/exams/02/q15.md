次のクラスの `// insert code here` に挿入したとき、コンパイルが成功するコードを選びなさい。

```java title=Loader.java
import java.io.IOException;

public class Loader {
    void load() throws IOException { }
}
```

```java title=FileLoader.java
import java.io.*;

public class FileLoader extends Loader {
    // insert code here
}
```

- A. `void load() throws FileNotFoundException { }`
- B. `void load() throws Exception { }`
- C. `void load() throws IOException, java.sql.SQLException { }`
- D. `void load() throws IllegalStateException { }`
- E. `void load() throws Throwable { }`
- F. `protected void load() throws IOException, InterruptedException { }`

## 解説
オーバーライドした子のメソッドは、親より**多くの検査例外を投げると宣言できません**。親を使う側は「IOException に備えておけば十分」と考えてコードを書くからです。

- A: FileNotFoundException は IOException の**子**なので、範囲が狭まっただけです。正しい。
- B: Exception は IOException の親で、範囲が広がるのでエラー。
- C: SQLException は IOException と無関係な検査例外なので、増やしたことになりエラー。
- D: IllegalStateException は RuntimeException の子（**非検査例外**）です。非検査例外は throws に書いても書かなくても制約を受けません。正しい。
- E: Throwable は IOException の親（祖先）なのでエラー。
- F: protected にアクセスを広げるのは問題ありませんが、InterruptedException は IOException と無関係な検査例外なのでエラー。

判断には例外の親子関係の知識が必要です（第6章 01 の階層図）。「throws に何か増えたらエラー」ではなく、「**検査例外の範囲が広がったらエラー**」と覚えます。

次のプログラムをコンパイル、実行したときの結果として、正しいものを選びなさい。

```java title=Main.java
import java.util.*;

class Key {
    int v;
    Key(int v) { this.v = v; }

    public boolean equals(Key other) {
        return other != null && v == other.v;
    }

    public int hashCode() {
        return v;
    }
}

public class Main {
    public static void main(String[] args) {
        Key a = new Key(1);
        Key b = new Key(1);
        List<Key> list = List.of(a);
        System.out.println(a.equals(b) + " " + Objects.equals(a, b) + " "
                + list.indexOf(b));
    }
}
```

- A. 「true true 0」と表示される
- B. 「true false -1」と表示される
- C. 「true false 0」と表示される
- D. 「false false -1」と表示される
- E. equals の引数が Object ではないため、コンパイルエラーが発生する

## 解説
Key の `equals(Key other)` は、引数の型が Object ではないので、Object の `equals(Object)` の**オーバーライドではなくオーバーロード**です。Key には equals が2つある状態になります。

| 呼び出し | 選ばれる equals | 結果 |
|---|---|---|
| `a.equals(b)` | b は Key 型なので equals(Key) | 値が同じ → true |
| `Objects.equals(a, b)` | 中で `a.equals((Object) b)` を呼ぶ → Object の equals | 別インスタンス → false |
| `list.indexOf(b)` | 中で equals(Object) を使って探す | 見つからない → **-1** |

Objects.equals やリストの indexOf・contains は、相手を Object として受け取って `equals(Object)` を呼びます。自分で書いた equals(Key) は呼ばれないので、中身が同じでも「等しくない」と判断されます（A・C は誤り）。

オーバーロードは書いてもエラーではありません（E は誤り）。`@Override` を付けていれば、ここでコンパイルエラーになって誤りに気づけます。正しくは `public boolean equals(Object other)` と書きます。

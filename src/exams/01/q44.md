次のプログラムを確認してください。

```java title=Types.java
interface Pet { }
abstract class Animal { }
class Cat extends Animal implements Pet { }
class Lion extends Cat { }
```

同じパッケージのクラス（java.util をインポート済み）に記述したとき、**コンパイルエラーになるコード**を選びなさい。

- A.
  ```java
  List<Animal> a = new ArrayList<>();
  a.add(new Lion());
  ```
- B.
  ```java
  List<Pet> b = new ArrayList<>();
  b.add(new Cat());
  ```
- C.
  ```java
  List<Cat> c = new ArrayList<>();
  c.add(new Lion());
  ```
- D.
  ```java
  List<Lion> d = new ArrayList<>();
  d.add(new Cat());
  ```
- E.
  ```java
  List<Object> e = new ArrayList<>();
  e.add(new Lion());
  ```

## 解説
`List<T>` の add に渡せるのは、**T 型の変数に代入できるもの**、つまり T そのものか T の子（実装クラス）です。

- A: Lion は Cat の子で、Cat は Animal の子なので、Lion は Animal に代入できます。
- B: Cat は Pet を実装しているので、Pet に代入できます。
- C: Lion は Cat の子です。
- E: すべてのクラスは Object の子です。
- D: Cat は Lion の**親**です。親のインスタンスを子の型の変数に入れることはできないので、コンパイルエラーです。

「Lion のリストに Cat を入れる」のは、「ライオンだけの檻に、ライオンかどうか分からない猫を入れる」ようなものです。逆向き（A〜C）は常に安全なので許されています。

## 検証

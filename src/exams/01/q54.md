例外処理についての説明として、正しいものを選びなさい。

- A. リソースを宣言しない通常の try 文には、catch ブロックか finally ブロックの少なくとも一方が必要である
- B. try-with-resources のリソースは、catch ブロックを実行した後に閉じられる
- C. 1つの try 文に、finally ブロックを複数書くことができる
- D. 継承関係にある2つの例外を別々の catch ブロックで捕まえるときは、サブクラスの例外を先に書かなければならない
- E. multi-catch では、継承関係にある例外同士を `|` で並べることができる

## 解説
- A: 通常の try 文は、catch か finally が1つも無いとコンパイルエラーです。正しい。なお try-with-resources は、catch も finally も無い `try (Res r = ...) { }` だけでも書けます。
- B: リソースは try ブロックを抜けた直後、**catch より前に**閉じられます。誤り。
- C: finally は1つの try 文に1つだけです。誤り。
- D: スーパークラスの catch を先に書くと、後ろのサブクラスの catch には絶対に到達できないので、コンパイルエラーになります。正しい。
- E: 継承関係のある例外を `|` で並べると、片方がもう片方に含まれていて無駄なので、コンパイルエラーです。誤り。

## 検証
@case 正解 A: catch も finally も無い try はエラー
@file T.java
class T { void m() { try { System.out.println(); } } }
@javac-error

@case A の補足: try-with-resources は単独で書ける
@file T.java
class T { void m() throws Exception { try (AutoCloseable r = () -> { }) { } } }
@javac

@case B: リソースは catch より前に閉じられる
@file Main.java
public class Main {
    public static void main(String[] args) {
        try (AutoCloseable r = () -> System.out.print("close ")) {
            throw new RuntimeException();
        } catch (Exception e) {
            System.out.print("catch");
        }
    }
}
@javac
@run Main
@stdout
close catch
@end

@case C: finally は複数書けない
@file T.java
class T { void m() { try { } finally { } finally { } } }
@javac-error

@case 正解 D: スーパークラスを先に書くとエラー
@file T.java
class T {
    void m() {
        try { Integer.parseInt("x"); }
        catch (IllegalArgumentException e) { }
        catch (NumberFormatException e) { }
    }
}
@javac-error has already been caught

@case E: 継承関係のある例外は multi-catch に並べられない
@file T.java
class T {
    void m() {
        try { Integer.parseInt("x"); }
        catch (IllegalArgumentException | NumberFormatException e) { }
    }
}
@javac-error

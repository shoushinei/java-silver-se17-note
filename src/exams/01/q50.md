次のプログラムを確認してください。Both インタフェースでコンパイルエラーが発生します。その理由として考えられるものを選びなさい。

```java title=Source.java
public interface Source {
    Iterable<String> items();
}
```

```java title=ListSource.java
import java.util.List;

public interface ListSource extends Source {
    List<String> items();
}
```

```java title=SetSource.java
import java.util.Set;

public interface SetSource extends Source {
    Set<String> items();
}
```

```java title=Both.java
public interface Both extends ListSource, SetSource {
}
```

- A. インタフェースは、2つ以上のインタフェースを継承できないため
- B. ListSource が、Source とは異なる戻り値型の同名メソッドを定義しているため
- C. ListSource と SetSource から受け継ぐ items() の戻り値型に互換性がないため
- D. Both が items() を定義していないため

## 解説
Both は ListSource と SetSource の両方から `items()` を受け継ぎます。1つのメソッドとして両立させるには、どちらかの戻り値型が他方の戻り値型の**子（またはそれ自身）**でなければなりません。

`List<String>` と `Set<String>` はどちらも `Collection<String>` の子ですが、**互いに親子関係がありません**。List でもあり Set でもある戻り値を返すメソッドは作れないので、Both でコンパイルエラーになります。

- A: インタフェースは `extends A, B` のように複数のインタフェースを継承できます。
- B: `List<String>` は `Iterable<String>` の子なので、ListSource の items() は正しいオーバーライド（共変戻り値）です。SetSource も同じです。
- D: インタフェースなので、メソッドを定義する必要はありません。

もし SetSource の戻り値が `Collection<String>` なら、`List<String>` がその子なので、Both はコンパイルできます。

## 検証
@case 正解 C: Both でエラー
@stem
@javac-error

@case ListSource と SetSource だけならコンパイルできる（B は正しいオーバーライド）
@stem
@file Both.java
public interface Both {
}
@javac

@case 参考: 片方が他方の子の型なら両立する
@stem

public interface SetSource extends Source {
    Collection<String> items();
}
@javac

次のプログラムはコンパイルエラーになります。その理由として、正しいものを選びなさい。

```java title=Vehicle.java
public abstract class Vehicle {
    private final int wheels;
    protected Vehicle(int wheels) {
        this.wheels = wheels;
    }
    public int wheels() {
        return wheels;
    }
}
```

```java title=Bike.java
public class Bike extends Vehicle {
    public String name() {
        return "bike";
    }
}
```

- A. 抽象クラスの Vehicle は、wheels() のような本体のあるメソッドを持てないため
- B. Vehicle のコンストラクタが protected なので、サブクラスの Bike から呼び出せないため
- C. Bike にはコンストラクタが無いので既定のコンストラクタが作られ、その中の super() が呼ぶ引数なしのコンストラクタが Vehicle に無いため
- D. final のフィールド wheels を、宣言と同時に初期化していないため

## 解説
コンストラクタを1つも書かないクラスには、コンパイラが**既定のコンストラクタ**を作ります。その中身は `super();`、つまり**親の引数なしのコンストラクタを呼ぶ**だけです。

ところが Vehicle には `Vehicle(int wheels)` しか無く、引数なしのコンストラクタがありません。コンストラクタを1つでも書いたクラスには既定のコンストラクタが作られないためです。呼べるコンストラクタが無いので、Bike でコンパイルエラーになります。

直すには、Bike に `public Bike() { super(2); }` のようなコンストラクタを書きます。

- A: 抽象クラスは、本体のあるメソッドもコンストラクタも持てます。
- B: protected はサブクラスから呼べます。
- D: final のフィールドは、コンストラクタで一度だけ代入すれば問題ありません。

## 検証
@case 正解 C: Bike でコンパイルエラー（引数なしのコンストラクタが無い）
@stem
@javac-error constructor Vehicle in class Vehicle cannot be applied

@case 参考: super(2) を呼ぶコンストラクタを書けば通る

    public Bike() {
        super(2);
    }

    }

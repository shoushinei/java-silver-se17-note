次のプログラムはコンパイルエラーになります。その理由として、正しいものを選びなさい。

```java title=lib/Printer.java
package lib;

public class Printer {
    protected void print() {
        System.out.println("printing");
    }
}
```

```java title=app/Office.java
package app;

import lib.Printer;

public class Office extends Printer {
    public void work() {
        print();
        new Printer().print();
    }
}
```

- A. Office は Printer のサブクラスではないため、別パッケージの protected メソッドを呼び出せない
- B. Office は Printer のサブクラスだが、別パッケージの protected メソッドに届くのは Office 型（自分の型）の参照を通したときだけで、Printer 型の参照からは呼び出せない
- C. Printer のコンストラクタが protected なので、new Printer() を記述できない
- D. print() を this. を付けずに呼び出しているため

## 解説
Office は Printer を継承しているので、別パッケージでも `print()`（this.print() と同じ）は呼べます。問題は `new Printer().print()` の行です。

別パッケージのサブクラスが protected メンバに届くのは、**自分のクラス（またはその子孫）の型の参照を通したときだけ**です。`new Printer()` の型は Printer なので、たとえ Office が Printer の子でも届きません。protected は「継承した自分の部品として使ってよい」という許可で、「親の型のオブジェクトなら何でも中を触ってよい」という許可ではないからです。

- A: Office は `extends Printer` しているので、サブクラスです。
- C: Printer にはコンストラクタが書かれていないので、既定のコンストラクタ（public なクラスなら public）が作られます。new できます。
- D: this. は省略してかまいません。

## 検証
@case 正解 B: Printer 型の参照からの呼び出しでエラー
@stem
@javac-error print() has protected access in Printer

    public void work() {
        print();
        this.print();

    }
}

次のクラスが Base.java に定義されています。

```java title=Base.java
public class Base {
}
```

別のファイル Sub.java に、Base のサブクラスとして記述できるクラス宣言を選びなさい。

- A. `abstract class Sub extends Base { }`
- B. `protected class Sub extends Base { }`
- C. `static class Sub extends Base { }`
- D. `non-sealed class Sub extends Base { }`
- E. `sealed class Sub extends Base { }`
- F. `private class Sub extends Base { }`
- G. `final class Sub extends Base { }`

## 解説
トップレベル（ほかのクラスの中ではない）のクラスに付けられるアクセス修飾子は、`public` か「なし」だけです。`protected`（B）と `private`（F）は、クラスの中に書く入れ子のクラスにしか付けられません。`static`（C）も入れ子のクラス専用です。

`abstract`（A）と `final`（G）はトップレベルでも付けられるので正解です。

- D の `non-sealed` は「sealed クラスの子として、継承を再び開放する」ための修飾子です。親の Base は sealed ではないので付けられません。
- E の `sealed` は、許可するサブクラス（permits）を持つクラスに付けます。Sub のサブクラスがどこにも無く、permits もないのでコンパイルエラーです。

## 検証
@case 正解 A: abstract は付けられる
@stem
@file Sub.java
abstract class Sub extends Base { }
@javac

@case 正解 G: final は付けられる
@stem
@file Sub.java
final class Sub extends Base { }
@javac

@case B: protected はトップレベルに付けられない
@stem
@file Sub.java
protected class Sub extends Base { }
@javac-error

@case C: static はトップレベルに付けられない
@stem
@file Sub.java
static class Sub extends Base { }
@javac-error

@case D: 親が sealed でないので non-sealed は付けられない
@stem
@file Sub.java
non-sealed class Sub extends Base { }
@javac-error

@case E: サブクラスの無い sealed はエラー
@stem
@file Sub.java
sealed class Sub extends Base { }
@javac-error

@case F: private はトップレベルに付けられない
@stem
@file Sub.java
private class Sub extends Base { }
@javac-error

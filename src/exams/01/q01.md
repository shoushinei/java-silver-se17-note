次のプログラムを確認してください。

```java title=Finder.java
public interface Finder {
    int indexOf(String[] words, String key);
}
```

```java title=LinearFinder.java
public interface LinearFinder extends Finder {
    @Override
    default int indexOf(String[] words, String key) {
        for (int i = 0; i < words.length; i++) {
            if (words[i].equals(key)) {
                return i;
            }
        }
        return -1;
    }
}
```

```java title=Shelf.java
public class Shelf implements LinearFinder {
}
```

```java title=Main.java
public class Main {
    public static void main(String... args) {
        String[] books = {"java", "sql", "css"};
        int pos = new Shelf().indexOf(books, args[1]);
        System.out.println(pos >= 0 ? "hit:" + pos : "miss");
    }
}
```

このプログラムを次のコマンドで実行したときの結果として、正しいものを選びなさい。

```console
> java Main sql css
```

- A. 「hit:1」と表示される
- B. 「hit:2」と表示される
- C. 「miss」と表示される
- D. Shelf クラスでコンパイルエラーが発生する
- E. 実行時に例外がスローされる

## 解説
ポイントは2つあります。

1つ目は、`LinearFinder` が親の `Finder` の抽象メソッド `indexOf` を **default メソッドとしてオーバーライドしている**ことです。サブインタフェースは、親の抽象メソッドに default で本体を与えられます。`@Override` を付けても問題ありません。これで `indexOf` は抽象ではなくなるので、`Shelf` は何も書かなくても `LinearFinder` を実装できます。D は誤りです。

2つ目は、コマンドライン引数の番号です。`java Main sql css` の引数は `args[0]` が `"sql"`、`args[1]` が `"css"` です。探すのは `"css"` なので、見つかる位置は 2 です。`args[1]` を「1つ目の引数」と読むと A を選んでしまいます。

`main(String... args)` は `main(String[] args)` と同じ扱いなので、起動にも問題はありません。

## 模擬試験

本番と同じ形式（90 分・60 問・選択式）の模擬試験です。問題はすべてオリジナルで、元の問題の焼き直しではありません。

| 試験 | 作り方 |
|---|---|
| 自作模擬試験 1 | 市販の問題集の模擬試験①と同じ論点を、別のコード・別の設定で問う |
| 自作模擬試験 2 | 模擬試験①・②の2回分を分析し、論点の比率・問題形式・ひっかけの傾向をそろえて新しく作った1回分 |
| 自作模擬試験 3 | 模擬試験①・②の章の配分・選ぶ数（1つ・2つ・3つ）にそろえて作った1回分。ひっかけを重ねた問題や細かい論点が多く、黒本よりかなり難しい（腕試し用） |
| 自作模擬試験 4 | 試験 3 が難しすぎた反省から、1問1論点・短い選択肢で作った1回分。基本問題が多く、黒本よりやや易しい（基礎の確認用） |
| 自作模擬試験 5 | 黒本①・②の120問を「基本・標準・応用」に分け直し、その割合（16・32・12 問）にそろえた1回分。黒本と同じ難しさのねらい |

| モード | ページ | 使い方 |
|---|---|---|
| テスト | `exams/01/` 〜 `exams/05/` | 90 分の制限時間つきで解き、採点して合否の目安を出す。提出後はそのまま全問を見直せる |
| 振り返り | `exams/01/review.html` 〜 `exams/05/review.html` | テストをせずに、正解・解説つきで読む。時間制限なし |

どの画面も「1 問ずつ表示 ＋ 横（スマホでは下から出るシート）に問題番号の一覧」という同じ形です。
番号を押せばその問題へ飛べ、← → キーや「前へ／次へ」で順に送れます。

- 受験中は、回答済み・選ぶ数が不足・見直しマークが一覧の番号に出ます。未回答やマーク付きだけに絞り込めます。
- 未回答が残っていても提出できます（残り問題数を確認してから提出）。時間切れで自動提出され、未回答は不正解です。
- 途中でタブを閉じても、回答とマークは残ります（時間は進み続けます）。
- 用事ができたときは**中断**できます。時計が止まり、問題は表示されなくなります。回答・見直しマーク・残り時間は
  このブラウザに保存され、次に開いたときの「続きから再開」でその残り時間から続けられます（中断した回数は記録に残ります）。
- 提出すると、まず結果の概要（得点・合否・章ごとの正答率）が出ます。一覧の番号には ○（正解）×（不正解）−（未回答）が付き、
  すべて／不正解・未回答／正解／見直しマークで絞り込めます。各問で自分の選択・正解・解説を確認でき、
  解説から教材の該当する節（「5-10「default / static / private」」のように）へ直接飛べます。
- 提出した回はすべて**受験記録**として残ります（第1回、第2回…）。いつでも「結果を開く」でその回の ○× と解説を見直せ、
  問題ごとに書いた**振り返りメモ**もその回の記録に保存されます。記録はこのブラウザにだけ保存されます
  （手元で `backend/` を動かして開いた場合は、データベースにも保存されます。下の「[自宅で受験記録 API とデータベースを動かす](#自宅で受験記録-api-とデータベースを動かすbackend)」）。
- 別のパソコンやブラウザの記録は、**記録を書き出す**（JSON ファイル）→ 移したい側で**記録を読み込む**で、今の記録に追加できます。
  試験のページはその試験の分、一覧のページはすべての試験の分をまとめて扱います。読み込みは足すだけで、今ある記録は消えません。
  同じ回は二重に入らず、足したあとは受けた日時の古い順に第1回、第2回…と振り直します。
- 記録が残っていない回（スクリーンショットや紙に ○× だけある回）は、**結果を手で入力する**で記録にできます。
  全問 ○ から始まり、番号を押すたびに ○ → × → 未回答 と変わります（見直しマークも付けられます）。
  保存すると採点結果の画面が開き、ふつうの回と同じように振り返りメモを書けます。選んだ選択肢は記録されません。
- 結果の画面は URL（`#r…-q12` など）にも位置が入るので、再読み込みしても同じ問題に戻れます。
- 合格ラインの目安は 65%（試験ごとに `exam.json` の `passRate` で変えられます）。

## はじめての方へ（使い方のページ）

文字で説明する代わりに、本物のページを枠（iframe）の中に開き、説明している部品に枠を重ねて 1 歩ずつ進めます。
「全体の流れ」「教材」「模擬試験」「受験記録」の4つに分かれていて、模擬試験の説明では実際にテストを始め、答えを選び、
提出して採点結果・解説・振り返りメモまでを見せます。

枠の中のページは、アドレスに `?guide` を付けて開いています。このときページは**見本モード**で動きます。

- 模擬試験は、受験記録などを localStorage に一切書かず、ページを開いているあいだだけのメモリに置きます。受験記録には見本の2回分が入っています。
  本物の受験記録は読みも書きもせず、`backend/` のサーバーにも送りません。
- 教材は「続きから」の位置を保存しません。トップは見本の「続きから」「前回の結果」を出します。

PC では枠を縮小して PC の画面を、スマホでは幅 390px のスマホの画面を見せます（目次や問題一覧の開き方も、それぞれの画面に合わせて変えます）。
手順は `src/site/guide.js` の `TOURS` に、開くページ・行う操作・枠を重ねる要素・説明文の組で書いてあります。

## 自宅で受験記録 API とデータベースを動かす（backend/）

GitHub Pages の公開ページは、受験記録をブラウザの中（localStorage）にだけ保存します。
自宅のパソコンで `backend/`（Spring Boot アプリ）を動かし、そこからページを開くと、記録が**データベースにも**保存され、次の機能が加わります。
Spring Boot の学習用に作ったものです。

### 使えるようになる機能

| 機能 | 内容 |
|---|---|
| 受験記録をデータベースに保存 | 提出すると、全問の正誤と選んだ選択肢をデータベースに保存する。ブラウザのデータを消しても、データベースには残る |
| 振り返りメモもデータベースに | 問題ごとのメモを書くと、データベースにも書き込む |
| **弱点レポート** | 採点結果の「弱点レポートを開く」で、間違えた問題を論点（教材の節）ごとに数えて多い順に並べ、問題ごとの論点・選んだ答え・自分のメモをまとめたテキストを出す。「コピーする」でそのまま生成AIに貼れる（練習問題を作ってもらうお願いの文も付いている） |
| あとから保存 | サーバーが止まっていた回や、ほかの端末から読み込んだ回・手で入力した回は、採点結果の「サーバーに保存する」で送れる |
| 削除の連動 | 受験記録を削除すると、データベースの記録も消す |
| データベースを直接見る | ブラウザの H2 コンソールで、保存された表を SQL で見られる |
| API | 記録の一覧・1件の詳細・弱点レポートを JSON やテキストで取り出せる（下の「API」） |

GitHub Pages で開いたときは、サーバーには問い合わせもせず、今までどおりブラウザの中だけで動きます（使い方のページの見本モードも同じ）。

### データベースは別に入れなくてよい

データベースには **H2 Database** を使っています。アプリの中に入っていて、ファイル1つ（`backend/data/exam.mv.db`）で動くので、
MySQL や PostgreSQL のようにデータベースのソフトを別にインストールする必要はありません。初めて起動したときに、表（テーブル）も自動で作られます。

### 必要なもの

| もの | 版 | メモ |
|---|---|---|
| JDK | **21 以上** | `JAVA_HOME` をその JDK に向けておく。Maven は入れなくてよい（同梱の `mvnw` を使う） |
| Git | | リポジトリを clone するため |
| Node.js | 18 以上 | **教材や問題を編集したときだけ**。`docs/` はビルド済みでリポジトリに入っているので、動かすだけなら不要 |

Spring Boot 4、H2 Database、Spring Data JPA を使っています。

### 動かし方（clone から）

```bash
git clone https://github.com/shoushinei/java-silver-se17-note.git
cd java-silver-se17-note/backend
./mvnw spring-boot:run
```

Windows の PowerShell では `.\mvnw spring-boot:run` です。初回は Maven と依存ライブラリのダウンロードで数分かかります。
ログに `questions.json を読み込みました（5 回ぶん・300 問）` と `Started BackendApplication` が出たら、ブラウザで開きます。

| アドレス | 中身 |
|---|---|
| http://localhost:8080/ | トップ（教材・模擬試験・使い方へのリンクも公開ページと同じ） |
| http://localhost:8080/exams/05/ | 模擬試験（ここから受けると、データベースにも保存される。開始画面に「サーバー（backend/）につながっています」と出る） |
| http://localhost:8080/note/ | 教材 |
| http://localhost:8080/h2-console | データベースの中身を見る画面（JDBC URL `jdbc:h2:file:./data/exam`、ユーザー `sa`、パスワードは空） |

止めるときは `Ctrl + C` です。起動し直しても、保存した記録は消えません。

- **必ず `backend/` の中で起動します。** 問題の対応表（`../docs/exams/questions.json`）とページ（`../docs/`）を、起動したフォルダからの位置で探すためです。見つからないと、どこを探したかをログに出して起動を止めます。
- **JDK の版を確かめる**ときは `./mvnw -v` です。`Java version: 21…` 以上なら大丈夫です。
- **8080 番がほかで使われている**ときは、番号を変えて起動します: `./mvnw spring-boot:run "-Dspring-boot.run.arguments=--server.port=8081"`
  （PowerShell では `-D…` を `"` で囲まないと、`.` のところで分かれてしまいます。jar なら `java -jar … --server.port=8081`）
- **ブラウザの記録はアドレスごとに別**です。GitHub Pages で受けた回は、`localhost:8080` の画面には出てきません（逆も同じ）。
  GitHub Pages で受けた回をデータベースに入れたいときは、公開ページの模擬試験で「記録を書き出す」→ `localhost:8080` の同じ試験で「記録を読み込む」→
  その回の「結果を開く」→「サーバーに保存する」の順に進めます。

### データベースの中身を見る（H2 コンソール）

http://localhost:8080/h2-console を開き、上の表の JDBC URL・ユーザーで「Connect」を押すと、左に表が並びます。

| 表 | 中身 |
|---|---|
| `ATTEMPT` | 受験1回分（試験・日時・得点・所要時間） |
| `ATTEMPT_ITEM` | 1問ずつの結果（選んだ答え・正誤・振り返りメモ） |

たとえば `SELECT * FROM ATTEMPT ORDER BY ID DESC;` で、新しい順に受験記録が見られます。
表の名前と列は `backend/src/main/java/.../attempt/` の `Attempt.java`・`AttemptItem.java` から自動で作られます。

### jar にして動かす

毎回ビルドせずに起動したいときは、1つのファイル（jar）にまとめます。

```bash
cd backend
./mvnw package
java -jar target/backend-0.0.1-SNAPSHOT.jar
```

これも `backend/` の中で実行します。`package` のときにテストも走ります（サーバーを止めてから実行してください。起動中だとデータベースのファイルを取り合ってテストが失敗します）。

### データの置き場所

保存先は `backend/data/exam.mv.db` です。**自分の受験記録とメモが入るので、`.gitignore` で GitHub には上げないようにしてあります。**
clone した直後は空の状態から始まります。

| したいこと | 方法 |
|---|---|
| 別のパソコンへ移す・控えを取る | サーバーを止めてから `backend/data/` フォルダをコピーする |
| まっさらに戻す | サーバーを止めてから `backend/data/` フォルダを消す（次の起動で空のデータベースができる） |

この API には**ログインの仕組みがありません**。自分のパソコンの中だけで使い、インターネットに公開するサーバーには置かないでください。

### ほかのデータベースを使いたいとき

H2 のままで足りますが、MySQL や PostgreSQL に保存したい場合は、Spring Boot の設定を差し替えます
（このリポジトリで動作を確かめているのは H2 だけです）。PostgreSQL なら次の2か所です。

1. `backend/pom.xml` の `<dependencies>` に、JDBC ドライバを足す

   ```xml
   <dependency>
     <groupId>org.postgresql</groupId>
     <artifactId>postgresql</artifactId>
     <scope>runtime</scope>
   </dependency>
   ```

2. `backend/src/main/resources/application.properties` の `spring.datasource.*` を書き換える（データベース `exam` は先に作っておく）

   ```properties
   spring.datasource.url=jdbc:postgresql://localhost:5432/exam
   spring.datasource.username=自分のユーザー名
   spring.datasource.password=自分のパスワード
   ```

`spring.jpa.hibernate.ddl-auto=update` になっているので、表は初めての起動で自動で作られます。H2 コンソール（`spring.h2.console.enabled`）は H2 専用なので、使わないなら `false` にします。

### API

| メソッド | パス | すること |
|---|---|---|
| POST | `/api/attempts` | 1回分を全問の結果ごと保存する（得点はサーバーが数える） |
| GET | `/api/attempts` | 受験記録の一覧（新しい順・概要だけ） |
| GET | `/api/attempts/{id}` | 1件を、問題ごとの結果とメモつきで |
| PUT | `/api/attempts/{id}/items/{問題番号}/memo` | 1問のメモを書き換える |
| DELETE | `/api/attempts/{id}` | 1件消す（問題ごとの記録も一緒に） |
| GET | `/api/attempts/{id}/report` | 弱点レポート（テキスト） |
| GET | `/api/exams/{試験ID}/questions/{問題番号}` | 問題の正解と論点 |

`backend/requests.http` に、そのまま送れるリクエストの例があります（VS Code の拡張機能 REST Client で「Send Request」を押すと送れます）。

### 構成

```
backend/src/main/java/io/github/shoushinei/backend/
├── BackendApplication.java    起動
├── PageController.java        /note/ や /exams/02/ のようなアドレスを index.html に回す（ページを docs/ から配るため）
├── attempt/                   受験記録（受験1回と、1問ずつの結果・メモ）
├── question/                  問題番号 → 正解・論点の対応表（docs/exams/questions.json）を起動時に読む
└── report/                    上の2つを組み合わせて、弱点レポートのテキストを作る
```

問題の対応表 `docs/exams/questions.json` は、`node build.mjs` が `src/exams/` の問題ファイル（`refs:` に書いた論点）から作ります。
問題を直したり足したりしたときは、`node build.mjs` のあとでサーバーを起動し直してください（対応表は起動時に1回だけ読みます）。

## リポジトリの構成

編集するのは `src/` だけです。`docs/` は `build.mjs` が生成する成果物で、
手で編集しても次のビルドで上書きされます。

```
src/
├── site/                      トップ・使い方・このサイトについて
│   ├── index.html                 トップ（ポータル）。「続きから」「前回の結果」もここ
│   ├── guide.html / guide.js      はじめての方へ（使い方）。手順は guide.js の TOURS
│   ├── about.html                 このサイトについて
│   ├── header.html / footer.html  3ページで共通の上のバーと下の注意書き
│   └── site.css
├── note/                      教材
│   ├── manifest.json              章と節の一覧。目次と並び順の唯一の定義
```

## ビルド

Node.js 18 以上が必要です。依存パッケージはありません。

```bash
node build.mjs
```

`docs/` の各ページが、それぞれ 1 枚の自己完結 HTML として書き出されます。
CSS も JS も埋め込むので、ダウンロードして `file://` で開いても、オフラインでもそのまま読めます
（使い方のページの「枠を重ねる」動きだけは、ブラウザが `file://` の中のページに触らせないため、簡易サーバー越しでないと出ません）。

生成物が `src/` と一致しているかだけ確かめたいときは:

```bash
node build.mjs --check
```

CI（`.github/workflows/build.yml`）はこれと、後述の模擬試験の検証を走らせます。
`src/` を直して `docs/` を更新し忘れると失敗するので、公開ページが古いまま
放置されることはありません。

ローカルで確認するときは、簡易サーバー越しに開いてください（localStorage を使う機能が `file://` だと環境によって効かないため）。

```bash
node build.mjs && python -m http.server 8080 --directory docs
```

## 編集のしかた

以下、教材のパスはすべて `src/note/` からの相対です。

### 本文を直す

直したい節のファイルを開いて編集し、`node build.mjs` を実行するだけです。
節と目次の対応は `manifest.json` にあるので、「目次のこの項目を直したい」というときはまずそこを引いてください。

### 論点番号と目次の名前

論点番号は**ビルドのたびに自動で振り直す**ので、本文に番号を書く必要はありません。
節は `manifest.json` の並び（`tn`）から「章-節」、節の中の `<h3>` は出てくる順に「章-節-項」になり、
見出しに番号が入って、目次にも並びます。`<h3>` には `p2-3-4` のような id が付き（すでに id があればそれを使い）、索引や外からのリンクに使います。

見出しが長いときは、目次に出す短い名前を `data-toc` に書きます。

```html
<h3 data-toc="キャスト不要で縮小できる3場面">② の続き ── キャストを書かなくても縮小できる3つの場面</h3>
```

`<h3>` を足したり並べ替えたりすると、その節の後ろの論点番号がずれます。模擬試験の `refs` は節（`c2-s03`）を指しているので影響しません。

### 節を追加する

1. `content/chN/` に `12-....html` を作る。中身は `<section id="cN-s12">` と `<div class="sh"><span class="num">12</span><h2>…</h2></div>` で始める。
2. `manifest.json` の該当章の `sections` に 1 行足す。

```json
{ "id": "c1-s08", "tn": "08", "label": "目次に出す短い名前", "file": "08-....html" }
```

`id` はファイル内の `<section id>` と一致していなければならず、
ずれているとビルドが止まって理由を教えてくれます。並び替えは `sections` の
順番を入れ替えるだけで、目次にも本文にも反映されます（論点番号も振り直されます）。

### 章を追加する

`content/ch7/` を作って `_chapter.html` と各節を置き、`manifest.json` の `chapters` に追記します。
`key`（`c7` など）は節の id の接頭辞で、論点番号の章の数字にもなります。

### 索引の語句を増やす

`data/index-terms.json` に 1 行足します。どの論点に載っているかは、ビルドが本文から自動で探します。

```json
{ "t": "表示名", "k": ["本文で探す語", "別の言い方"], "y": "よみ", "x": ["4-6-1"] }
```

| 項目 | 意味 |
|---|---|
| `t` | 索引に出す名前。先頭の文字で、記号・数字・A〜Z・50音のどこに並ぶかが決まる |
| `k` | 本文で探す語（省略すると `t`）。英数字の語は、単語の途中には当たらない（`List` は `ArrayList` に当たらない） |
| `y` | 読み（漢字を含む語だけ）。50音の並びに使う。カタカナの語は省略してよい |
| `x` | 当たっても載せない論点番号（たまたま同じ語が出てくる論点を外す） |

見出しにその語がある論点、太字・表の見出しにある論点、本文のコードにある論点の順に優先し、1 語につき最大 6 つまで載せます（見出しにある論点は太字の番号）。
本文に 1 回も出てこない語があると、ビルドが止まって語を教えてくれます。

### トップ・使い方・このサイトについて

`src/site/` の HTML を直します。数（章・節・論点・試験・問題の数）は `{{points}}` などの差し込み口に、ビルドが実際の数を入れます。
使い方の手順は `guide.js` の `TOURS` に書きます。`sel` に書いた要素が見つからないときは、枠を出さずに説明だけを出します。

### 見た目を変える

色とフォントは `styles/01-tokens.css` の CSS 変数に集約してあります。
トップ・使い方・模擬試験のページもこの変数と、コード・表の CSS を教材から借りています。
CSS は**ファイル名の番号順に連結される**ので、番号が後ろのファイルほど優先されます。

### スマホの見た目を変える

狭い画面向けの指定は `styles/20-mobile.css` にまとめてあります（切り替えの境目は 860px）。
PC のサイドバーとスマホのドロワーは**同じ `<nav class="toc">` を使い回して**います。
目次リンクを複製すると検索側の「href → リンク」の対応が壊れるためで、DOM は 1 つのまま CSS で見た目だけを切り替えています。

## 模擬試験の編集

### 問題を直す・足す

1 問 = 1 ファイル（`src/exams/01/q07.md` など）で、ファイル名の順に問 1, 2, … と並びます。

````markdown
---
answer: A, C
refs:
  - c5-s10 サブインタフェースの default で親の抽象メソッドを実装できる
---
問題文。

```java title=Main.java
public class Main { ... }
```

- A. 選択肢
- B. …

## 解説
解説本文。

## 検証
@case 正解 A
@stem
@javac
@run Main
@stdout
期待する出力
@end
````

- `answer` … 正解。複数なら `,` 区切り。「〜つ選びなさい」の数はここから自動で決まる
- `refs` … 解説に出す「教材で確認する」。節 id と一言（画面には「5-10「default / static / private」」のように論点番号で出る）
- `title=` を付けた java コードは、問題文に行番号つきで表示される
- 選択肢には `` `コード` `` も書ける。複数行のコードは、選択肢の次の行から字下げして ```` ``` ```` で囲む
- 解説には段落・`- ` の箇条書き・コードブロック・`| 見出し | … |` と `|---|` で始める表が書ける

`refs` の節 id が `manifest.json` に無いとビルドが止まります。
章ごとの正答率は、この `refs` の先頭の節の章で集計します。

### 問題のコードを確かめる

「## 検証」に書いた手順を、JDK で実際にコンパイル・実行して、
問題と解説が主張する結果（出力・コンパイルエラー・例外）になるかを確かめます。
`@stem` を使えば、問題文に表示しているコードそのものが検証されます。

```bash
node tools/verify-exams.mjs          # すべて
node tools/verify-exams.mjs 01 7     # 試験 01 の問 7 だけ
```

JDK（`javac` / `java`）が必要です。言語仕様は `--release 17` に固定しています。
CI は試験と同じ Java 17 でこれを走らせます。書ける命令の一覧は `tools/verify-exams.mjs` の先頭にあります
（「途中まで表示してから例外」は `@output` と `@exception` を組にして確かめます）。
Java 17 より後で動きが変わったもの（instance main など）は `@only-jdk 17` を付け、手元の JDK が違えば skip して CI で確かめます。

### 試験を追加する

`src/exams/06/` のように連番のディレクトリを作り、`exam.json` と `q01.md` 〜 を置いて `node build.mjs` を実行します。
一覧ページ（`docs/exams/index.html`）とトップの試験の一覧には自動で並び、使い方のページはいちばん新しい回を見本に使います。

```json
{ "title": "自作模擬試験 6", "description": "一覧に出す説明", "minutes": 90, "passRate": 0.65 }
```

#### 難しさの目安（黒本の模擬試験と同じにする）

2人で試したところ、黒本②は 90 分でちょうど解き終わりましたが、試験 3 は 15 問残して時間切れ、試験 4 は易しすぎました。
そこで黒本①・②の 120 問を、解くのに要る手間で3段階に分け直し、その割合を新しい試験の目安にしています。

| 段階 | 目安 | 黒本① | 黒本② | 試験 3 | 試験 4 | 試験 5 |
|---|---|---|---|---|---|---|
| 基本 | 知識1つ、または1〜2手で解ける | 16 | 19 | 約 5 | 40 | 16 |
| 標準 | ひっかけが1つ、または3〜6手の追跡 | 32 | 30 | 約 27 | 20 | 32 |
| 応用 | 範囲内の論点を2つ組み合わせる・長い追跡・紛らわしい選択肢を全部確かめる | 12 | 11 | 約 28 | 0 | 12 |

あわせて次をそろえます。

- 論点は黒本と教材に載っている範囲だけにする（試験 3 は範囲外の細かい点が約 11 問あった）
- 「コンパイルエラーが発生する」などは、エラーの行や理由を問う問題以外では一般形の選択肢にする
- 選択肢は平均 5 個前後（黒本は約 5〜5.4 個）。1つ・2つ・3つ選択は 45・11・4 問
- 試験 1〜4 や黒本と同じ組み立ての問題を作らない（論点が同じでも、コードと切り口を変える）

## GitHub Pages で公開する

このリポジトリを GitHub に push したあと、一度だけ設定します。

1. リポジトリの **Settings › Pages** を開く
2. **Source** を `Deploy from a branch` にする
3. **Branch** を `main` / `/docs` にして Save
